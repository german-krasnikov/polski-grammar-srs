# UX2 Web — тема, настройки и читаемый экран обучения

Статус: **реализация завершена; основные virtual acceptance сценарии пройдены 2026-09-25**. Этот blueprint описывает исходный handoff UX2 после [UX1](PreferencesBlueprint.md); результаты и неисполненные части gate зафиксированы в [UX2WebTester.md](UX2WebTester.md). React остаётся эталоном поведения, Kotlin/JS и Kotlin/Wasm проходят общие сценарии. Прямой 400% browser zoom и физические accessibility gates остаются NOT RUN.

## Объём и существующие потребители

- Браузерный UI фактически строит DOM через `HtmlElementView` в `kotlin/composeApp/src/webMain/kotlin/polski/ui/TrainingWebApp.kt`; `TrainingDomRenderer` каждый значимый снимок пересоздаёт subtree, но сохраняет известный focus id, scroll и активную IME-композицию. Новые Settings и тема должны работать в этой схеме. `jsMain/main.kt` и `wasmJsMain/main.kt` используют один `TrainingWebApp()` через `ComposeViewport`.
- `kotlin/shared/src/commonMain/kotlin/polski/presentation/AppUiState.kt` содержит четыре `AppTab`, но не Settings. `TrainingStore` владеет карточкой, черновиком, методом и FSRS. `VocabularyWebController` хранит самостоятельную текущую карточку, оба направления, редактор и черновик в памяти. Навигация не должна пересоздавать эти объекты.
- Текущий web напрямую читает/пишет `polski-explanation-method-v1` в `TrainingWebApp.kt`; UX1 переносит это в один preference controller по [контракту](PreferencesBlueprint.md). Нельзя добавлять рядом ещё один writer старого ключа. `ProgressWeb.kt` уже имеет экспорт/сброс, `VocabularyWeb.kt` — каталог, импорт/экспорт и восстановление; перенос ссылок в Settings не должен удалять прежний рабочий путь до приёмки.
- В `training.css` и `matrix-progress.css` тёмные цвета зашиты в селекторах, включая матрицы и словарь. UX2 охватывает обе таблицы и все состояния карточки, а не только header. `index.html` задаёт статичный `theme-color`.

## Контракты, состояние и зависимости

**Обязательный первый срез UX1.** [PreferencesBlueprint.md](PreferencesBlueprint.md) достаточен как общий контракт, но его код ещё отсутствует. До UX2 Developer создаёт `NEW kotlin/shared/src/commonMain/kotlin/polski/preferences/UserPreferences.kt`, `UserPreferencesCodec.kt` и минимальный `UserPreferencesRepository.kt`: явные wire values `System|Light|Dark`, `System|Reduced`, `Logic|Situations`, `Oral|Typed`; `schemaVersion=1`, `coursePair=pl-ru`, выключенные reminders и валидируемые defaults. Codec возвращает typed `Loaded`/`RecoveryRequired(raw, reason)` и отказывается от неизвестных полей, enum и версии >1. Repository имеет typed `Missing`/`Unavailable`/`WriteFailed` и не смешивается с progress/vocabulary JSON. В срезе нужен один session-level coordinator с immutable preference snapshot и `setExplanationMethod`, `setAnswerMode`, `setAppearance`, `setMotion`; он единственный сохраняет v1 и отправляет соответствующие `AppAction` в `TrainingStore`. Загрузка preferences должна завершиться до создания `TrainingStore` или синхронно обновить его до первого видимого вопроса; иначе старый метод успеет мигнуть дефолтом. При `Revealed` ответный режим сохраняется сейчас, применяется следующему `Question`. Browser adapter и UI из пунктов ниже — первые реальные потребители этого API. Android/Mac/iOS adapters и delivery напоминаний в этот срез не входят. Первая реализация должна подтвердить PR1–PR3 и PR5 UX1 для web, прежде чем считать W1–W6 проверенными.

1. **Предпочтения.** Взять `UserPreferencesV1` и codec из UX1, не вводя web-специфичную схему. Browser adapter (`NEW kotlin/composeApp/src/webMain/kotlin/polski/platform/WebPreferencesRepository.kt`) читает отдельный `polski-preferences-v1`, затем идемпотентно мигрирует старый method key. На malformed/future JSON, отказе `localStorage` или readback ошибка не перезаписывает исходный raw. Session coordinator (`NEW .../webMain/kotlin/polski/ui/WebPreferencesController.kt`, либо минимальный эквивалент UX1) хранит snapshot и один action route для метода, режима ответа, темы и motion. Он передаёт method/answer actions в существующий `TrainingStore`, не вызывает `Rate`/`Reveal` при изменении предпочтения. Смена answer mode во время `Revealed` применяется на следующем `Question` согласно UX1.
2. **Тема.** Отдельный browser appearance adapter (`NEW .../webMain/kotlin/polski/platform/WebAppearance.kt`) разрешает `System|Light|Dark` через `matchMedia('(prefers-color-scheme: dark)')`, подписывается на изменения и снимает listener при закрытии Compose mount. `System` следует изменению браузера без reload; явный override остаётся выбранным. Эффективная палитра отражается на `document.documentElement` через один `data-theme=light|dark`, синхронизирует `color-scheme`, `meta[name=theme-color]` и все host CSS токены. Изменение DOM theme attribute не должно очищать `.training-web-host`, `TrainingStore` или `VocabularyWebController`. Motion: `System|Reduced` разрешается через отдельный `matchMedia('(prefers-reduced-motion: reduce)')`; CSS и любая будущая Compose анимация получают одну effective value. События анимации не являются источником оценки или навигации.
3. **Навигация.** Settings — web shell destination, не `AppTab.Settings` в общем `TrainingStore`. `NEW .../webMain/kotlin/polski/ui/WebRouteController.kt` (или локальный объект рядом с `TrainingWebApp`) отображает четыре существующих раздела и `settings` на hash URL `#/training|vocabulary|matrix|progress|settings`. Пустой/неизвестный hash безопасно открывает training; прямой `#/settings` работает на статическом host без server rewrite. Переход в Settings запоминает текущий раздел как return destination только в session/navigation state. Route controller владеет `popstate`/`hashchange` listeners и `history.pushState`/`replaceState`, снимает listeners при unmount; card reveal и оценка не создают history entries. Он отправляет `AppAction.SelectTab` только при выборе учебного раздела и никогда при показе Settings. Кнопка «Вернуться к карточке» открывает запомненный раздел; browser Back/Forward восстанавливает destination. Прямой заход в Settings возвращает в training, не уводит пользователя за пределы приложения. Проверить двойные события popstate/hashchange, чтобы один переход не выполнялся дважды.
4. **Renderer.** `TrainingDomRenderer.render()` принимает `route`, preference snapshot и callbacks для shell действий. Состояние Settings меняет только отображаемый раздел. `TrainingStore` и `VocabularyWebController` создаются один раз на Compose mount и остаются живыми при переходах. Прежняя оптимизация `old.copy(draft=state.draft)==state` должна учитывать изменившиеся route/preferences: открытие Settings, смена темы и вернувшийся tab должны рендериться; при вводе/IME не пересоздавать textarea. Для Settings — `NEW .../webMain/kotlin/polski/ui/SettingsWeb.kt`: семантические `main`, `h2`, `fieldset`/`legend` или явные `label`, живой статус сохранения, действующие элементы для метода, режима ответа, темы и motion, раздельные ссылки/действия для прогресса и словаря. Напоминания показать как неподдерживаемую браузерную возможность с объяснением; не просить permission и не предлагать toggle, который обещает доставку при закрытом браузере. Пункты будущих языков/неподдержанных импортов не выдавать за работающие.
5. **Визуальная система.** `training.css` — единственный слой semantic CSS custom properties для light/dark: surface, elevated surface, text, muted, border, focus, primary, source-before, target-after, success/error, table headers and highlights. `matrix-progress.css` использует те же tokens; проверить словарь, ошибку хранения, эталон и таблицы. Красный исходной формы и отдельный целевой цвет сохраняют подчёркивание и подписи; цвет не единственный сигнал. Сократить `renderHeader()` до компактного заголовка/неброских счётчиков; на широкой области держать подписанные destinations, на узкой — компактную, всегда подписанную навигацию с видимым Settings entry. Перенести второстепенные опции в раскрываемый блок или Settings, но «Подача объяснений», выбор режима тренировки, набор слов, справка и путь к прогрессу остаются достижимыми без потери карточки. Задача и следующее действие должны попадать в первый viewport 390×844; 320 CSS px и 400% zoom должны reflow без горизонтального scroll обычной страницы. Матрица остаётся отдельной подписанной областью горизонтального scroll.

## Порядок реализации

1. Завершить UX1 common codec/controller и web storage migration; зафиксировать текущие React и Kotlin JS/Wasm сценарии метода/черновика/FSRS. Затем подключить web Preferences через один writer и удалить прямую запись старого method key из Kotlin UI после проверки миграции.
2. Добавить route controller, Settings entry и минимальный settings screen. Сначала проверить Back/Forward, direct link/reload и сохранение грамматической/словарной карточки. Вернуть focus в логичное место после Settings, не присваивать фокус textarea при открытой странице настроек.
3. Ввести semantic tokens и light/dark палитры для обоих CSS, resolver System и meta theme-color. Проверить тему на всех четырёх разделах, включая матрицу/редактор/ошибки, в JS и Wasm. Затем изменить header, nav, toolbar и узкую компоновку по UX0 снимкам. `prefers-reduced-motion` уже отключает CSS transition/animation; добавить user override и синхронизацию media subscription.
4. Подключить доступные JSON действия в Settings через существующие владельцы данных. Новую логику file import/export или notification delivery выносить в отдельный контракт и проверять до появления работающего пункта. Swipe-rating только после раскрытия и только как дополнение к двум видимым кнопкам; для грамматики не переносить pointer handler словаря вслепую, учитывать выделение текста, вертикальную прокрутку, IME и table pan.

| ID | Сценарий и наблюдаемый результат |
| --- | --- |

| W2 | System theme динамически следует light/dark media query без reload; ручная Light/Dark переживает reload и игнорирует последующее системное изменение. `data-theme`, `color-scheme`, `theme-color` и видимые элементы согласованы на JS и Wasm. Переключение не меняет `exerciseId`, draft, selection, scroll, focus и число/JSON FSRS reviews. |
| W3 | Settings из каждого из четырёх разделов, browser Back/Forward, прямой `#/settings` и reload работают. Возврат сохраняет открытую грамматическую фазу/черновик и словарное направление/черновик. Нажатие двух оценок после возврата создаёт ровно по одному соответствующему review; route change сам review не создаёт. |
| W4 | На 390×844 задание и главное следующее действие видны до скролла при обычном размере текста; 320 CSS px и 400% zoom не дают общего горизонтального overflow, все разделы/Settings доступны клавиатурой. | W5 | Контраст, focus indicator, исходное/целевое изменение с текстовой подписью и читаемость в обеих палитрах проверены на карточке, словаре, таблице, Settings, ошибке сохранения и эталоне. Reduced/System motion меняется динамически, контент и оценки доступны без анимации. |
| W6 | Browser Settings честно сообщает, что закрытый браузер не получает надёжных локальных напоминаний без отдельного Push/PWA gate; permission prompt не появляется при входе. Раздельные рабочие пути JSON progress/vocabulary сохранены, текущие raw/FSRS данные не изменяются от навигации/темы. |

Developer ведёт реализацию и меняет продуктовую документацию; Tester проверяет JS и Wasm production builds в Chromium/Firefox/WebKit, narrow/zoom/IME, storage-denied и историю; Reviewer отдельно оценивает single writer, lifecycle media/history listeners, CSS palette coverage и доказательства. Указывать PASS/FAIL/NOT RUN отдельно для тестов, сборок и браузеров. Общий web parity и реальные Safari/экранный диктор остаются отдельными gates из основного плана.
