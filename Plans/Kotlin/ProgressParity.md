# Progress fixture replay — Kotlin web

Date: 2026-09-23. This is main-agent verification against all 20 pinned React `progress.json` cases, not independent Stage 11 acceptance. The production Kotlin browser artifact was used for UI cases; a generated Kotlin common test replays the exact same-skill midnight transitions and import inputs. React remains the published baseline.

| Fixture IDs | Kotlin result and evidence |
| --- | --- |
| `P-fresh`, `P-missing-skills`, `P-save-load`, `P-export-import` | **PASS:** complete JSON exported from Kotlin UI equals each React expected document. The existing migration browser case also loads a current Kotlin export in React. [Load test](../../tests/browser/kotlin-parity-progress-load.spec.ts). |
| `P-oral-good`, `P-typed-wrong` | **PASS:** one UI review at the fixture instant produces the exact React serialized cards, stats and counters. [Review test](../../tests/browser/kotlin-parity-progress-review.spec.ts). |
| `P-queue` | **PASS:** scheduled mode chooses oldest due `case.acc.f`; focused mode permits future `case.acc.n`. [Load/queue test](../../tests/browser/kotlin-parity-progress-load.spec.ts). |
| `P-day-before-midnight-warsaw`, `P-day-after-midnight-warsaw`, `P-day-dst-before`, `P-day-dst-after`, `P-day-same-instant-utc` | **PASS:** browser UI writes the fixture's local day and one review at each fixed instant. [Local-day test](../../tests/browser/kotlin-progress-local-day.spec.ts). |
| `P-review-midnight-winter`, `P-review-midnight-dst` | **PASS:** first UI review matches the full fixture; UI review of the next chain skill resets only the daily count after midnight. The [generated common test](../../kotlin/shared/src/commonTest/kotlin/polski/progress/ProgressFixtureParityTest.kt) replays both reviews on the **same** skill and matches complete typed progress after each transition. Its [generator](../../kotlin/shared/src/commonTest/kotlin/polski/progress/generate_parity.py) reads the pinned fixture. |
| `P-load-malformed`, `P-load-unsupported-version`, `P-storage-read-error` | **PASS under the Kotlin safety contract:** raw bytes remain exportable or storage is shown unavailable; no fresh document replaces unreadable data. React's expected fresh fallback is intentionally not copied. [Recovery test](../../tests/browser/kotlin-parity-progress-recovery.spec.ts). |
| `P-import-invalid-json`, `P-import-missing-fields`, `P-import-unsupported-version` | **PASS under the Kotlin safety contract:** the exact raw fixture inputs decode as `Invalid`, `Invalid`, and `Unsupported`. React accepts version 99 in the last case, a baseline defect; Kotlin refuses it to protect existing progress. The generated common test covers these inputs. There is no file-import control in either current web UI. |

The four browser fixture suites passed on **Wasm and forced JS** in Chromium, Firefox and Playwright WebKit: load/queue 15/15, review 6/6, local-day/midnight UI 21/21, recovery 9/9 **per branch**. The complete integrated Playwright configuration later passed **120/120 per branch**, including direct P02/P03/P05/P10 browser comparisons. Its first concurrent JS run lost trace files to the Wasm run because both used the default results directory; after assigning branch-specific `outputDir`, complete JS reruns passed. `:shared:jsBrowserTest :shared:wasmJsBrowserTest --tests 'polski.progress.ProgressFixtureParityTest'` passed 5/5 on each target. The direct P08 React ↔ Kotlin matrix check passed 3/3 per branch separately. TypeScript `npm run typecheck` passed.

This closes the fixture **execution ledger**, not the migration gate. The three recovery and three import cases require reviewer agreement on the documented intentional difference from React. Physical mobile browsers, real Polish IME and assistive technology, full P01–P12 UI parity, performance, independent tester/reviewer handoff and live CI remain open under [Plan.md](Plan.md).
