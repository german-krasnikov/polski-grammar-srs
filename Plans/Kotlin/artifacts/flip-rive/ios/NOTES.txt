GAP AGAINST THE PLAN'S LITERAL §5 PROTOCOL (reported, not fixed — would require production code)
FlipCardRivePlan.md §5 specifies `XCTOSSignpostMetric(...)` "around an os_signpost interval for
flip+effect" for variants A/B/C. No os_signpost calls exist in FlashCardView.swift/
RiveEffectOverlay.swift (confirmed absent) — adding them is a production-code change, out of this
tester's scope ("Do not change production code"). §10's own evidence log already flags this as not
collected ("количественные измерения — отдельный проход"). What this pass measures instead is
UI-interaction wall-clock round-trip time (XCUITest gesture -> next expected element appearing),
which is a coarser, real, but different quantity than a per-frame/os_signpost interval — it
includes XCUITest's own accessibility-snapshot and event-synthesis overhead (typically 1-2s per
step in this app on this simulator), not just the app's render time. Treat the absolute seconds in
perf-report.json's flip/rate round-trip times as XCUITest-inflated; treat the *relative* deltas
between variants (A vs B vs C) as the more meaningful signal, since that overhead is present in all
three the same way.
No true per-frame p50/p95/p99 (CADisplayLink/Instruments-Animation-Hitches-based) or dropped/janky
frame % was collected — not attempted this pass; NOT RUN. The plan's own §5 protocol names xctrace
("Animation Hitches" template) only for macOS, not for iOS, so this isn't a protocol gap for iOS,
but it does mean frame-level percentiles are not available from this evidence, only the interaction
p50/p95/p99 in perf-report.json (computed from 5 samples per variant, so p95/p99 are close to max
of 5, not a real percentile estimate — treat as indicative only, not statistically robust).

REGRESSIONS FOUND IN THE TEST HARNESS ITSELF (fixed here, harness-only, not app defects)
1. `app.buttons["Движение"]` never matched: the Motion picker (Menu-style, same pattern as the
   existing "Ответ, ..." picker in PolskiGrammarUITests.swift) exposes its accessibility label as
   "Движение, <current value>", not the bare title. Fixed with a `label BEGINSWITH "Движение,"`
   predicate, matching the codebase's own existing convention.
2. `revealCurrentCard` didn't know about two milestone phases that a long run of rate cycles can
   hit — "ChainComplete" (offers "Следующий набор слов"/"К повторениям") and "NoDue" (offers
   "Потренировать цепочку" once nothing is due) — both defined in PolskiGrammarApp.swift's
   `switch state.string("phase")`. Fixed by dismissing either the same way a person would
   ("К повторениям" / "Потренировать цепочку") before continuing to look for "revealAnswer".
   Neither is an app defect — a fresh `resetTrainingProgress` plus 5-65 rate cycles legitimately
   walks through these real screens.
