# Срез course pack: местоименные контексты и притяжательные примеры

## Scope и baseline хостов

Партия 3 [CoursePackRemainingRoadmap.md](CoursePackRemainingRoadmap.md) для этапов 1–2 [CoursePacksPlan.md](CoursePacksPlan.md), после принятия партии 2: убрать повторяющиеся авторские контексты личных местоимений, пояснения и демонстрацию семи владельцев из UI-кода. Существующие personalPronouns (девять парадигм), possessives (семь ID/labels), noun/adjective forms и алгоритмы possessiveForm/nounPhrase уже принадлежат pack/domain; их не дублировать. Не менять выбор раздела, actions, упражнение agreement.my, FSRS или progress. У всех хостов сохраняется нынешняя структура: React/Kotlin Web/Desktop — таблицы, Android/iOS — карточки/секции.

Источники: src/ui/GrammarTables.tsx (две pronouns sections); kotlin/composeApp/src/webMain/kotlin/polski/ui/MatrixWeb.kt (renderPronouns); kotlin/composeApp/src/desktopMain/kotlin/polski/ui/screens/MatrixScreen.kt (PronounsDesktop); kotlin/composeApp/src/androidMain/kotlin/polski/ui/screens/AndroidMatrixScreen.kt (AndroidPronounsSection); kotlin/shared/src/iosMain/kotlin/polski/ios/IosSnapshot.kt (matrixSnapshot pronouns/possessives); kotlin/iosApp/PolskiGrammar/PolskiGrammarApp.swift (pronouns). Для React таблица показывает FormContrast от nominative pronoun к выражению; React/Kotlin Web possessive table сравнивает полную фразу с nominative baseline. Это поведение не должно исчезнуть при извлечении текста.

В AndroidMatrixScreen.kt сейчас `Text("Mówię o… o ${forms.getValue(GramCase.LOC)}")`: подпись уже содержит o, значение тоже начинается с o. Это наблюдаемый baseline defect, а не авторское повторение предлога. Не помещать «o o» ни в pack, ни в golden teaching fixture. Зафиксировать отдельный regression case; исправление renderer на один предлог делать отдельным явным production diff/коммитом после или вместе с extraction при отдельном обозначении изменения поведения. До такого исправления Android P08 по этой ячейке остаётся FAIL/known deviation, даже если остальные данные перенесены.

## Контракт авторских данных

Добавить обязательный reference.pronounTeaching в courses/pl-ru/course.json:

- personal.title; intro.react/compact; footer.react/web/native с точным текстом выше. pronounIds — упорядоченные ссылки на девять ключей personalPronouns.
- contexts — ровно пять ordered entries с id gen/dat/acc/inst/loc и caseId того же значения. Каждая запись хранит cue.full, cue.compact, cue.ios и caseName. full/compact совпадают по словам, но React получает caseName отдельным small, Kotlin Web строит header `cue.full + « · » + caseName`, Desktop/Android получают cue.compact. Для iOS: «Nie widzę», «Daję prezent», «Widzę», «Idę», «Mówię o» соответственно. Поле valuePrefix для inst = «z », loc = «o »; inst.specialValues.ja = «ze mną». Остальные cases не имеют prefix/override. Это presentation pattern для уже существующих форм, не новая таблица склонения; нельзя дублировать польские формы всех девяти pronouns.
- possessive.title; demo `{nounId: wife, adjectiveId: beautiful, number: sg, cases: [nom, acc, gen]}`. У каждой case — точные captions для web, desktop и ios; Android сохраняет собственные enum-префиксы NOM/ACC/GEN. demo.invariableOwnerIds = [his, her, their], rule.invariable = «Владелец не склоняется», rule.variable = «Согласуется с żona». Полные польские tails вычислять из adjectiveForm + nounForm или nounPhrase(wife, case, {adjectiveId: beautiful}) без копии трёх готовых фраз. Префикс владельца добавляет существующий possessiveForm; для React/Kotlin Web contrast baseline — вся nominative фраза того же владельца.

Schema courses/schema/course-pack-v1.schema.json: required, additionalProperties:false, nonblank/noHtml text, exact cardinalities 9/5/3/3 и допустимые ID/case enum. scripts/validate-course.mjs: проверка порядка/уникальности pronounIds и contexts, ссылок на personalPronouns/possessives/noun/adjective, допустимости gender f и number sg demo, specialValues.ja только для inst, всех нужных variants, уникальности invariableOwnerIds и подмножества possessives. Ошибки с путём /reference/pronounTeaching/...; validator проверяет связи/структуру, pinned tests — конкретный текст, чтобы не блокировать явную редакторскую правку.

src/data/course.ts предоставляет узкий read-only coursePronounTeaching. Kotlin shared CourseData.kt предоставляет typed PronounTeaching/PronounContext/PossessiveDemo (или эквивалент) и парсит case/person/owner ID через существующие типы; host выбирает display variant. IosSnapshot.kt продолжает вычислять forms и отдаёт SwiftUI лишь нужные cue/intro/footer/demo captions и строки pronouns/possessives; Swift не загружает course.json. Контексты составляются одним чистым адаптером из pack pattern + существующей формы, чтобы Android не вводил второй o. Состояние и хранение не добавляются.
