# UX3 Mac — настройки, системный вид и спокойный desktop UI

**Архивный scope:** после решения пользователя от 2026-09-25 этот blueprint применяется к существующему Compose Desktop/JVM **preview**, а конечный Mac UX3 выполняется в SwiftUI по [NativeHostDecision.md](NativeHostDecision.md). Описанный ниже Swift helper для JVM не переносится в новый SwiftUI host. Исторические результаты и код preview сохраняются.

Статус: архитектурный handoff, **не реализация**. Выполнять после web UX1/UX2 по [PlatformUXPlan.md](PlatformUXPlan.md); исторический [MacDesktop.md](MacDesktop.md) и его незакрытый host gate не изменять. Проверено по `composeApp/desktopMain` и `shared/preferences` 2026-09-25. Mac остаётся нативным Compose/JVM host поверх общего `TrainingStore`/`VocabularySession`; `java.*`, Swing, AWT и macOS bridge остаются в `desktopMain`.

## Текущая база и границы

- `kotlin/composeApp/src/desktopMain/kotlin/polski/desktop/Main.kt`: `main()` открывает один `Window`, фиксированный `darkColorScheme`, `DesktopSession` создаёт `TrainingStore` через `remember(generation)` и `VocabularySession` через `remember`. Старый `Preferences.userRoot().node("dev/polski/grammarmatrix")["explanationMethod"]` задаёт начальный метод, а `LaunchedEffect(state.explanationMethod)` пишет его обратно. Импорт прогресса увеличивает `generation` и пересоздаёт store. Эти фактические владельцы нельзя обходить новым Settings экраном.
- `kotlin/composeApp/src/desktopMain/kotlin/polski/ui/screens/TrainingScreen.kt` содержит выбор метода и устного/письменного ответа, карточку, две оценки и scoped Space/1/2. `ProgressScreen.kt` экспортирует/сбрасывает progress, `Main.kt` выполняет native file dialogs импорта/экспорта progress и словаря. `DesktopProgressRepository.kt` и `DesktopVocabularyRepository.kt` используют `~/Library/Application Support/Polski Grammar Matrix`, атомарную замену и backup при явном импорте. Оставить эти JSON и FSRS контракты без изменения.
- `kotlin/shared/src/commonMain/kotlin/polski/preferences/{UserPreferences.kt,UserPreferencesCodec.kt,UserPreferencesRepository.kt}` уже существуют в рабочем дереве: `UserPreferencesV1`, `Appearance.System|Light|Dark`, `Motion.System|Reduced`, typed load/save, строгий codec с recoverable raw. Web уже реализует `WebPreferencesController`; Mac adapter не использует DOM и не копирует web session как слой.
- Текущий верхний hero, счётчики и горизонтальная полоса разделов занимают место до задания. UX3 даёт desktop sidebar/toolbar и ограниченную читаемую колонку; плановая узкая/широкая компоновка не меняет генерацию цепочки, навигацию навыков, польские формы и расписание.

## Контракты и владельцы

1. **Mac preferences storage — NEW** `kotlin/composeApp/src/desktopMain/kotlin/polski/desktop/DesktopPreferencesRepository.kt : UserPreferencesRepository`. Файл `preferences-v1.json` в том же Application Support каталоге, отдельно от `progress-v1.json` и `vocabulary-v1.json`. При отсутствии нового файла читать старый `java.util.prefs.Preferences` key `explanationMethod` (`Logic|Situations`), сформировать `UserPreferencesV1`, записать атомарно и проверить readback; старый key оставить для восстановления до отдельного cutover. Когда оба существуют, валидный v1 имеет приоритет. При malformed/unsupported v1 вернуть `RecoveryRequired(raw, reason)` и не подменять его старым key/дефолтом; при отказе чтения/записи вернуть `Unavailable`/`WriteFailed` и сохранить исходные байты. Повторный запуск миграции идемпотентен. Прямой `LaunchedEffect(state.explanationMethod)` в `Main.kt` удалить после включения единого writer.
2. **Владелец предпочтений — NEW** `DesktopPreferencesController` в `desktopMain` (минимальный host coordinator поверх общих model/codec). Один immutable snapshot и статус `Loaded|RecoveryRequired|Unavailable|WriteFailed`; один маршрут изменения method, answer, appearance, motion. Создать его один раз на окно до `TrainingStore`, передать начальный method в конструктор store. Изменение метода с карточки и Settings идёт через controller, затем `AppAction.SetExplanationMethod`. Выбор answer mode в фазе `Revealed` сохраняется сразу и применяется лишь к следующей `Question` по [UX1 контракту](PreferencesBlueprint.md); показать это в Settings без изменения замороженного ответа. Appearance/motion не вызывают `Rate`, `Reveal`, переинициализацию store или `onImported`. Сохранение prefs и подтверждение UI результата различать; при отказе остаётся экспортируемое значение в памяти с явной ошибкой. UI не может молча объявить настройку сохранённой, если readback не прошёл.
3. **Settings destination — NEW** `kotlin/composeApp/src/desktopMain/kotlin/polski/ui/screens/DesktopSettingsScreen.kt`. В `Window` добавить `MenuBar` с `Settings…` и нативным shortcut `⌘,` (проверить сигнатуру `Shortcut` в pinned Compose), плюс видимый Settings entry в sidebar/toolbar. MenuBar и entry открывают **одно** локальное состояние назначения окна; `AppTab` и `TrainingStore` не получают фиктивный Settings tab. Закрытие Settings возвращает прежний раздел и фокус к разумному контролу, сохраняет текущую карточку/черновик и словарное направление/редактор. Настройки: курс польский↔русский только как активная информация; работающие method, answer mode, System/Light/Dark, System/Reduced motion; управление данными отдельными действиями для progress, vocabulary и preferences JSON; о приложении/жестах/клавиатуре. `swipeRatingEnabled` не выводить на Mac без реально реализованного жеста. Раздел напоминаний показывает `Недоступно на Mac в этой сборке` без запроса разрешения и без enabled toggle до capability gate ниже.
4. **Импорт/экспорт.** Существующие `JFileChooser`/`JOptionPane` эффекты в `Main.kt` переиспользовать для progress/vocabulary, не обходя `DesktopProgressRepository.importJson` и `VocabularySession.importJson`. Сохранить прежние действия в Progress/словаре до проверки доступности Settings. Preferences JSON импортировать только явно: `UserPreferencesCodec.decode` перед заменой, backup текущего raw, атомарная запись/readback; при ошибке оставить старый активный файл и backup. Экспортировать либо валидный snapshot, либо исходный recovery raw с честным именем файла. Нельзя сериализовать prefs в progress/vocabulary payload и нельзя импортом настроек сбрасывать FSRS.
5. **Системные appearance и motion — NEW** `desktopMain/.../desktop/MacSystemPreferences.kt` с узким read/observe/close API `MacSystemAppearance { isDark, reduceMotion, increaseContrast }`. Проверить на pinned Compose/JVM, даёт ли `isSystemInDarkTheme()` живую подписку; принимать этот путь только после наблюдаемой смены System Light↔Dark в запущенном и упакованном `.app`. Для Reduce Motion использовать реальное macOS состояние `NSWorkspace.accessibilityDisplayShouldReduceMotion` и уведомление `NSWorkspaceAccessibilityDisplayOptionsDidChangeNotification` через маленький macOS-only bridge, если Compose/Skiko не даёт эквивалентного наблюдения. Bridge должен быть собран внутрь `.app`, обновлять Compose state на UI thread и снимать observer при закрытии; не подменять OS настройку таймером, текущим app toggle или стартовым снимком. Если мост не доказан в пакете, System motion пометить неподдержанным и не считать MX4 пройденным. Ручные Light/Dark/Reduced перекрывают соответствующий системный сигнал; смена OS во время System действует без restart. [AppKit effective appearance](https://developer.apple.com/documentation/appkit/nsapplication/effectiveappearance), [macOS Reduce Motion](https://developer.apple.com/documentation/appkit/nsworkspace/accessibilitydisplayshouldreducemotion).
6. **Визуальная система — NEW** `desktopMain/.../desktop/DesktopTheme.kt` или близкий компактный набор semantic colors поверх `MaterialTheme`: светлая и тёмная palette, surface/elevated/text/focus/source-red/target-accent/error/selection. Заменить жёсткие `background`, `textColor`, `accent` и локальные `Color(0x…)` в `Main.kt`, `TrainingScreen.kt`, `MatrixScreen.kt`, `ProgressScreen.kt` и общем `VocabularyScreen` только через корректные theme tokens/параметры на desktop, без смены Android палитры как побочного эффекта. Текстовая подпись «было → стало» и подчёркивание остаются при обеих палитрах и Increase Contrast. Один короткий state-driven reveal/transition можно добавить после контракта Reduce Motion: при `Reduced` без движения, а запись FSRS всё равно происходит только от `AppAction.Rate`.
7. **Компоновка и фокус.** `Main.kt` адаптирует sidebar/toolbar и одно/двухколоночную тренировку к фактической ширине окна через layout constraints, без пересоздания store на resize. На широком окне справка может стоять сбоку; на узком становится следующей областью прокрутки. Ограничить ширину учебного текста, уменьшить hero/счётчики до сводки, не обрезать русские/польские строки и controls при крупном шрифте. Широкие матрицы сохраняют подписанный собственный horizontal scroll. `TrainingScreen` оставляет visible button на каждое действие и не перехватывает `⌘,`, текстовый ввод, выбор текста или IME своими Space/1/2 shortcut. Settings имеет последовательный keyboard/VoiceOver порядок и видимый focus. Native system dialogs остаются modal host effects, не общими composables.

### Конкретный мост для System appearance и Reduce Motion

Для JVM нет используемого в проекте AppKit binding (`desktopMain` содержит только Compose Desktop 1.12.1), поэтому предпочтительный проверяемый путь — небольшой **NEW** `kotlin/composeApp/src/desktopMain/macos/MacDisplayObserver.swift` как локальный process helper, а не `defaults` polling. Swift helper с `NSApplication.shared` и activation policy `.prohibited` удерживает main run loop; подписывается KVO на `NSApp.effectiveAppearance` и определяет dark через `bestMatch(from: [.darkAqua, .aqua])`. Он читает `NSWorkspace.shared.accessibilityDisplayShouldReduceMotion` и `accessibilityDisplayShouldIncreaseContrast`, регистрирует именно `NSWorkspace.shared.notificationCenter` для `accessibilityDisplayOptionsDidChangeNotification`, повторно читает оба значения на каждом событии. Apple показывает [KVO для `effectiveAppearance`](https://developer.apple.com/documentation/uikit/supporting-dark-mode-in-your-interface) и документирует [Reduce Motion + workspace notification](https://developer.apple.com/documentation/appkit/nsworkspace/accessibilitydisplayshouldreducemotion). Ручная тема Compose не меняет вид helper: он передаёт системную величину, а `DesktopPreferencesController` вычисляет effective choice.

**NEW** `kotlin/composeApp/src/desktopMain/kotlin/polski/desktop/MacSystemPreferences.kt` запускает helper через `ProcessBuilder` один раз на окно, читает ограниченный line protocol вроде `v1 dark=0 motion=1 contrast=0` с начальным snapshot и последующими изменениями, валидирует версию/три boolean и публикует immutable state в Compose на UI dispatcher. Ошибка запуска, malformed line, EOF или неожиданное завершение становится явным `Unavailable`, а не тихим `false`; UI не показывает неподтверждённый режим System как работающий. `close()` отменяет reader, закрывает streams, завершает child process и запрещает поздние callbacks. Исключить второй подписчик при recomposition и после `generation++` на progress import. Для `⌘,`, темы и карточки owner по-прежнему одно окно, не helper.

В **`kotlin/composeApp/build.gradle.kts`** добавить macOS-only `swiftc` task с заявленным output и зависимостью упаковки, включить бинарник через `nativeDistributions.appResourcesRootDir` (официальные каталоги `macos`/`macos-arm64`/`macos-x64`); в packaged `.app` найти его через `System.getProperty("compose.application.resources.dir")`. Для `:composeApp:run` передать путь к тому же compiled build output явно через JVM argument, без зависимости от current working directory. Архитектура helper должна совпадать с host package; Intel/Apple Silicon либо собирать отдельные артефакты, либо universal binary и проверять обе slices. Пакетный task обязан компилировать helper до копирования ресурсов, а не брать вручную оставленный бинарник. Проверить его наличие, executable bit, архитектуру и запуск **из** `.app`; будущая подпись/нотаризация должна подписывать и этот вложенный executable, но не относится к локальному UX3 gate. Официальное описание [Compose packaged resources](https://kotlinlang.org/docs/multiplatform/compose-native-distribution.html#adding-files-to-packaged-application) фиксирует `appResourcesRootDir` и `compose.application.resources.dir`.

Проверки моста: в `desktopTest` подставить fake line source/process для initial/change/malformed/EOF/close и подтвердить отсутствие позднего state update; отдельно на macOS запустить реальный Swift helper и сравнить initial values с System Settings, переключить Light↔Dark и Reduce Motion/Increase Contrast **при открытом процессе**, получить ровно обновлённый snapshot без restart; затем повторить в свежей `.app` и проверить реальную перекраску/отсутствие движения без изменения exercise ID, draft и FSRS. Compose test без смены системной настройки доказывает только mapping. Если KVO helper на конкретной macOS не даёт update, Developer возвращает Architect один воспроизводимый лог и выбирает другой документированный native observation mechanism; не заменяет его недокументированным `AppleInterfaceThemeChangedNotification` или периодическим чтением `defaults` под видом системного observer.

## Порядок реализации и приёмка

1. Desktop repository + migration и controller. Сначала зафиксировать RED для старого key, v1 precedence, corrupted raw, failed write/readback и для сохранения method/draft/FSRS. Затем убрать второго writer в `Main.kt` и подтвердить GREEN на desktop; общий codec уже имеет common tests, повторять их только при изменении.
2. Settings screen + MenuBar/`⌘,` + старые data actions. Проверить открытие из всех четырёх разделов, возврат, сохранение grammar/vocabulary transient state и отказ записи. Пункты prefs import/export вводить вместе с backup/readback и явным статусом.
3. OS observation spike и тема. Сначала подтвердить изменение OS appearance/Reduce Motion на живом процессе и packaged `.app`, затем подключить tokens и анимацию. Не выдавать `isSystemInDarkTheme()` или native bridge за динамический без host evidence. Убирать жёсткие цвета по всем desktop экранам; на общем `VocabularyScreen` scope через theme, не через macOS импорты.
4. Sidebar/toolbar, читаемая колонка, узкое окно и крупный текст. Снять before/after для одинаковой карточки; проверить полный путь Question→Revealed→Rating, один review и сохранение после restart. Потом Tester проверяет package и Reviewer читает diff/evidence.
