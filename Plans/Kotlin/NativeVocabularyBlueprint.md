# Нативный словарь · blueprint

Статус: реализован в локальных нативных хостах, приёмочные gates перечислены ниже и в [Evidence.md](Evidence.md). Основание: шаги 6 и 8 [CoursePacksPlan.md](CoursePacksPlan.md). Первая пара `pl-ru`; словарный документ не заменяет и не мигрирует грамматический прогресс. Исходное веб-поведение: `VocabularyWebController` и `VocabularyCodec`.

## Границы и владение

- `kotlin/shared/src/commonMain/kotlin/polski/vocabulary/`: состояние словарной сессии, команды и контракты репозитория. `VocabularyCodec` остаётся единственным сериализатором, генератором ключей двух направлений и проверкой документа. Время, UUID, планировщик и хранилище вводятся через интерфейсы; никакой UIKit/Android/JVM API в commonMain.
- Mac: `kotlin/composeApp/src/desktopMain/kotlin/polski/desktop/` владеет файловым репозиторием и системными диалогами импорт/экспорт; общий Compose Material экран в `composeApp/commonMain/ui/screens` используется Mac и Android с адаптацией расположения контролов и Android-свайпом. Документ `vocabulary-v1.json` в существующем Application Support каталоге, отдельно от `progress-v1.json`. Запись через существующий `writeDesktopJsonAtomically`, чтение с лимитом 10 МБ. Неверные исходные байты остаются доступными для экспорта, автоматическое пустое сохранение блокируется.
- Android: `kotlin/androidApp` владеет `AtomicFile` репозиторием, picker через Activity Result API и ViewModel lifecycle; `composeApp/commonMain` — экраном Material 3 и жестом оценки после раскрытия. Имя файла и grammar progress раздельны.
- iOS: `kotlin/shared/src/iosMain/kotlin/polski/ios/` владеет адаптером хранения и мостом JSON snapshot; SwiftUI — нативным экраном и системным fileImporter/fileExporter. JSON snapshot только представление, команда оценки идёт в Kotlin. Не вводить второе расписание на Swift-стороне.

## Общий контракт

`VocabularySession` получает `VocabularyRepository`, `Scheduler`, часы `() -> Instant` и генератор UUID; coroutine scope принадлежит host. `VocabularyUiState` содержит `VocabularyLoadStatus` (`Loading`, `Ready`, `RecoveryRequired`, `Unavailable`), неизменяемый `VocabularyDocument`, направление, подборку, режим ответа, текущий ID, введённый текст, фазу reveal, ошибку и флаг записи. Выбор карточки через `VocabularyCodec.dueIds`; смена направления снимает reveal и не меняет документы/ID. Рейтинг принимается только после reveal и только `Again`/`Good`; результат FSRS сохраняется до перехода к следующей карточке. Текстовый ответ не оценивается автоматически.

Мутации (`select`, `review`, create/update/delete own item, import merge) сериализуются одной mutex. Следующее состояние показывается после успешной записи и read-back; при ошибке остаётся прежний документ/карточка и выводится ошибка. Неверный документ не перезаписывается. Удаление пользовательской карточки требует подтверждения в host UI, исключает её из очереди, но сохраняет прежние SRS записи в экспортируемом JSON. Импорт валидируется до резервного копирования/замены, лимит 10 МБ; при объединении текущие локальные SRS записи имеют приоритет как в web. Экспорт возвращает байты из `VocabularyCodec.encode` либо исходные повреждённые байты в режиме восстановления.

Структура UI повторяет проверенный веб-контракт: направление `ru→pl` / `pl→ru`; сначала запрос, потом самостоятельное раскрытие; на обороте перевод, форма и предложение; затем только две оценки. Каталог A1/A2/B1 и вложенные топ-100/500/1000 использует `vocabularyItems`/`frequencyItems`; неподготовленные строки видны, но не выбираются. Редактор: лемма, перевод, форма, пример, уровень, проверка дубликата; импорт/экспорт JSON. Свайп на Android/iOS: влево `Повторить`, вправо `Вспомнил`, активен после reveal и имеет равноправные кнопки для доступности; вертикальный scroll не перехватывается.

## Проверки и порядок

1. Common test: раздельный FSRS по направлениям; выбор и снятие галочки; успешная запись перед переходом; ошибка записи сохраняет текущую карточку; повреждённый JSON не перезаписывается; импорт валидируется; редактирование сохраняет ID; удаление оставляет историю. React/Kotlin JSON fixtures сохраняют паритет.
2. Mac: репозиторий на временном каталоге с отказом записи/повреждёнными байтами; Compose desktop compile, запуск и проверка клавиатуры/узкого окна. Системный импорт/экспорт отдельно от грамматического JSON.
3. Android: `AtomicFile` тест и APK, Emulator с выбором слов, двумя направлениями, restart, импорт/экспорт, свайпом после reveal и TalkBack при доступности.
4. iOS: Kotlin iOS Simulator tests для snapshot/команд, SwiftUI build, iPhone/iPad Simulator с restart, импорт/экспорт, жестом после reveal и VoiceOver при доступности.
5. Tester сверяет с web, Reviewer читает diff и доказательства. Независимый Tester добавил приёмочные тесты для сессии и Desktop-репозитория; Reviewer выявил два Major-дефекта записи, после исправления повторно проверил соответствующий diff и одобрил его. Запуски на симуляторах и ручные сценарии фиксируются отдельно в `Evidence.md`.

Содержимое пакета остаётся первым незакрытым редакторским gate; этот blueprint допускает разработку независимого нативного хоста, но не закрывает шаги 1–2 и не объявляет 1000 лемм готовыми карточками.
