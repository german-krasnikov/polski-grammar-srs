# Режим слов и собственные карточки · завершение шага 6

Дата: 2026-09-24. Основание: [CoursePacksPlan.md](CoursePacksPlan.md), шаг 6, и существующий [NativeVocabularyBlueprint.md](NativeVocabularyBlueprint.md). Это handoff следующего этапа после каталога V1–V5, а не отчёт о пройденной приёмке. Первая пара остаётся `pl-ru`; пользователь выбрал виртуальные Android/iOS устройства для проверки.

## Фактическая база и незакрытый gate

`src/vocabulary/storage.ts` и `kotlin/shared/src/commonMain/kotlin/polski/vocabulary/VocabularyDocument.kt` уже используют отдельный документ `polski-vocabulary-pl-ru-v1` и два независимых ключа `pl-ru:vocabulary:ru-pl:<id>`/`pl-ru:vocabulary:pl-ru:<id>`. React, Kotlin Web, Desktop, Android и SwiftUI умеют выбирать слова, раскрывать ответ, вручную оценивать двумя кнопками, добавлять/редактировать собственные слова и вызывать импорт/экспорт. Нативный `VocabularySession` сериализует мутации перед переходом карточки. Android `MainActivity` и `AndroidSessionViewModel` используют Activity Result file picker и UTF-8 с ограничением 10 МБ; iOS `PolskiGrammarApp.swift` использует `fileImporter`/`fileExporter` и security-scoped чтение с тем же лимитом. [Evidence.md](Evidence.md) уже фиксирует отдельные Android Emulator/iPhone Simulator сценарии выбора, оценки и restart.

Открыт **наблюдаемый file picker round-trip** Android/iOS и Mac: экспорт через системный диалог → проверка файла → импорт через системный диалог → те же selectedIds, собственные поля и две истории FSRS после restart. Текущие unit/session тесты и наличие методов picker не доказывают этот сценарий. Также отдельно нужны видимый recovery повреждённого хранилища с экспортом **исходных байтов** без пустой перезаписи, отказ от импорта неправильной пары/превышенного размера без потери текущего документа и Kotlin→React чтение экспортированного файла. Лимит 10 МБ сейчас есть в Android/iOS/Mac importer и `VocabularySession.importJson`; React читает выбранный `File` без такого лимита, Kotlin Web принимает текст из textarea без file picker. Веб-ограничение размера не заявлять как уже существующий parity contract: если оно требуется продукту, добавить отдельно с тестами, а в этом шаге native oversized acceptance не приписывать браузерам. Реальные IME, VoiceOver/TalkBack и физические устройства остаются `NOT RUN` при виртуальной приёмке.

## Контракт и последовательность

1. **Снимок данных до правок.** Закрепить `tests/fixtures/react-vocabulary-sample.json` и все существующие shipped IDs после шага 5 (исходные 32 особенно). Выбрать одну поставляемую и одну пользовательскую карточку; записать `selectedIds`, `custom`, **четыре** независимые `cards` (по двум направлениям для каждого ID) и exact ключи. Сравнивать декодированные объекты и поля, не порядок ключей сериализатора. Снятая галочка исключает карточку из due, но не удаляет history; правка собственного текста сохраняет ID/history; повторная лемма при create/edit отклоняется с видимой причиной; удаление собственного слова требует подтверждения и сохраняет архивные `cards` в экспорте. Новые готовые записи каталога шага 5 не меняют прежние ID.
2. **Web и Desktop.** После Step5 source freeze проверить React file import ↔ Kotlin JS/Wasm textarea import/JSON export с двумя направлениями и своим словом; browser reload, storage failure и недействительный JSON. Desktop в автоматическом тесте использует временный каталог и реальные репозитории; отдельный UI-прогон проверяет системный picker, отмену, неверную pair, файл больше 10 МБ и повторное открытие приложения. При повреждённом локальном документе каждый host показывает recovery, отдаёт исходный raw JSON для экспорта и не записывает пустой документ до явного успешного импорта. Проверить отмену picker без записи и отсутствие побочного review. Импорт — merge, не replacement: selectedIds объединяются, локальные custom поля и локальные FSRS cards побеждают при совпадающем ID/key, новые import-only ID/cards добавляются. В **заполненном** профиле imported custom с новым ID и нормализованной польской lemma существующей custom/готовой shipped записи отклоняется до записи с видимой причиной. При восстановлении старого v1 экспорта в **пустой** профиль (нет selectedIds, custom и cards) ID и историю custom, чья лемма позднее стала готовой shipped, необходимо сохранить; частотная строка остаётся привязана только к shipped ID, а custom виден отдельно в «Мои слова». Wire v1 не содержит версии каталога или доказуемого времени создания: старый экспорт и вручную созданный файл с теми же байтами неразличимы, поэтому допуск shipped-homonym при пустом restore — осознанная граница совместимости. В заполненном профиле новые коллизии по-прежнему fail-closed; резервная копия не переписывается. Добавить регрессию `merge(empty, legacy export)` на React/Kotlin и через путь импорта. Изменять доменную модель только по воспроизводимому дефекту.
3. **Android Emulator.** Установить свежий APK, выбрать две карточки, создать своё слово, получить review в каждом направлении после reveal. В системном CreateDocument записать экспорт; через `content://` прочитать фактические байты и сверить v1 документ. Внести контролируемую добавочную запись в валидный JSON без уничтожения текущих review, затем вызвать GetContent и проверить приоритет локальной истории после merge, результат на экране и после force-stop/restart. Повторить с неправильной pair/битым JSON/файлом больше 10 МБ и отменой picker; во всех случаях сохранить текущие байты/review. Свайп влево/вправо проверять только после reveal, вертикальная прокрутка должна оставаться доступной. Android platform files не копировать напрямую в private app storage для обхода picker.
4. **iPhone Simulator.** XCTest либо последовательный UI-прогон проходит SwiftUI `.fileExporter` и `.fileImporter`, проверяет реальный файл в simulator Files, те же `selectedIds`/`custom`/четыре `cards` после завершения и нового запуска, затем invalid pair/JSON/файл больше 10 МБ и отмену picker без потери документа. Security-scoped доступ тестируется через тот же UI путь. Если Files-provider в simulator не даёт стабильного автоматического сценария, отметить конкретный шаг `NOT RUN`, приложить воспроизводимое наблюдение и проверить доступный bridge/unit путь отдельно, не объявляя round-trip PASS.
5. **Сверка и решение.** Tester независимо читает экспортируемые байты и исполняет сценарии на свежих артефактах; Reviewer проверяет возможный production diff и evidence. Root фиксирует PASS/FAIL/NOT RUN отдельно для React, Kotlin JS/Wasm, Desktop, Android Emulator, iPhone Simulator и физических/accessibility gate. После исправления дефекта повторяются затронутые сценарии. Коммит, публикация и новые языковые пары из этого этапа не следуют.
