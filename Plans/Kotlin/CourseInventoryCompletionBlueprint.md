# Срез course pack: редакторская инвентаризация и gate завершения

## Scope и текущее состояние

Партия 6 [CoursePackRemainingRoadmap.md](CoursePackRemainingRoadmap.md) этапов 1–2 [CoursePacksPlan.md](CoursePacksPlan.md), после приёмки партий 0–5. Исходный срез проекта имел 33 файла и 1628 строк-кандидатов по кавычкам/backtick; это историческая база проектирования. Реализованный генератор рекурсивно охватывает 101 production-файл React/TS, Kotlin source sets и SwiftUI, включая JSX text и внутренние строки многострочных литералов. Текущий generated `source-inventory.json` содержит 2365 строк-кандидатов, а `inventory-decisions.json` и `inventory-coverage.json` разворачивают их в 4504 отдельные части. Imports, JSON/DOM keys, enum ID, ошибки, URL и несколько literals на одной строке тоже входят в счёт, поэтому он не равен числу учебных фраз. Ключ решения — path + enclosing symbol + SHA-256 exact source + occurrence; номер строки и sha256 всего файла используются только для навигации и проверки свежести. Generated inventory и coverage report не редактировать вручную.

После партий 0–5 ожидаются только узкие остатки авторского курса, которые надо подтвердить на свежем inventory, а не считать уже перенесёнными:

## Стабильные решения и checker

Реализованы courses/pl-ru/inventory-decisions.json и courses/schema/inventory-decisions-v1.schema.json. Не менять пользовательский schemaVersion pack или progress. Каждое решение имеет path, symbol (реальное имя функции/компонента/объекта либо file-scope), `sourceFingerprint` (SHA-256 от exact `literalLines.source`, без номера строки), `occurrence` среди одинаковых строк в том же symbol, category, непустой reason и при pack-backed — `packPointer` в course.json. Допустимые категории: `pack-backed-authored`, `runtime-morphology`, `ui-localization-chrome`, `serialization-plumbing`, `diagnostic` и узкая `inactive-prototype` для пяти allowlisted файлов прежнего Compose spike. Checker запрещает эту категорию вне списка и любое обращение к `SpikeScreen` из production-кода; прототип не является экраном приложения. Для совпадающего source с несколькими string tokens — `parts` с точным ordinal токена, category/reason/packPointer каждого; не разрешать одну метку `mixed`, которая скрыла бы учебную фразу. Пример смыслового ключа: path `src/ui/GrammarTables.tsx`, symbol `CaseReference`, sourceFingerprint текущей строки с цветовой подсказкой, occurrence 1; отдельные parts отмечают грамматический тезис и цветовое UI-пояснение. `line` хранить только в generated отчёте для перехода к коду. Если строка содержит кавычку лишь как синтаксис/апостроф без string token, нужна явная `serialization-plumbing` или `ui-localization-chrome` запись с причиной, не молчаливый skip.

Реализованы scripts/check-course-inventory.mjs и `npm run course:inventory:decisions:check`; CI выполняет этот gate. Checker сначала сверяет свежесть source-inventory.json через существующий `node scripts/inventory-course.mjs --check`, затем строит кандидаты из его literalLines и сопоставляет path + symbol + sourceFingerprint + occurrence. Для TS/TSX получать enclosing symbol/string spans из установленного TypeScript scanner/AST; Kotlin/Swift обрабатывать quote-aware lexical scanner с учётом escapes и multiline literals, но не пытаться угадать смысл. Нераспознанный синтаксис и неоднозначный symbol должны завершаться ошибкой с path/line, а не выпадать из аудита. Checker обязан обнаружить неизвестный candidate, устаревшее/дублирующееся решение, непокрытый token внутри длинной строки, недопустимую category, пустую причину, неверный packPointer и смену source текста. Сдвиг строк без изменения source/symbol не меняет ключ; изменение литерала или появление одинакового литерала в том же symbol требует осознанной повторной классификации. Для частых однородных imports/JSON keys допустимы узкие проверяемые правила, но итоговый machine-readable coverage report всё равно разворачивает их в path/symbol/category/reason по каждому кандидату; broad regex по языку запрещён. `sha256` файла остаётся индикатором свежести inventory, не ключом решения.

Поскольку line-based inventory объединяет много literals в длинной строке App.tsx/GrammarTables.tsx, checker должен показывать каждый token/часть при review. Для pack-backed решения требовать own-property JSON pointer на непустой строковый лист, token с точным именем листа и отсутствие второй hardcoded копии целой авторской строки в любом охваченном production-файле; если source содержит только adapter access или динамический formatter, классифицировать соответствующий программный token отдельно. Автоматическая проверка не определяет, является ли текст учебным: Developer/редактор принимает это решение и документирует reason; Tester вручную аудирует спорные польские/русские фразы и выборочно сверяет пять хостов, Reviewer оценивает ложные exemptions. Не создавать тысячи фиктивных тестов по формулировкам.

## Gate «pl-ru pack complete»

Все партии 0–6 имеют принятый source diff и актуальные PASS/FAIL/NOT RUN в Plans/Kotlin/Evidence.md; source-inventory свежий, checker решений даёт 100% coverage без unknown/stale/mixed, а ручной аудит не находит польской формы, учебной схемы, демонстрационного предложения или русской грамматической подсказки, доступной только в одном host. Для новых reference/vocabulary fields есть strict schema, semantic links, exact before/after fixtures и реальные consumers React/Kotlin Web/Desktop/Android/iOS (включая iOS snapshot), без пустых fallback. Офлайн загрузка курса и валидатор проходят; pinned grammar/exercise/progress fixtures и P01–P08 сохраняются либо отличаются лишь по отдельно согласованной редакторской правке. Browser, simulator и physical-device evidence фиксируются раздельно: pack-complete не закрывает web parity и device gates [Plan.md](Plan.md). При недоступном устройстве писать NOT RUN, не PASS.

Developer выполнил извлечение содержания и адаптеры; основной агент реализовал decisions/schema/checker и расширенный source audit. Tester независимо проверяет acceptance, Reviewer оценивает итоговый diff и обоснования классификаций. Фактические PASS/FAIL/NOT RUN записываются в Evidence.md и отчёте Tester; исторический blueprint сам по себе не закрывает исходный web/device gate.
