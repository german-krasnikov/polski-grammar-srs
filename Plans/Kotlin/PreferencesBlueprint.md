# UX1 — контракт настроек и перехода от прежних ключей

Статус: архитектурный handoff к [PlatformUXPlan.md](PlatformUXPlan.md), **не реализация**. Подготовлен по текущим `AppUiState`, `TrainingStore`, `VocabularySession` и четырём host 2026-09-24. Начать код после фиксации итоговых артефактов CoursePacks 7–9. Основной [workflow](../../.agents/skills/workflow/SKILL.md) требует Developer → Tester → Reviewer; этот handoff не объявляет их проверки выполненными.

## Данные и владелец

- **NEW** `kotlin/shared/src/commonMain/kotlin/polski/preferences/UserPreferences.kt`: `UserPreferencesV1` с явными wire values. Поля: `schemaVersion=1`, `coursePair="pl-ru"`, `explanationMethod=Logic|Situations`, `answerMode=Oral|Typed`, `appearance=System|Light|Dark`, `motion=System|Reduced`, `swipeRatingEnabled` и `reminder` (`enabled=false`, local time, days, quiet hours). Неподдерживаемые языковые пары и невозможные дни/время — ошибка валидации. **Правило v1:** неизвестные поля/enum и версия >1 отклоняются с сохранением исходного raw для восстановления; новые поля требуют новой версии schema и явной миграции, чтобы старый клиент не потерял их при записи. Разрешение OS, next scheduled request ID и текущее системное appearance **не** записываются как пользовательский выбор.
- **NEW** `UserPreferencesCodec.kt`: чистое decode/encode/validate без платформенного storage. Дефолты совместимы с нынешним методом `Logic`, устным ответом и системной темой; напоминания выключены. Неполный v1 использует явно разрешённые defaults; неизвестная версия не откатывается к v1 автоматически. При нечитаемом документе вернуть raw + reason для экспорта/восстановления, не записывать поверх него дефолт.
- **NEW** `UserPreferencesRepository.kt`: узкий read/write raw contract с typed исходами `Loaded`, `Missing`, `RecoveryRequired`, `Unavailable` и `Saved`, `WriteFailed`; реализация не меняет `ProgressDocument`, `VocabularyDocument` или FSRS. Если общий интерфейс не добавляет полезной подстановки во всех host, оставить codec общим, а repository contract минимальным. Сохранение предпочтения и UI-подтверждение результата различаются; отказ записи показывается, выбранное в памяти значение остаётся экспортируемым. Перед явным импортом настроек сохранить текущий валидный v1 raw в отдельный backup, затем проверить запись чтением; при сбое сохранить прежний активный документ и backup для восстановления. Миграция старого ключа также не удаляет исходный ключ до успешной записи/чтения нового v1.
- Один session-level coordinator/controller владеет snapshot предпочтений и направляет изменения в `TrainingStore`. Текущий `SetExplanationMethod` остаётся семантическим действием, но все UI entrypoints, включая picker на карточке и Settings, проходят через один action router, который меняет предпочтение и диспатчит его в store. Нельзя одновременно оставлять прежние host `LaunchedEffect(state.explanationMethod)`/DOM listener как второй writer. Изменение внешнего вида/жеста не диспатчит `Rate`, не меняет `ProgressDocument` и не пересоздаёт карточку. Тема — render parameter host, не поле FSRS state.
- Сейчас `AppAction.SetAnswerMode` работает только в `CardPhase.Question`. Если пользователь меняет предпочтение ответа в Settings во время `Revealed`, сохранить выбор в `UserPreferencesV1`, не менять показанную оценку/замороженный ответ и применить режим при следующем `Question`; тест должен покрывать эту границу.

## Миграция по host и границы

| Host | Существующий ключ | Новый adapter и порядок |
| --- | --- | --- |
| React baseline / Kotlin web | `localStorage['polski-explanation-method-v1']` со значениями `logic|situations`; оба на одном origin видят ключ | В Kotlin JS/Wasm web adapter читать новый отдельный ключ `polski-preferences-v1` первым. Если его нет, взять прежний method key, создать v1 и записать **после успешной проверки**. Не удалять старый ключ до отдельного cutover; React остаётся эталоном. При отказе LocalStorage оставаться в памяти и предлагать JSON recovery. |
| Mac Compose JVM | `Preferences` key `explanationMethod=Logic|Situations` в текущем `Main.kt` | Новый `desktopMain` adapter читает свой JSON в app-specific Application Support; при отсутствии переносит прежний preference key. Запись атомарна по macOS file contract, старый ключ сохраняется до проверки обратной совместимости. `⌘,`/menu и native JSON picker — host effects. |
| Android | `SharedPreferences("polski-preferences")["explanationMethod"]`, `AndroidSessionViewModel.kt`/`MainActivity.kt` | Новый `androidMain`/application adapter использует app-private storage с сериализацией writes. При отсутствии нового v1 переносит старый key. Смена конфигурации и process death не должны откатить ещё не подтверждённый выбор без сообщения об отказе записи. OS notification permission/channel status читается отдельно. |
| iOS/iPadOS | `NSUserDefaults["explanationMethod"]` в `IosSession.kt` | Новый `iosMain` adapter/узкий Swift bridge читает отдельный v1 key сначала, затем старый. `UNUserNotificationCenter` status остаётся в Swift host. `IosSnapshot` передаёт immutable preferences для SwiftUI, SwiftUI действия проходят через bridge без дублирующего writer в `@State`. |

Миграция идемпотентна: первый запуск с новым v1 не перечитывает устаревший method key; повторный запуск после сбоя записи повторяет перенос без потери исходных данных. Не использовать общий ключ `localStorage` на разных origin как псевдосинхронизацию. Для React не объявлять новые темы/настройки реализованными: это сохранённый эталон, а UX2 относится к Kotlin web.

## Интеграция и порядок реализации

1. Зафиксировать v1 JSON fixture: все варианты enum, дефолты, неправильные типы/диапазоны, неизвестную версию и сохранение raw. Сначала наблюдаемый RED на общем codec/controller, затем минимальная реализация и GREEN в JS/Wasm/Desktop/iOS simulator targets по доступным задачам.
2. Подключить web adapter и UI action router; написать browser acceptance «старый `situations` → новый v1 → reload», «Settings ↔ picker, черновик/карточка/FSRS не изменились», «storage denied → экспорт и retry». Только после этого убрать web writer старого ключа из Kotlin. React key не удалять.
3. Подключить Mac, Android, iOS adapters последовательно по [UX3–UX5](PlatformUXPlan.md), сохранив одно и то же wire schema. Для каждого: legacy method migration, UI Settings ↔ карточка, interruption/restart, failed write/recovery, системная/ручная тема. Не связывать завершение UX1 с уведомлениями: delivery gates описаны отдельно.
4. Перенести кнопки progress/vocabulary import/export в Settings, оставив доступный путь к ним на прежних экранах до проверки навигации и screen-reader discoverability. Сами v1 payloads и правила безопасного импорта остаются прежними.

## Критерии UX1

- **PR1** old method key на каждом host при отсутствии v1 даёт тот же метод после двух запусков; новый v1 выигрывает у старого ключа, если оба есть.
- **PR2** смена метода или темы в Settings и на карточке отражается в обоих местах без новой FSRS записи, потери черновика/фокуса/выбранного слова; тёмная/светлая ручная тема переживает restart. Режим ответа, выбранный при открытом эталоне, применяется лишь на следующем вопросе.
- **PR3** неизвестное поле/версия, malformed JSON и write failure не заменяют исходный raw дефолтом и доступны пользователю для экспорта/восстановления. Явный импорт валидного v1 создаёт backup прежнего v1; имитация сбоя записи/readback оставляет прежний активный документ и доступный backup.
- **PR4** current/legacy progress JSON, оба направления слов, 32 approved cards и две оценки дают прежние ID, интервалы и сериализованный FSRS независимо от preference changes.
- **PR5** `system` appearance и motion реагируют на изменение OS/браузера во время активного экрана; ручной override не сбрасывается; контраст source/target и доступность проверяются в обеих палитрах.

Developer фиксирует фактические команды/RED/GREEN. Tester проверяет новые сценарии на поддерживаемых target и не выдаёт common test за UI/notification evidence. Reviewer оценивает итоговый diff, миграцию, ресурсный lifecycle и отсутствие второго writer. Публикация и удаление старых ключей — отдельные решения.
