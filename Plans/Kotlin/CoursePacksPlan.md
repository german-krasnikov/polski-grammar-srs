# Курсы, способы обучения и карточки слов

Последующее обновление интерфейса, адаптивной навигации, настроек, светлой/тёмной темы и напоминаний описано в [PlatformUXPlan.md](PlatformUXPlan.md). Его UX0–UX6 начинаются после сохранения текущей виртуальной приёмки шагов 7–9; открытые физические/IME/assistive gates остаются открытыми.

Дата: 2026-09-23. Статус: проектирование завершено по ответам пользователя; веб-реализация частично готова, полная приёмка ещё открыта. Первый рабочий курс: **польский для русскоязычного учащегося**. Новые изучаемые/родные языки нельзя показывать доступными, пока для них нет проверенного содержания. Web — первый target, затем Mac, Android и iOS.

## Продуктовый контракт

- Независимые параметры: изучаемый язык, родной язык, методика объяснения и режим занятий. Первая языковая пара `pl-ru`; выбор других пар появится только с готовыми пакетами. Пользователь свободно меняет методику, сохраняя карточки и FSRS. Методики можно добавлять без копирования экранов.
- Две первые методики: **«Схемы и логика»** (нынешняя последовательная аналитическая подача) и **«Живые ситуации»** (сначала смысл и контекст, затем наблюдение формы и короткое правило). Они могут различаться порядком вводных примеров, подсказками и типом первого шага задания; правильные польские формы и оценка FSRS одинаковы. Не описывать их как врождённые типы мозга. [Обзор APS](https://www.psychologicalscience.org/journals/pspi/j.1539-6053.2009.01038.x/) и [метаанализ 2024 года](https://www.frontiersin.org/journals/psychology/articles/10.3389/fpsyg.2024.1428732/full) не подтверждают надёжно подбор обучения по «стилю мозга». Выбор методики — предпочтение и проверяемая гипотеза UX, а не диагноз.
- Режимы: существующие грамматические преобразования/цепочка, повторение по расписанию и **слова**. Карточки слов идут в двух отдельных направлениях: родной → изучаемый (воспроизведение) и изучаемый → родной (узнавание). Каждое направление имеет отдельный FSRS ID; [эксперимент по receptive/productive retrieval](https://www.jstage.jst.go.jp/article/katejournal/30/0/30_11/_article) обнаружил разные результаты для этих двух тренировок. В обоих направлениях после раскрытия видны перевод, форма, короткий пример в предложении и две оценки «Повторить»/«Вспомнил»; на мобильных — прежние жесты. Аудио сейчас не входит.
- Словарь: каталог по ступеням A1/A2/B1… и кумулятивные частотные срезы топ-100/500/1000; пользователь отмечает слова галочками и может создать/редактировать свои. Частотный ранг и учебный уровень — **разные** поля. Частота сама по себе не сертифицирует уровень CEFR: авторы [нового польского частотного списка](https://academic.oup.com/ijl/article/doi/10.1093/ijl/ecag032/8823755) прямо предлагают проверять педагогическое сопоставление. В интерфейсе не называть автоматическую разметку «официальным A1». Только готовые карточки с проверенным переводом и примером доступны для тренировки.
- Прогресс разделён по языковой паре, режиму/направлению и учебному элементу. Существующие польские грамматические skill IDs и JSON v1 остаются читаемыми без обнуления. Снятие галочки со слова исключает его из очереди, но не удаляет историю. Переключение методики не меняет ID. Пользовательские карточки получают стабильный локальный ID и входят в экспорт/импорт; удаление требует подтверждения, история не переписывается молча.
- Сравнение «было → стало»: красная старая часть видна уже на лицевой стороне грамматической карточки, новая часть показывается только после раскрытия и выделяется другим контрастным цветом. При надёжной морфемной паре выделяются окончания; при полной замене — слова/группы целиком с подписью. В эталоне, паре форм, правилах с явными примерами и **каждой строке таблицы** показывается конкретная опора для сравнения. Перевод слова в другой язык — смысловая пара, поэтому в словарной карточке подписывать языки и выделять целые слова, не изображать перевод как морфемное изменение. Цвет дублируют подписи и разные подчёркивания, как требует [WCAG](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color).

## Архитектура и границы

### Blueprint первого незакрытого gate · инвентаризация и валидация

- Источник данных остаётся `courses/pl-ru/course.json` и `frequency-top1000.json`. NEW `courses/schema/*.schema.json` описывает wire-формат версии 1; NEW `scripts/validate-course.mjs` проверяет schema и связи между ID, prerequisite и частотным рангом до сборки. Ни React, ни Kotlin не получают права исправлять неверный пакет при чтении. Валидация авторского пакета идёт в npm build и CI; Kotlin runtime сохраняет собственную защиту от неверного встроенного JSON.
- NEW `courses/pl-ru/source-inventory.json` фиксирует места, где контент ещё в TS/Kotlin UI или фабриках, с владельцем и состоянием переноса. Удалять строку из исходного кода можно только после побайтовой сверки соответствующих exercise/matrix fixtures. Для новых языков пакет и его локализация не должны менять польские skill IDs или текущие ключи прогресса.
- Валидация — чистый Node-инструмент автора курса без обращения к хранилищу пользователя. Не допускаются пустые формы, неизвестные зависимости навыков, цикл prerequisites, дубли ID/лемм/рангов, несоответствие `frequencyRank → lemma`, HTML-подобные теги и неготовая словарная карточка без перевода/формы/примера. Браузерный код не загружает Ajv. Ошибка возвращает путь поля и ненулевой exit code, не перезаписывая пакет.
- Приёмка: валидный текущий пакет проходит; изменённые временные копии получают отказ по каждому независимому классу ошибок; React и Kotlin parity fixtures и старый прогресс не меняются. После schema gate переносить генераторные тексты и таблицы по одному семейству, запуская только затронутые проверки.

1. Версионированный пакет содержания `courses/pl-ru/` (NEW) хранит manifest (`target=pl`, `native=ru`, version, авторство/лицензии), skills, лексемы, переводы, примеры, тематические/частотные подборки, варианты объяснений и явные пары `before/after` с выделенными сегментами там, где автоматическое сопоставление небезопасно. JSON валидируется в CI и загружается в React и Kotlin из **одного источника**. Извлечённые из кода польские материалы сверяются с pinned fixtures побуквенно до удаления дублей. Формат контента не содержит HTML или исполняемый код.
2. Общие Kotlin-контракты в `kotlin/shared`: `CoursePack`, `LearningItem`, `StudyDirection`, `ExplanationMethod`, `FocusSpan` и валидатор. UI получает уже подготовленный `StudyCard`; морфология, SRS, хранение, источник времени и случайности остаются программной логикой. Для польской грамматики можно иметь адаптер генерации, но польские тексты, таблицы, списки слов и схемы не живут в UI. Новые языки добавляют pack и, только если требуется, узкий морфологический адаптер; не копируют Store/экраны.
3. Подсветка — чистая презентационная функция над **явными сегментами** из учебного пакета или над проверенной парой форм текущей грамматической фабрики. Эвристика общего префикса — ограниченный fallback польского существующего контента, никогда не выдаёт догадку за достоверную морфему. Для словарной пары и неоднозначных форм отмечается целая единица. Сопоставление с контекстным предложением сохраняет исходные буквы, регистр и пунктуацию; неподходящий фрагмент не окрашивается.
4. Пользовательский словарь — отдельный документ хранения с валидацией, версиями, резервным экспортом и безопасным импортом. Поставляемый пакет неизменяем. ID пользовательской карточки не зависит от редактируемого текста; правка перевода/примера не сбрасывает FSRS автоматически. React legacy progress и Kotlin v1 остаются нетронутыми, расширение — с сохранением неизвестных полей и явной миграцией, если понадобится новая schema.
5. Контракт методики содержит этапы `introduce → retrieve → feedback → review` и варианты текста/порядка; общие доказательные элементы доступны в обеих методиках: активное воспоминание, повторение с интервалами, контекст и обратная связь. [Исследование spaced L2 vocabulary](https://www.cambridge.org/core/journals/applied-psycholinguistics/article/abs/testing-the-deficient-processing-account-of-the-spacing-effect-in-second-language-vocabulary-learning-evidence-from-eye-tracking/988917446309D54CDDD868BDAA532C18) поддерживает разнесение повторов, но оптимальный способ объяснения для наших пользователей ещё требует измерений. Подсветка не заменяет контекст: [метаанализ visual enhancement](https://www.cambridge.org/core/journals/studies-in-second-language-acquisition/article/abs/visual-input-enhancement-and-grammar-learning-a-metaanalytic-review/B9D0C50B09928C20C94548B37B29A042) нашёл небольшой средний эффект и возможную цену для понимания смысла.
6. Для «Живых ситуаций» редакторский шаблон: короткая узнаваемая сцена → одна фраза с понятным намерением говорящего → вопрос о значении → явное сравнение польских форм и краткое правило → самостоятельное воспроизведение → объяснение после ответа. [Метаанализ эксплицитного обучения L2](https://onlinelibrary.wiley.com/doi/10.1111/flan.12726) поддерживает включение ясного правила, но не доказывает превосходство именно этого шаблона. [Исследование контекста при извлечении слова](https://www.jstage.jst.go.jp/article/let/61/0/61_125/_article) обнаружило выигрыш в узнавании значения, но не в воспроизведении формы или значения; поэтому пример в предложении не заменяет отдельное задание на recall. На первых заданиях одного правила давать однотипную управляемую практику, после освоения смешивать с другими формами и расписанием FSRS. Это проектная гипотеза, опирающаяся в том числе на [исследование blocked/interleaved practice](https://onlinelibrary.wiley.com/doi/full/10.1111/lang.12659) у конкретной группы подростков, а не универсальная настройка «типа мозга». Измерять отдельно completion, долю правильных ответов и отложенное удержание; сравнивать при одинаковом содержании и расписании.

## Последовательность выполнения и gate

1. **Инвентаризация и данные.** Зафиксировать все польские строки в `src/data`, `src/training`, `src/ui/GrammarTables.tsx` и `kotlin/shared/data`, `ExerciseFactory`, `MatrixWeb`, native matrix hosts; записать происхождение и лицензии. Разделить учебные данные, языковые шаблоны и алгоритмы. Выход: machine-readable pack schema, набор pinned Polish fixtures и тесты валидации. Gate: ни одна старая форма/цепочка/прогресс не меняется.
2. **Первый пакет `pl-ru`.** Вынести словари, skills, переводы, формулы, объяснения, иллюстративные схемы и списки из кода; один источник генерирует/поставляет данные React и Kotlin. Переподключить старую грамматическую фабрику без изменения результатов. Gate: fixtures/React/Kotlin parity, отказ на неверный пакет, offline load.
3. **Контраст в грамматике.** Реализовать [детальный контракт подсветки](ContrastHighlightPlan.md) на web: исходное красное до reveal, эталон и пара форм после, все строки таблиц с опорой. Наблюдаемый браузерный RED уже получен для отсутствующей красной части в React и Kotlin DOM. Gate: польские диакритики, замены, несколько изменений, темная/светлая тема, 320 px, текстовая альтернатива цвету и отсутствие раннего эталона. Реализация и виртуальные проверки записаны в [Step3 Tester report](Stage-ContrastCompletion-Tester.md); финальное независимое ревью CSS-fix одобрено 24 сентября.
4. **Методики.** Подключить два варианта объяснения и первого учебного шага из pack, селектор и сохранение предпочтения отдельно от прогресса. Методику можно менять на текущей карточке без нового review и потери введённого ответа. Подробный [архитектурный handoff](MethodologyCycleBlueprint.md) фиксирует `introduce → retrieve → feedback → review` и A1–A7. Gate: одинаковые правильные ответы/FSRS; каждая сцена соответствует любому предложению, которое может выдать генератор для навыка, не раскрывает эталон до ответа и не заявляет ложной «нейроподстройки». После появления полного цикла сравнить отложенное удержание при одинаковых заданиях и интервалах.
5. **Словарный каталог.** Использовать доступный лицензированный частотный источник [Leksjo / NKJP, CC BY 4.0](https://github.com/KubaCiolo/leksjo-dane) и документировать атрибуцию. Топ-100/500/1000 должны быть вложенными срезами, а не тремя копиями карточек. Переводы и короткие примеры проходят редакторскую проверку; при использовании [Tatoeba](https://en.wiki.tatoeba.org/articles/show/using-the-tatoeba-corpus) соблюдать атрибуцию предложений. A1/A2/B1 метки проверять отдельно, не выводить автоматически из ранга. Подробный [архитектурный handoff](VocabularyCatalogBlueprint.md) фиксирует редакторский процесс и V1–V5. Gate: нет карточек без перевода/примера, диапазоны и источники честно обозначены.
6. **Режим слов и собственные карточки.** Выбор галочками, две независимые стороны recall, oral/typed reveal, ручная оценка, очередь только выбранных слов; локальный редактор с созданием, изменением, удалением, дубликатами, экспортом/импортом и восстановлением после перезапуска. [Handoff завершения](VocabularyModesCompletionBlueprint.md) фиксирует оставшийся системный file picker round-trip и проверку повреждённых данных на виртуальных устройствах. Gate: раздельный прогресс направлений, безопасное сохранение, обратная совместимость со старым JSON и отсутствие автоматической оценки FSRS по опечатке.
7. **Web приёмка.** React baseline + Kotlin Wasm/JS в Chromium/Firefox/WebKit, затем реальный мобильный Safari/Android browser при доступности. [Финальный виртуальный handoff](FinalVirtualAcceptanceBlueprint.md) задаёт остаточные P02–P12 сценарии и проверку свежести артефактов. Критерии: старая цепочка и FSRS fixtures не теряются; переключение методики, список/редактор и обе стороны слов переживают reload; клавиатура/IME/доступность/узкий экран работают. Исправить FAIL и повторить затронутые тесты.
8. **Mac → Android → iOS.** Использовать те же pack/domain/state, но нативные контролы и системные темы; мобильные свайпы только после reveal. На каждом target отдельно проверять сборку, тесты, запуск и UI. Никаких заявлений о физических устройствах или screen readers по результату симулятора.
9. **Tester → Reviewer → docs.** Независимая приёмка по фактическому diff, включая лицензии/атрибуцию, безопасность импорта, ресурсный lifecycle и старый прогресс. Затем обновить README/product contract/верификацию. Коммит, публикация и включение новых языков требуют отдельного решения.
