# Module design: TrainingStore и web UI (этапы 8–10)

## Scope and consumers

Этап 8 переносит единственный владелец учебной сессии из `src/ui/App.tsx` в общий Kotlin state holder. Этапы 9–10 отображают его в браузере: тренировка, контекстная справка, четыре раздела матрицы и прогресс. React/TypeScript остаётся эталоном поведения; производство, React deploy, нативные hosts и новая функция импорта в UI не входят в эти этапы. Контрольные случаи — `Plans/Kotlin/Plan.md` P02–P09/P11/P12 и `Plans/Kotlin/Parity.md`. Фактический web spike в `kotlin/composeApp/src/webMain/kotlin/polski/ui/SpikeHtmlControls.kt` доказал `HtmlElementView` для DOM textarea/buttons/table на JS и Wasm в desktop браузерах; `Plans/Kotlin/WebCompatibility.md` оставляет physical browser/IME/screen reader gate открытым. Реализацию full UI надо строить на этой проверенной web ветке, сохранив возможность узкого DOM host для проблемного элемента после device evidence.

Входы store: действия пользователя, `ExerciseFactory` (`kotlin/shared/src/commonMain/kotlin/polski/training/ExerciseFactory.kt`), `evaluate` (`.../training/AnswerEvaluator.kt`), `nextSkillId` (`.../training/SkillQueue.kt`), `Scheduler` (`.../srs/Scheduler.kt`), прогресс/review/codec/repository этапа 7, часы/локальный день и результаты host effects. Выходы: неизменяемый `AppUiState` и очередь подтверждаемых `UiEffect`. Store не зависит от DOM, Compose, LocalStorage или системного времени. Compose/DOM слой не выбирает случайную карточку, не оценивает ответ и не записывает progress. Compose shared UI остаётся пригодным для будущих native hosts; этот план не объявляет их реализованными.

`Rate` is legal only for the currently revealed, unrated `exerciseId`. It marks that ID consumed synchronously in the reducer before launching persistence, captures **one** `Instant` and local day for `recordReview`, and advances once. Oral correctness derives from rating (`Again` is mistake); typed correctness comes from the evaluation frozen at `Reveal`, regardless of rating. `EditAnswer` after reveal is ignored. Revealing an empty typed answer is allowed and incorrect. Answer mode can change before reveal; the draft remains until exercise replacement, matching `App.tsx`. Rating preview uses the card and captured display time, never recomposes into another FSRS result without a time refresh.

There is one mutable authority: `TrainingStore`. View callbacks send actions. Browser adapters implement effects/time/storage capabilities; domain functions remain in `shared`. Matrix selectors are presentation state in store for deterministic navigation. React mounts `GrammarTables` only while matrix tab is active: entering from another tab initializes section `map`, noun `wife`, adjective `beautiful`, owner `my`, number `sg`, verb `do`, masculine group. Selector changes persist while staying on matrix, then reset on a later matrix entry; drill actions read the current selection before leaving. Switching to progress or matrix does **not** replace the current training exercise, draft, reveal or reference flag. Returning to training shows the same card and phase. The reference panel itself is independent of matrix selector state.

## State and resources

Initial session: tab `train`, mode `chain`, seed index 0, first generated five-card chain, oral mode, answer hidden, reference/picker closed. Progress loading precedes actionable rating; if stage-7 migration returns recovery-needed/unsupported, show the recovery/export path and do not start a fresh write over source bytes. Starting chain resets chain index/completion/draft/reveal, chooses the requested seed and shows its first card. The next-seed button at completion uses `(seedIndex + 1) % 12`. Starting schedule clears stale answer/reveal, selects earliest due only if `due <= captured now`; with no due cards it shows completion and the earliest future due across all cards. Refresh can move `NoDue` into a due card without a mode click; do not show next due from the stale current exercise. Choosing a skill from picker/progress/table enters focused mode, generates one exercise with optional preferred noun/adjective seed, and subsequent focused ratings stay on that skill with a new exercise. Matrix `chain` drill uses matching noun seed and restarts at step 1. Each mode change clears stale answer/review guard. Picker open/close alone does not change mode/card.

At reveal, store freezes the exact typed text and `Evaluation`; accepted variants use existing evaluator. Back shows expected, accepted, changes, explanation/formula and four interval previews. Five accepted chain ratings save progress and show all five expected sentences; no sixth review can be created from the completion state. Tab/reference changes preserve the same `exerciseId`. A `Rate` with stale ID, repeated click/key, or pending old button after animation is a no-op. Card replacement gets a `FocusReveal(newExerciseId)` effect after renderer has attached the new button. React's current `rate` calls focus before the replacement mounts, and `react-baseline.spec.ts` records the resulting focus defect; Kotlin is required to focus the new reveal control. The focus effect expires if its exercise is no longer current and must be acknowledged whether performed or skipped.

Save operations use monotonically increasing revisions and a single sequential writer attached to the store owner. Each accepted review/reset updates in-memory progress and revision first, then queues a snapshot. The writer never commits revision *n+1* before *n*; if coalescing is chosen, only a newer complete snapshot may replace an unwritten older snapshot. A stale completion may update only its own bookkeeping, never clear an error or mark a newer revision saved. A failed save keeps current in-memory progress for export and shows the actionable `Экспортируй JSON перед закрытием` warning. Later success clears it only if that success covers the latest in-memory revision. Export serializes the **current in-memory** snapshot through stage-7 legacy-compatible codec, including reviews after failed save. Reset first produces `ConfirmReset` with ID; cancellation changes nothing. Confirmation creates fresh progress, queues a save/reset through stage-7 safe repository contract, starts seed 0 chain and clears the old draft. Failure still exposes the new in-memory state for export and a recovery warning; repository handling must not erase a raw corrupt/unsupported backup. Download effect contains a stable JSON snapshot and filename `polski-srs-progress.json`; acknowledgments prevent duplicate download on recomposition/re-subscription. Effect execution errors produce a visible retryable message without consuming progress.

The web entrypoint owns one store per mounted app, its coroutine scope and one timer/listener set. Refresh at the React 30-second cadence plus `visibilitychange`/focus after backgrounding; compute due count and today from fresh absolute time/local day, including timezone/DST change, rather than adding ticks to a counter. `RefreshTime` does not mutate durable history or regenerate an existing card. No `GlobalScope`; `close()` cancels pending work and removes listeners, and any delayed host effect/save completion from the old owner is ignored. Recomposition does not construct another store/timer. A new page load reads durable progress through stage 7 and starts a new ephemeral chain session; typed draft is not promised durable across reload.

## Decisions and tradeoffs

The stage-2 spike's `HtmlElementView` plus Compose layout is the smallest proven JS/Wasm path for real browser semantics. Keep actual HTML buttons/select/textarea/table; a pure canvas card would reintroduce the measured accessible-name, table-role and click interception failures. Do not add JS-only presenter until an actual host limitation calls for it. Browser host maps keyboard events: global Space reveal and keys 1–4 rating only on training tab with active card, when target is not input/textarea/select/button/link/contenteditable, no repeat/modifiers/composition; native button Enter/Space remains browser behavior. Textarea Enter reveals only when not composing and not Shift; Shift+Enter inserts newline. `compositionstart/end` and `isComposing` both guard the path, including Safari/WebKit cases. Handled events call `preventDefault` only when taking an app action.

The React CSS is a layout/reference baseline, not a Kotlin stylesheet import contract. Preserve bounded main width, readable 320 px cards, single-column reference below ~860 px, four rating actions wrapping or fitting without clipping, contained horizontal scrolling for two-dimensional tables, visible focus, non-color correctness cues and reduced-motion behavior. Fix the recorded React large-text overflow rather than replicating it. Keep answer hidden from both visual and accessibility trees until reveal; transient animation must not keep old rating buttons actionable. CSS/DOM transitions are visual only, short, interruptible and disabled by `prefers-reduced-motion`; store transitions are immediate. Screen-reader names and table `scope=col/row` are host contracts, not merely Compose test tags.

Stage-7 handshake is unresolved until `Plans/Kotlin/ProgressMigration.md` and implementation are accepted: exact `Progress`/`ReviewReducer`/`ProgressRepository`/`ProgressCodec` symbols, whether load/save are suspend, migration recovery result, reset semantics, and format of current legacy export. Adapt the presentation port to that API, with no second progress schema or bypass of migration. FSRS stage 6 may still change implementation internals; store depends only on verified `Scheduler` contract. No production/tests/build claims follow from this design.
