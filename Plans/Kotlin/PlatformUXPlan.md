# План развития UI/UX, настроек и напоминаний

**Изменение host UI от 2026-09-25:** конечный Mac UX3 теперь выполняется в нативном **SwiftUI** приложении поверх Kotlin/Native framework; существующий Compose Desktop/JVM и его [UX3 blueprint](UX3MacBlueprint.md) остаются превью и источником доказательств/данных. Web сохраняет семантический DOM/CSS на Kotlin JS/Wasm, Android — Jetpack Compose Material 3, iPhone/iPad — SwiftUI. Порядок и новые gates описаны в [NativeHostDecision.md](NativeHostDecision.md). Упоминания Compose Desktop ниже относятся к текущей базе, а не к конечному Mac host.

Источники проверены 2026-09-24. Статус на 2026-09-25: **UX1 shared preferences contract и web adapter выполнены; UX2 Web реализован, основные production Playwright gates прошли**. Следующий этап — [UX3 Mac](UX3MacBlueprint.md), затем UX4 Android, UX5 iPhone/iPad и общая UX6. 400% browser zoom, physical Safari, IME, screen-reader и device gates пока не проверены; ограничения и нестабильный единичный тестовый outlier записаны в [UX2 отчёте](UX2WebTester.md). Настройки, темы и напоминания на нативных платформах ещё не объявлены реализованными.

## Текущая база и цель

Общий `TrainingStore`/`AppUiState` (`kotlin/shared/src/commonMain/kotlin/polski/presentation/`) уже дают четыре раздела, два метода объяснения, две оценки FSRS, прогресс и черновик ответа. Браузерный Compose UI находится в `kotlin/composeApp/src/webMain/kotlin/polski/ui/TrainingWebApp.kt`, Mac Compose — в `kotlin/composeApp/src/desktopMain/kotlin/polski/desktop/Main.kt`, Android Material 3 — в `kotlin/androidApp/src/main/java/dev/polski/grammarmatrix/MainActivity.kt`, iOS SwiftUI — в `kotlin/iosApp/PolskiGrammar/PolskiGrammarApp.swift`. JSON перенос и мобильные свайпы после раскрытия существуют, но единых Settings и системных напоминаний нет; данные и действия рассыпаны по экранам.

Цель — спокойный экран с одной очевидной следующей операцией: задача → ответ/раскрытие → сравнение → «Повторить» или «Вспомнил». Исходная изменяемая форма остаётся красной, целевая/окончание — отдельным акцентом и **текстовой подписью**. Справка раскрывается по запросу, но существенное правило не скрывается ради минимализма. Метод «логика / ситуации» — предпочтение подачи, не диагноз мозга. [Метаанализ instructional signaling](https://www.sciencedirect.com/science/article/pii/S1747938X17300581) поддерживает тестирование умеренных подсказок, но не доказывает пользу конкретной палитры или «типа учащегося».

## UX0. Общий дизайн-контракт

1. Зафиксировать baseline всех состояний: новая карточка, ввод, эталон, две оценки, пустая очередь, ошибка хранения, импорт, редактор слов, матрица. Для каждого описать основное действие, вторичные действия, путь назад, фокус и содержимое accessibility tree. Ответ не показывать до раскрытия.
2. Установить небольшие semantic tokens для поверхности, текста, основного действия, исходной/целевой формы, ошибки, фокуса, типографики, отступов и движения. Проверить контраст в системной, светлой и тёмной теме, Increase Contrast; цвет никогда не единственный сигнал. Ширина строки ограничена, учебный текст растёт без ellipsis, таблица скроллится внутри обозначенной области.
   Три варианта темы обязательны на каждом host: «Системная» следует текущей настройке OS/браузера **и её изменению без перезапуска**, ручные «Светлая» и «Тёмная» переопределяют её. Переключение сохраняет карточку, ввод, скролл, фокус и FSRS; исходный красный и целевой акцент остаются различимыми в обеих палитрах и при повышенном контрасте.
   Платформенные основы: [Apple Dark Mode](https://developer.apple.com/design/human-interface-guidelines/dark-mode), [Android Material 3 dynamic color](https://developer.android.com/develop/ui/compose/designsystems/material3), [web `prefers-color-scheme`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/%40media/prefers-color-scheme).
3. Motion выражает изменение состояния, не управляет им. Раскрытие, переключение карточки и подтверждение оценки короткие, прерываемые; нет бесконечного движения. При Reduce Motion контент и управление те же. FSRS записывается один раз независимо от завершения кадра/анимации.
4. Единый жест для грамматики и слов **только после раскрытия**: влево «Повторить», вправо «Вспомнил». Направление и решение видны до отпускания; порог, отмена, вертикальная прокрутка, выделение текста и свайп таблицы не оценивают. Всегда остаются видимые кнопки, keyboard и screen-reader actions. iOS back gesture и Android predictive back имеют приоритет у края экрана.
5. Приёмка компоновки: web 320 CSS px и 400% zoom; компактная и широкая область; небольшой iPhone, iPad Split View, Android portrait/landscape/split-screen, узкое Mac окно; крупный шрифт, клавиатура, тёмная тема, Reduce Motion. [WCAG 2.2](https://www.w3.org/WAI/WCAG22/understanding/), [Android window size classes](https://developer.android.com/develop/adaptive-apps/guides/use-window-size-classes), [Apple accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility).

Исторические снимки до UX-работ: [Mac](artifacts/stage10/native-desktop-training.png), [Android](artifacts/android/native-training.png), [iPhone](artifacts/ios/course-method-final-iphone.png), [web desktop](artifacts/stage1/desktop-revealed.png). На Mac/телефонах крупный приветственный блок, счётчики и несколько рядов выбора занимают первый экран; само задание частично уходит вниз. Это наблюдение по снимкам, не замена измерения текущего build. В UX0 повторно снять **свежие** кадры, затем сократить hero до компактного заголовка, переместить счётчики в ненавязчивую сводку, объединить вторичные настройки и дать исходному предложению/задаче приоритет в первом viewport. Сравнить до/после при одинаковом содержании и размере окна; успех — задача и следующее действие сразу видны без ощущения перегруженной панели, а все прежние выборы остаются доступны.

Свежая Kotlin/Wasm compatibility distribution из [manifest](artifacts/final-virtual/manifest.json) снята в Chromium при [1440×900](artifacts/ux0/kotlin-web-desktop.png) и [390×844](artifacts/ux0/kotlin-web-mobile.png) без пользовательского прогресса. Мобильный снимок подтверждает отсутствие горизонтального overflow, но четыре верхних раздела и несколько рядов режима/метода/набора занимают почти половину viewport до карточки. Это baseline UX0 для переработки навигации и иерархии, а не проверка accessibility или качества обучения.

## UX1. Настройки и модель предпочтений

Один раздел **«Настройки»** доступен без потери незавершённой карточки. «Все возможные настройки» означает все релевантные **работающие** опции, а не неактивные обещания будущих языков.

| Группа | Первая версия и инвариант |
| --- | --- |
| Обучение | Метод «Логика / Ситуации», ответ «Устно / Письменно», включение и памятка свайпов там, где они реализованы. Смена не создаёт review, не теряет черновик/очередь. |
| Язык и курс | Активен только польский для русскоязычных. Будущие языки не выглядят доступными; при их добавлении прогресс хранится по языковой паре и направлению. |
| Вид и доступность | «Системная / Светлая / Тёмная», «Системное / Меньше движения», при необходимости повышенный контраст и масштаб учебного текста. Пункт включать лишь после реализации на host; системный font scaling/Dynamic Type остаётся базой. |
| Напоминания | Выкл. по умолчанию; локальное время, дни, тихие часы, текущий permission/delivery status, тест только по явному нажатию. Если надёжной доставки нет — честное ограничение/недоступно. |
| Данные | Отдельные экспорт/импорт **прогресса JSON** и **словаря JSON**, статус сохранения и восстановления, подтверждаемый сброс. Перед заменой backup; повреждённый файл не уничтожает данные. |
| О приложении | Версия, лицензии, атрибуция словаря, доступность и подсказки по жестам/клавиатуре. Неподготовленные top-100/500/1000 и CEFR не заявлять готовыми. |

Создать версионированный `UserPreferencesV1` в `shared/commonMain` и платформенные repository adapters **отдельно от `ProgressDocument` и словарного JSON**. Мигрировать существующие web `polski-explanation-method-v1` и Android `explanationMethod`, определить дефолты, обработку неизвестных полей/версий, отказ записи и экспорт/импорт настроек только при явном пользовательском действии. `TrainingStore` и Settings используют один источник значения метода; не заводить несогласованные копии в host. Модель напоминаний различает желание пользователя, разрешение OS и реально поставленное расписание. Экспорт через штатный picker/download; импорт показывает тип, версию и последствия, валидирует до замены и сохраняет raw для восстановления. Старые ID, четыре исторических FSRS-значения, пользовательские слова и оба направления остаются совместимыми.

Точные новые контракты, миграция всех четырёх host и приёмка PR1–PR5 — в [PreferencesBlueprint.md](PreferencesBlueprint.md).

## Напоминания: реальный capability gate

При opt-in и разрешении вычислять следующую подходящую дату из **обеих** очередей: грамматических `nextDue`/`dueCount` в `TrainingStore` и отдельно выбранных слов с двумя направлениями в `VocabularySession`. Сейчас `AppUiState.nextDue` не включает словарь; прежде чем включать напоминания, нужен общий read-only projection ближайшего срока с типом очереди/направлением, без слияния FSRS-историй. Учитывать выбранное локальное время, дни недели и тихие часы; `dueCount > 0` означает уже доступные грамматические повторения **сейчас**, но не является условием постановки будущего напоминания. После последней оценки возможно `dueCount = 0`, `nextDue = завтра`: расписание должно пережить закрытие приложения и напомнить завтра. Если карточки уже due, ближайшее разрешённое пользовательское время остаётся кандидатом; если выбранных карточек/предстоящих повторений вообще нет, события нет. Ограничить частоту и дедуплицировать. Текст lock screen нейтрален («Пора повторить»). Изменение любой FSRS-очереди, выбора слов, предпочтений, часового пояса или системного разрешения отменяет/пересчитывает события. Tap ведёт в соответствующую очередь; при одновременной готовности обеих даёт явный выбор, а не теряет одну. Время — предпочтение, не гарантия точной минуты; отказ не вызывает повторный prompt. Обязательные тесты: после последней оценки `dueCount = 0`, `nextDue` завтра, приложение закрыто → завтра одно уведомление; новая оценка/перенос срока отменяет старое; готовое слово при пустой грамматической очереди даёт напоминание и открывает нужное направление.

| Host | Подход и ограничение |
| --- | --- |
| iOS/iPadOS | `UNUserNotificationCenter`: permission после включения, локальное расписание/cancel, status и tap routing. [Apple permission](https://developer.apple.com/documentation/usernotifications/asking-permission-to-use-notifications), [scheduling](https://developer.apple.com/documentation/usernotifications/scheduling-a-notification-locally-from-your-app). |
| Android | API 33+ `POST_NOTIFICATIONS`, user-controlled channel; inexact `WorkManager` для обычных напоминаний. Doze/periodic work не обещают точный момент, exact alarm не нужен. [Permission](https://developer.android.com/develop/ui/compose/notifications/notification-permission), [channels](https://developer.android.com/develop/ui/compose/notifications/channels), [work requests](https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started/define-work). |
| Mac JVM | Сначала доказать мост к системным уведомлениям, app identity для packaged `.app`, authorization, доставку и click routing. Таймер/баннер внутри окна не достаточен. До успеха UI показывает «недоступно». |

[MDN Notifications](https://developer.mozilla.org/en-US/docs/Web/API/Notifications_API/Using_the_Notifications_API). |

## UX6. Общая приёмка и workflow

Architect уточняет `UserPreferencesV1`, миграцию и platform adapters; Developer делает поведенческие RED→GREEN и host implementation; Tester независимо сверяет JSON/FSRS/жесты/экраны/permissions; Reviewer читает итоговый diff и доказательства по [workflow](../../.agents/skills/workflow/SKILL.md). Сравнить оба направления слов, цепочку, две оценки, точный FSRS JSON, 32 утверждённые словарные карточки и legacy-импорт. Для каждого target записать **PASS / FAIL / NOT RUN** отдельно по тестам, сборке, живому экрану, доступности и уведомлениям; виртуальный запуск не закрывает физический gate. Обновить README/support matrix и навыки по наблюдаемым отклонениям; не объявлять публикацию.

Долгоживущие рекомендации сохранены в общих навыках: [Compose UI](../../.claude/skills/compose-multiplatform-ui/SKILL.md), [web](../../.claude/skills/kmp-web/SKILL.md), [Mac](../../.claude/skills/kmp-desktop/SKILL.md), [Android](../../.claude/skills/kmp-android/SKILL.md), [iOS](../../.claude/skills/kmp-ios/SKILL.md). `.agents/skills/` ссылается на эти канонические файлы; API/версии пересматривать перед каждым шагом.
