# Решение этапа 6: общий FSRS scheduler

## Scope and consumers

Этап 6 переносит только поведение [`src/srs/scheduler.ts`](../../src/srs/scheduler.ts) поверх зафиксированного `ts-fsrs` **5.4.2**. Потребители: будущие `ProgressCodec`/`TrainingStore` в `kotlin/shared`, затем браузерный host (`kotlin/composeApp`); Android/iOS должны использовать тот же `commonMain` после добавления targets. Действующие targets `kotlin/shared/build.gradle.kts`: JS browser и Wasm/JS browser; `jvmToolchain(21)` задаёт JDK, но отдельный JVM target сейчас не объявлен. Native targets пока не объявлены. `shared` не зависит от Compose, DOM, localStorage или платформенного `Date`. Текущие `src/**` и fixtures остаются эталоном. Параметры продукта: retention `0.9`, cap `3650` дней, fuzz `true`, short-term `true`, learning `1m, 10m`, relearning `10m`.

## Выбор реализации и проверка кандидатов

Источник переносимого поведения — установленный `node_modules/ts-fsrs/dist/index.cjs.map` с `sourcesContent` версии 5.4.2, а не более новая upstream ветка. Вложенные в sourcemap `src/constant.ts`, `src/default.ts`, `src/models.ts`, `src/abstract_scheduler.ts`, `src/impl/basic_scheduler.ts`, `src/strategies/{learning_steps,seed}.ts`, `src/{algorithm,alea,help,convert}.ts` показывают `BasicScheduler`, 21 вес FSRS-6, UTC-calendar elapsed days, step-стратегию, seed `${reviewEpochMs}_${repsAfterIncrement}_${difficulty*stability}` и Alea/Mash. Это проверка исходников в установленном package, не результат Kotlin differential tests. [Официальное описание FSRS-6](https://github.com/open-spaced-repetition/awesome-fsrs/wiki/The-Algorithm) подтверждает 21 параметр и формулы, но не определяет продуктовые шаги, сериализацию или fuzz.

## Public contract

Предлагаемые файлы, все **NEW** под `kotlin/shared/src/commonMain/kotlin/polski/srs/`:

| Файл / символ | Ответственность |
| --- | --- |
| `Scheduler.kt`: `interface Scheduler`, `enum class Rating { Again, Hard, Good, Easy }`, `data class SchedulePreview` | Узкий API `newCard(skillId: String, at: Instant): StoredCard`, `preview(card: StoredCard, at: Instant): SchedulePreview`, `review(card: StoredCard, rating: Rating, at: Instant): StoredCard`, `isDue(card: StoredCard, at: Instant): Boolean`. Все операции синхронные. Preview содержит четыре `Instant` due. Нет глобальных часов или внешнего RNG. |
| `SrsCard.kt`: `data class SrsCard`, `data class StoredCard`, `enum class CardState` | Поля `due: Instant`, `stability/difficulty: Double`, `elapsedDays/scheduledDays/reps/lapses/learningSteps: Int`, `state`, `lastReview: Instant?`; `StoredCard(skillId, card)`. Значения состояния `New=0`, `Learning=1`, `Review=2`, `Relearning=3`; оценка `Again=1`..`Easy=4`, Manual не участвует. Копия результата не меняет вход. |
| `FsrsScheduler.kt`: `class FsrsScheduler : Scheduler` | Фиксированные product settings и `BasicScheduler` transition semantics. Экземпляр без изменяемого состояния между вызовами. Internal параметр `fuzzEnabled=true` только для differential harness; production wiring всегда `true`. |
| `FsrsMath.kt`: `internal` формулы/rounding/step/cap | 21 weights `[0.212, 1.2931, 2.3065, 8.2956, 6.4133, 0.8334, 3.0194, 0.001, 1.8722, 0.1666, 0.796, 1.4835, 0.0614, 0.2629, 1.6483, 0.6014, 1.8729, 0.5425, 0.0912, 0.0658, 0.1542]`; 8-decimal `roundTo` в тех же точках, `Math.round` semantics для неотрицательных интервалов. Не применять Kotlin `roundToInt()` механически для отрицательного/полуцелого значения. |
| `Alea.kt`: `internal` deterministic seed→draw | Порт Mash/Alea с JS 32-bit unsigned/signed conversion и UTF-16 `charCodeAt` semantics для seed. Новый Alea создаётся из seed при каждом вычислении интервала, как в `apply_fuzz`, без общего mutable generator. |
| `SrsCardWire.kt`: `object SrsCardWire` | Явное отображение legacy `snake_case` JSON полей в card и обратно, ISO UTC с **ровно тремя** цифрами миллисекунд (`toISOString`), отсутствие `last_review` при null, numeric `state`; decoder возвращает recoverable invalid result вместо подмены карточки. Этот mapper используется будущим `ProgressCodec`, который отвечает за весь progress JSON. |

Контракт `SrsCardWire.kt` включает **NEW** `data class SerializedCard` с `due: String`, числовыми полями с JSON именами через явное отображение, `state: Int`, `lastReview: String?`; **NEW** `sealed interface CardDecodeResult` с `Valid(card: SrsCard)` и `Invalid(reason: String)`; `SrsCardWire.decode(value: SerializedCard): CardDecodeResult` и `encode(card: SrsCard): SerializedCard`. `ProgressCodec` этапа 7 читает/пишет сами JSON keys и исключает `last_review` из объекта при null. Фиксированные FSRS параметры не входят в JSON карточки. Это позволяет проверить scheduler независимо от выбранной в этапе 7 JSON-библиотеки.

`kotlin.time.Instant` в выбранном Kotlin 2.4.20 доступен для всех targets и поддерживает parse/epoch milliseconds; [Kotlin Instant API](https://kotlinlang.org/api/core/kotlin-stdlib/kotlin.time/-instant/). Scheduler принимает уже захваченный `at` от `TrainingStore` и не владеет часами. `newCard` кладёт `at` в due, нули во все FSRS числовые поля, New, без `last_review`. `isDue` — `card.due <= at` по абсолютному instant. `preview` использует тот же `at` и те же расчёты, что `review` для каждого rating, и не меняет вход/другие карточки. Входной `skillId` переносится без нормализации.

Wire-форма повторяет `src/types.ts` и `serialize`/`deserialize`: обязательные `due`, `stability`, `difficulty`, `elapsed_days`, `scheduled_days`, `reps`, `lapses`, `learning_steps`, `state`; `last_review` опционален. При parse принимаются валидные ISO instants, включая offset, но writer канонизирует в UTC `.sssZ`; переход через epoch milliseconds обязателен, чтобы сохранить JS Date precision. Не заменять invalid date/enum/nonfinite/отрицательные counts нулями; ошибка возвращается codec/import flow, сырой progress остаётся доступен для восстановления/экспорта. Сохранение неизвестных свойств и полной версии файла принадлежит этапу 7 `ProgressCodec`; для известных Card полей round trip должен быть без потерь. Разница между `last_review` absent и JSON null при legacy import решается там: оба отображаются в `null`, writer опускает поле.

## State, time and RNG

`dateDiffInDays` у 5.4.2 сравнивает **UTC даты** последнего review и `at`, отбрасывая часы; может дать 0 при смене локального дня и не зависит от зоны браузера. Отдельный `localDay` для счётчиков `reviewsToday` остаётся в progress/store contract, не в scheduler. Due вычисляется от точного `at` как `minutes * 60_000` или `days * 86_400_000` epoch milliseconds; день FSRS — ровно 24 часа даже на DST. Сначала применяются ограничения формулы, `roundTo(…, 8)`, `next_interval` c cap 3650, затем fuzz range/draw, затем порядок Hard ≤ Good < Easy; из-за принудительного порядка крайний Easy может превысить `maximum_interval` (как у 5.4.2), что нельзя «исправлять» без change request. `stability` имеет отдельный algorithm cap 36500.

Production fuzz должен воспроизвести именно seeded Alea из package: seed формируется **после** `reps += 1` и **до** расчёта следующей памяти, из старых `difficulty*stability`; JS `String(Double)` в seed нужно сверять на характерных значениях (целое, десятичное, exponent) и реализовать совместимое форматирование. Если точный формат не доказан на JS/Wasm/JVM, gate остается незакрытым, а не заменяется `Random.Default`. Для test harness допускается inject/internal seed formatter или фиксированный draw seam, но default путь использует production algorithm. Диапазон fuzz: кусочные доли 0.15 на `[2.5,7]`, 0.1 на `[7,20]`, 0.05 выше 20; минимум 2 дня, просроченное ограничение `elapsedDays+1` только когда interval больше elapsed, максимум cap перед ordering. Fuzz ниже 2.5 не применяется. Все вызовы чистые: preview повторяем и не потребляет внешнее состояние, review конкретного rating совпадает с соответствующей веткой preview при одном `at`.

## Verification / acceptance contract

Допуски установлены **до** Kotlin реализации: все JSON keys/enum/counts, `skillId`, due/last-review ISO и scheduled days сравнивать **точно**; `stability` и `difficulty` — `abs(actual - expected) <= 1e-7` после JS-эквивалентного округления до 8 знаков, без относительного допуска. Не считать совпадение чисел достаточным, если из-за threshold отличается целое число дней. В fuzz-off differential ожидаются те же точные даты и состояния. В production fuzz-on текущие fixture due/date тоже сравниваются точно, поскольку выбран точный seeded Alea; отдельно проверяются границы/монотонность. Любое расширение допуска требует изменения этого документа **до** переоценки тестов с обоснованным измерением по targets.

1. `P10-A`: все 21 [`scheduler.json`](../../tests/fixtures/kotlin-parity/scheduler.json) case: 4 состояния × 4 оценки, same-day, overdue, short-step, fuzz, cap. Сравнивать полный `review.card`, каждый из четырёх due в preview, `isDue`, исходный card round trip и отсутствие изменения входа. Fixture `F-Learning-*` намеренно содержит `at` раньше `due`, но не раньше `last_review`; scheduler не должен навязывать due gate, это обязанность вызывающего store.
2. `P10-B`: расширить oracle fixtures из **установленного** TS package до граничных переходов: второй learning step (Good → Review), повтор Hard, Review→Relearning→Review, same UTC day/UTC midnight, leap day/DST, exact due equality, long overdue, cap у Hard/Good/Easy, fuzz threshold 2.5, интервалы 7/20, и два seed с дробным/exponent произведением. Generator записывает вход, params, time, package version, provenance и expected полный card/preview. Не менять существующие 21 fixture.
3. `P10-C`: дифференциал с fuzz disabled через отдельный fixture generator, вызывающий `fsrs({...enable_fuzz:false})`; реальный React wrapper не меняется. Проверить формулы всех state/rating и round boundaries до fuzz. Затем fuzz enabled: один и тот же card/time/rating даёт идентичный результат при повторе, preview/review due совпадают, интервалы в upstream range после ordering, нет общего RNG drift между карточками; JS/Wasm/JVM значения против pinned oracle. На native после добавления targets — те же common fixtures и сборка/прогон соответствующего target.
4. `P10-D`: malformed/unsupported card inputs дают recoverable validation error без записи нового progress; отсутствующий `last_review` на New сохраняет отсутствие. `newCard` и wire encode/decode сохраняют все обязательные поля, миллисекунды и поля старого progress. `isDue` проверяется на `at-1ms`, `at`, `at+1ms`.

Developer вёл focused TDD в `kotlin/shared/src/commonTest/kotlin/polski/srs/{SchedulerParityTest,SrsCardWireTest}.kt` и закрепил provenance дополнительных fixtures. Наблюдался RED на 16 исчерпанных learning/relearning step cases и на невалидных memory states; после исправления independent tester подтвердил pinned oracle `--check` для 70 cases и **99/99 PASS на JS и 99/99 PASS на Wasm** по SRS tests, см. [Stage6-Tester.md](Stage6-Tester.md). Ревью обоих исправлений — APPROVED_WITH_MINOR без Critical/Major. Основной агент затем повторил полный shared suite: **142/142 PASS** на каждом target. Браузерный UI для FSRS и native targets **NOT RUN**. React fixture PASS в `Parity.md` — историческая проверка базовой версии, не свидетельство о Kotlin UI.

## Handoff

Порядок реализации: (1) card/wire contract и TDD 21 cases, (2) чистые FSRS-6 формулы и step strategy с fuzz-off differential, (3) UTC/MS arithmetic и границы, (4) Alea/JS seed + fuzz-on differential, (5) caller integration с captured `at`, validation/recovery и attribution/docs. `FsrsScheduler` не сохраняет состояние, не запускает корутины и не владеет ресурсами. Documentation owner: Developer добавляет KDoc для единиц времени, rounding, mutation, errors и usage; основной агент синхронизирует общий stage/evidence после проверки. Открытый технический gate: доказать одинаковое JS number-to-string seed форматирование и округление на всех активных targets; пока нет differential evidence, stage 6 не закрыт.
