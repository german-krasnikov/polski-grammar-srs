# Text wire and one-time legacy migration: architecture design

Status: **design only; no codec, migration, host run or clean-CI result is claimed**. This is the wire-level companion to [NoJsonFullPortPlan.md](NoJsonFullPortPlan.md) and the owner's [ADR-51/ADR-52](../../AI/decisions.md). It covers durable progress, vocabulary and preferences plus cross-host import/export. `POLSKI-TEXT` below is **candidate A**, not an adopted header or file extension: compare it with the established-format and smaller-helper arms in [TextWireExperimentBlueprint.md](TextWireExperimentBlueprint.md), freeze each arm's canonical bytes independently, then choose one protocol before document or repository integration. Apple UI snapshots are a separate transient decision: first prove a typed Kotlin/Swift bridge on live hosts; only a failed bridge gate admits a separately tested text snapshot schema. All examples and paths below are proposals to test, not implemented interfaces.

The former progress migration's JSON `__kmpMigration` stamp, byte-identical React export and retained JSON backup are **historical behavior superseded by ADR-51**. Preserve their safety properties—unknown-data retention, readback, interruption recovery and no overwrite—without writing or exporting JSON. Keep old key/file names and their exact bytes solely as read-only legacy inputs until each migration commits and cleans them up.

## Proposed `POLSKI-TEXT` framing (wire version 1)

Use a small native static codec utility with an ordered typed tree, shared as Kotlin common code and mirrored in TypeScript for the retained React consumer. The codec owns framing, escaping and type checks, while document/domain owners retain migration policy, FSRS validation, import merge and independent expected values. Swift needs no save codec if it passes text bytes to the KMP framework; host pickers/storage remain native. The same frozen corpus must run in TS, KMP JVM/JS/Wasm/Native and, if snapshots use text, Swift. A reusable DSL declaration/template may describe repeated document field names and generate schema checks only if it eliminates duplicate rules under a measured P8 comparison. The byte lexer, hash, atomic writes and legacy readers are native mechanics.

The file is strict UTF-8 with **no BOM**, LF line endings and a final LF. It begins `POLSKI-TEXT<TAB>1<TAB><kind><TAB><schemaVersion><LF>`, where `kind` is `progress`, `vocabulary`, `preferences` or, separately, `snapshot`; unknown wire versions or kinds are `Unsupported`, never coerced. One root record follows. Every record is one line with TAB-separated columns:

| Tag | Line shape | Meaning |
| --- | --- | --- |
| `M` | `M<TAB>key<TAB>childCount` | Ordered map/record; the next `childCount` complete values are its children. Root key is the structural sentinel `-`. Duplicate decoded keys fail. |
| `L` | `L<TAB>key<TAB>itemCount` | Ordered list; the next `itemCount` complete values must each have the structural sentinel `-`. Empty list is count `0`. |
| `S` | `S<TAB>key<TAB>escapedText` | String, including empty string. No implicit number/bool conversion. |
| `I` | `I<TAB>key<TAB>signedDecimal` | Signed 64-bit integer with shortest decimal spelling: `0` or optional `-` followed by nonzero digit and digits. Domain schema further restricts to Int/nonnegative/ranges. |
| `D` | `D<TAB>key<TAB>16LowerHexDigits` | Finite IEEE-754 binary64 bit pattern; exact stability/difficulty round-trip, including `-0.0` if accepted by the existing domain validator. NaN/Infinity are invalid. |
| `B` | `B<TAB>key<TAB>0-or-1` | Boolean. |
| `N` | `N<TAB>key` | Explicit null, distinct from missing, empty string, empty map and empty list. |

Every **named** child key is encoded as `K:` followed by escaped text; `-` is reserved only for root and list-item positions. Thus the empty key is `K:`, the literal legacy key `-` is `K:-`, and a literal key `K:-` is `K:K:-`; decoding strips exactly one `K:` prefix. No named key is confused with the sentinel, including an unknown legacy extension key. `K:` key payload and `escapedText` use the same escaping function. Raw Unicode scalars stay visible except backslash, U+0000–U+001F and U+007F–U+009F; these use the unique spellings `\\`, `\t`, `\n`, `\r` for their respective characters and uppercase `\uXXXX` for all other excluded code units. Unpaired UTF-16 surrogates use uppercase `\uXXXX`; valid surrogate pairs encode as their raw Unicode scalar. No Unicode normalization, locale case conversion or trimming is performed by the wire. The encoder chooses exactly one representation for each UTF-16 code-unit sequence; the decoder rejects malformed escapes, invalid UTF-8 and noncanonical alternative spellings, including `\u` where a raw scalar or short escape was required. A separate conformance case must establish how Swift/Foundation preserves or rejects lone surrogates; do not claim full cross-host round-trip until it does. The decoder enforces bounded depth, record count, string bytes and total bytes *before* allocation; domain-specific limits such as the 10 MB progress import and 1 MB preferences import remain at least as strict as today. Zero-length string, absent field, `N`, `M ... 0` and `L ... 0` are separate values.

The root is `M<TAB>-<TAB>n`. Nested maps use explicit `M`, not JSON-like inline cells. The parser consumes child counts with a bounded stack and rejects a sentinel `-` in map children, a `K:` named child in lists, a `K:` named root, duplicate decoded keys, extra/truncated rows, impossible count, overflow, CRLF, BOM and unknown tags. Domain codecs validate exact required fields, types, legal extras, list order and references after framing; a valid generic tree alone is not a valid save. An illustrative empty progress file (digest line omitted here deliberately) is:

```text
POLSKI-TEXT	1	progress	2
M	-	6
I	K:version	2
L	K:cards	0
L	K:stats	0
I	K:reviewsToday	0
S	K:lastDay	2026-10-18
I	K:totalReviews	0
```

`stats` is an ordered list of `{skillId, reviews, correct, streak, mistakes}` records rather than a dynamic-key object; cards likewise remain ordered records. The list order is part of the model when the old document preserved it. New maps emit known fields in the schema's fixed order, then typed unknown extension records in their preserved source order. No separate authored table duplicates those names. For a newly created document with no inherited extension order, sort extension keys lexicographically by **UTF-16 code units**, unsigned 16-bit value by value, with a shorter equal prefix first (P24); never sort by UTF-8 bytes, locale, Unicode scalar values or platform default. The decoder retains the encoded extension order, so canonical re-encode does not silently re-sort a migrated document. Freeze independent keys spanning ASCII/BMP (`\uE000`), supplementary (`\uD800\uDC00`) and lone-surrogate (`\uD800`, `\uDC00`) cases and compare exact encoded bytes across TS/Kotlin/Swift where applicable; if a host cannot retain those code units, recovery blocks that document rather than changing order or dropping a key. This ordering rule and preserved list order are necessary for `encode(decode(bytes)) == bytes` on canonical input. String IDs, card keys, ISO instants and local days are `S`; FSRS counters and enum wire values are `I`, memory numbers are `D`; optional `last_review` is an explicit `N` or `S` per the frozen schema. Schema versions are per document and distinct from framing version. New document versions must never be decoded with old defaults silently.

End with `H<TAB>sha256<TAB><64 lowercase hex digits><LF>`. The digest covers every preceding byte from the `P` in the header through the LF immediately before `H`, including all exact escapes and order. This is corruption detection and a migration readback identity, **not authentication** against an adversary who can rewrite the file and digest. Use one tested SHA-256 implementation/adaptor per target, verified against standard vectors and the same frozen corpus; if KMP JS/Wasm/Native cannot implement this without unacceptable P8 cost, decide the integrity mechanism explicitly before writing documents. Decode verifies digest and canonical re-encode equality. Atomic repository readback additionally compares exact bytes and decoded model; a hash match alone is insufficient.

## Typed documents, extensions and unresolved data policy

`ProgressDocument.source: JsonObject` must become a typed ordered `ExtensionTree` containing exactly the representable unknown legacy root, card, stats and nested values. The migration reader may *read* JSON once and construct that tree; no JSON tree appears in new runtime APIs, save files, backup files, snapshots or exports. Preserve known progress fields (`cards`, `stats`, `reviewsToday`, `lastDay`, `totalReviews`), every `SrsCardWire` value/state/timestamp, unknown skill cards/stats and extension records. Do not normalize local day or add missing known skills before confirming the raw legacy content can be represented without loss; then apply existing completion policy as a separate, explicitly tested transition. The vocabulary document must preserve pair identity, selected/custom order, directional card keys, exact custom text and representable unknown fields; today its decoder drops some unknowns, so a strict migration adapter—not that projection—must be used. Preferences v1–v4 known fields/defaults and early target/native peek remain, but `UserPreferencesCodec` currently rejects unknown fields; unsupported versions and unknown-unconvertible values stop in recovery.

**Open contract:** distinguish preservation of unknown JSON values as typed text extension records from application interpretation. A legacy value with no lossless mapping to the typed tree, duplicate object keys that the current parser collapses, non-finite/unsafe numbers, invalid Unicode, or conflicting multiple old backups must not be discarded to satisfy the format ban. Return `RecoveryRequired` with the original old bytes untouched and no automatic fresh save. An owner decision is required if such a case cannot be migrated while also deleting all old JSON after success. Do not delete the old bytes, offer a JSON export or claim zero-JSON completion for that user. Frozen negative controls must include these cases.

## Transaction protocol and host boundaries

Use new paths/keys such as `polski-progress-text-v2`, `polski-vocabulary-<pair>-text-v2` and `polski-preferences-text-v2` (exact names frozen before implementation); never reuse a legacy `.json` filename or key for text. A text receipt carries document kind, legacy key/path identifier, exact old-byte SHA-256, new-byte SHA-256, schema version and transaction ID; it contains no old JSON payload. Use separate receipts per document/pair. New normal saves/imports back up the previous **text** bytes only; a user import is decode→validate→merge/replace decision→write temp/new key→read back→commit, with rollback on any failure. Preserve current local-wins vocabulary merge, progress import replacement, and preferences validation; text format changes none of those domain choices.

For a legacy document, under a per-document lock: (1) if a valid new text document plus matching durable receipt exists, finish deleting any remaining matching old JSON keys/files/backups without parsing again; mismatching leftovers require recovery. **If valid new text and any legacy bytes coexist without a matching durable receipt, enter `RecoveryRequired` before any write, migration replay, deletion or ordinary save. Neither version is presumed authoritative; preserve both byte sequences for explicit provenance resolution.** A stale, malformed or mismatched receipt is the same recovery case. (2) Only when no valid new document exists, read old bytes once for this migration attempt, validate version and all content, compare any existing backup copies, and construct the typed model/extensions without loss. (3) Encode new text, write to a distinct destination, read back exact bytes, verify digest, decode and compare all known and extension values. (4) Write/read back the text receipt. (5) Delete old primary and backup JSON keys/files and verify absence. Only then mark migration complete and expose normal load/save. A crash before receipt with both old and new bytes requires that same recovery path, not an automatic overwrite from possibly stale legacy; a crash after a matching receipt resumes verified cleanup, never replays reviews or merges custom words twice. A delete failure leaves recovery/incomplete state even when the new text exists. No step writes JSON, including a backup or error report. If an old backup differs from the primary, stop and present recovery; do not choose one silently. A fresh document created when no legacy data exists may load without a migration receipt; a receipt is required to claim cleanup of legacy bytes, not for ordinary text saves.

The store interface must gain explicit delete/list-old-backups operations and failure injection; current `RawKeyValueStore` has only `get`/`put`, and `RawProgressRepository` retains legacy/backup keys. Browser localStorage has no multi-key transaction, so the receipt and idempotent recovery are mandatory; write-and-readback each key and compare it, not merely assume `setItem` succeeded. An in-process per-document lock covers only one tab and is **insufficient** for same-origin tabs. New-version tabs require a proven cross-tab exclusion/transaction mechanism for migration and subsequent writes (for example an IndexedDB transaction-owned store or Web Locks where the target browser matrix supports it), plus re-reading and comparing both old and new byte hashes immediately before each commit/delete and recovering from stale receipts. BroadcastChannel notification or a best-effort localStorage lease alone is not a lock. An already-open old-version tab does not participate in a new lock and can rewrite legacy JSON after cleanup; before a mechanism or host policy proves that writer is quiesced, cross-tab migration and literal zero-JSON cleanup are **NOT PROVEN and block release**. Tests must interleave two new tabs and an old-version tab at write, receipt, delete, crash and reload boundaries, assert no lost review/custom word, and treat any reappearing old key as recovery rather than success. Android `AtomicFile` continues to own temp/rollback for each file; iOS NSUserDefaults and macOS/Compose Desktop files need their existing platform-specific write/readback guarantees plus deletion verification. Repositories must keep cancellation, lock ordering and previous in-memory state on failure; `TrainingStore` still serializes revisions and acknowledges exports by effect ID. For iOS/macOS import/export, replace `.json` UTType/MIME/filenames and Swift `JSONSerialization` snapshot handling only after the new typed/text bridge executes on real apps. React and Kotlin web storage are per-origin; do not claim migration of one origin's save by another origin without an explicit file transfer.

Snapshot choice is an independent gate: prefer typed KMP DTOs through the existing `IosSession`/`MacSession` interfaces and SwiftUI models. A successful Kotlin framework compile is insufficient; exercise nested matrix/style/lifehack data, nullable exercise, ordered effects, revision and acknowledgement in live iOS/macOS UIs. If typed export fails, define a `snapshot` schema on the same framing with no durable-save assumptions, bounded size, monotonic revision and a Swift parser tested against the KMP encoder. Commands remain semantic host actions; no new COMMAND/WIRE DSL is inferred from the historical NO-GO. Do not place mutable progress state or a JSON-shaped string inside a DTO to evade the constraint.

## Independent acceptance and P8 gate

Freeze protocol cases **before implementation** as text literals and expected typed trees, not generated output. Positive corpus: progress across every FSRS state/rating and timestamps; unknown skill and extension keys `-`, empty and `K:-`; UTF-16 key ordering across ASCII, BMP, supplementary and lone-surrogate keys; 32 prepared vocabulary cards, custom Unicode/emoji/escaped control text, homonyms and both directions; preferences v1–v4 conversion/defaults/reminder days/tint and early course peek; empty/null/absent distinctions; cross TS↔KMP JVM/JS/Wasm↔Native and Swift snapshot decode where used. Require byte-for-byte canonical re-encode and semantic equivalence, including the old accepted export fields except for ADR-51's explicit format change. Negative corpus: bad header/version/kind/schema, unprefixed or misplaced key/sentinel, noncanonical escape (`\u0009` for tab, `\u0041` for `A`, lowercase hex), malformed escape, invalid UTF-8/lone surrogate handling, overlong count/depth/size, duplicate decoded keys or IDs, trailing data, incorrect digest, NaN/Infinity bits, invalid FSRS state/date, bad preferences pack, invalid vocabulary pair/card wire, unknown-unconvertible extensions, **valid new text plus old bytes with no/mismatched receipt**, write/readback/digest/receipt/delete failures, cross-tab races and every crash boundary. Verify both old and new bytes remain untouched in that coexistence recovery case; verify untouched old bytes and no JSON output after each other failure.

**Legacy migration test exception:** final clean-CI tests must exercise actual old-user JSON input bytes because ADR-51 permits that one-time *read*. Freeze a minimal corpus as explicitly labelled **read-only legacy literals embedded in migration-test source**, or retain the existing `react-progress-v1.json` samples at their exact test-resource paths if they pass byte-hash review and are excluded from shipped apps. The samples are input only to the legacy reader, never a new authored format, expected-output generator, renamed JSON file, backup or export. Freeze exact bytes and hashes; assert the decoder is invoked only along migration paths; keep all newly authored requirement examples and expected outputs in text/DSL. The accepted exception is an *active migration-test input dependency*, so “no active JSON test dependency” in an earlier plan cannot be read literally: it means no **general** application JSON fixture/data dependency. [NoJsonFullPortPlan.md](NoJsonFullPortPlan.md) NJ06/NJ08 and [NoJsonAcceptance.md](NoJsonAcceptance.md) already name the exact-path, byte-hashed, test-only allowance; the final inventory must enumerate every permitted literal or file and prove it is absent from shipped bundles. No new `.json` test artifact is authorized by this design.

Treat `POLSKI-TEXT` as one **candidate**, not the chosen protocol. The concrete smaller established-format arm is **TOML 1.0 with a flat ordered `[[record]]` table sequence**, parsed and printed by maintained TOML libraries rather than a product lexer. Each row carries a parent/index, node tag and, where needed, a key and typed payload; use TOML strings for ordinary text and an explicit array of UTF-16 code units only for values TOML cannot represent losslessly (including lone surrogates). Keep the same document schemas, old-user reader, digest/receipt semantics, independent corpus, target host matrix, size bounds and recovery transaction for both arms; a TOML library's permissive duplicate/number behavior must be constrained by the same domain validator. Pin and audit actual TS/KMP JVM/JS/Wasm/Native/Swift library availability, parser behavior, package/bundle cost and licensing before claiming this arm is feasible. If the required host/library cannot round-trip the complete corpus, mark TOML **NO-GO with the failing case**; do not weaken the corpus or silently add a second parser. Compare both protocol arms against the good native static utility implementation under P8: total authored/generated lines, extension and UTF-16 handling, independent semantic edit sites, adaptation in Swift, reviewer locations, compile/package/cold-warm startup cost and N=10/100/1000 encode/decode scaling with ≥2× P23 headroom where required. Select no protocol until that equal-guarantee comparison runs. There is no P8 reason to author per-byte escaping, SHA or file transactions as Logic/FEATURE. A DSL declaration is warranted only if one schema/record declaration generates both TS and Kotlin field validation/read plans and demonstrably reduces independent semantic edit sites or defects over good native typed codecs. If the compiler's `*.inputs.json` or example JSON remains in this path, it fails the zero-JSON gate even when the save codec passes. Tester records exact runner/host, cases, source/artifact hashes, PASS/FAIL/NOT RUN/skips. Reviewer names violated P4/P5/P7/P8/P10/P15–P18/P23/P24 with file, trigger and consequence. Stop before integration on any silent data loss, unclassified schema difference, missing cleanup/recovery, active JSON emitter, unexecuted required host or native comparator win.
