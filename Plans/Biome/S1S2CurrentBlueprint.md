## Контракт S1

Ответ: сохранить порядок JS `NFC → польский lowercase → JS trim → удаление конечных .!? → схлопывание JS /\\s+/g` и сравнение с ожидаемым и `accepted`. JS whitespace включает NBSP, THIN, NNBSP, IDEOGRAPHIC и BOM из ожиданий; не подменять его платформенным `String.trim()`/Kotlin `\\s` без явного набора code points. Точное значение `normalized`, `correct`, `expected` и расстояние Левенштейна по UTF-16 code units — публичный результат `evaluate`; отсутствие диакритики остаётся ошибкой. Самый маленький кандидат — **NEW** чистый helper в `kotlin/shared/src/commonMain/kotlin/polski/grammar/JsWhitespace.kt`, используемый `AnswerNormalizer.normalize` и словарём. Его API должен обозначать `isJsWhitespace(codePoint)`/`trimJsWhitespace(String)` и `collapseJsWhitespace(String)`; набор кодовых точек фиксировать по JS поведению и тестам, без зависимости от UI/хранилища. Если маленькая правка существующего `AnswerNormalizer.kt` с одной общей внутренней функцией даёт те же гарантии и меньше стоимость, отдельный файл не нужен. Проверить `actual` Unicode case/NFC на всех компилируемых целях, а не предполагать идентичность JVM/Native/JS.

Словарь: `lemma`, `translation`, `form`, `example` обрезаются **перед** `1..240` UTF-16 code units и перед сохранением/экспортом; остальные поля, схема v1, ключи, карточки FSRS и ошибки остаются по текущему контракту. В `VocabularyCodec.validate` валидировать и **возвращать копию с обрезанными custom**; `decode` использовать этот результат, `encode` сериализовать именно проверенную копию, `merge` сравнивать нормализованные леммы и сохранять проверенный результат. Это важно: сейчас `encode` вызывает `validate(document)`, но сериализует первоначальный `document`. `VocabularySession.saveCustom` не должен обходить codec, а commit остаётся единственным владельцем записи; на отказе импорт/merge сохраняют прежний профиль и raw recovery. Сравнение дубликатов сохраняет существующие правила ID, case-insensitive lemma, same-ID winner и допуск старого homonym при восстановлении пустого профиля. Лимит — `String.length`, а не число Unicode scalar/grapheme.

Review: `ReviewReducer.recordReview` уже вычисляет `correct = typedCorrect ?: (rating != Rating.Again)`. Не переносить FSRS или мутацию статистики в DSL-предикат и не менять Scheduler. `RT-05` закрепляет конфликт `rating=again`, `typedCorrect=true`; обычные девять review случаев остаются независимым регрессионным набором.

## Контракт S2 и граница общего кода

Предлагаемый минимальный **NEW** `kotlin/shared/src/commonMain/kotlin/polski/interaction/SwipeDecision.kt` — только если измерение с равным набором тестов покажет пользу против малых native helpers. Возможная ABI: `SwipeDecision(dx: Double, dy: Double, threshold: Double, axisRatio: Double, checkYOnRelease: Boolean): SwipeRating?`, где `SwipeRating` — `Again/Good`, `null` — no commit. Передавать уже измеренные host units; `threshold > 0`, `axisRatio > 0`, конечные числа; равенство `abs(dx) >= threshold` проходит, а для требующих ось Y хостов строгое `abs(dx) > abs(dy) * axisRatio`. Положительный dx — Good, отрицательный — Again. Android на release передаёт `checkYOnRelease=false`: его начальный gesture arbitration уже требует горизонтального доминирования с ratio 1 и tap slop, но release решается **только dx**. Web/iOS/macOS передают `true`, ratio 1.25. Кандидат не читает clock, density, pointer, Compose, DOM или SwiftUI; не хранит gesture state и не вызывает callback.

| Хост | Порог, переданный после измерения хостом | Ratio для host gesture | Release | Вне pure-решения |
|---|---:|---:|---|---|
| Android | 72 dp → px через `LocalDensity` | 1.0 на захвате | только dx | `detectDragGesture`, tap/slop, TalkBack, `SingleRatingGate`, анимация |
| web | 75 CSS px | 1.25 | dx и dy | primary pointer/capture, sticky horizontal, interactive descendants, CSS/timeout |
| iOS | 80 pt | 1.25 | dx и dy | `DragGesture(minimumDistance:18)`, reveal/reduceMotion, fly-out/onRate |
| macOS | 70 pt | 1.25 | dx и dy | `DragGesture(minimumDistance:8)`, reveal/reduceMotion, fly-out/onRating |

Первый контроль — оставить текущие четыре маленькие native проверки и закрепить одинаковые независимые граничные входы. Kotlin common helper действительно общий для Android/web, но вызов из Swift требует реального экспорта через существующие `IosSession`/`MacSession` или другой уже существующий bridge: это дополнительные API, interop и Xcode проверки. Не объявлять Swift потребителем helper, пока скомпилированные call sites не подтверждены. Если общая ABI через bridge стоит дороже двух Swift helpers с теми же fixtures, сохранить host-local вычисление и зафиксировать ограничение общей функции; не добавлять Swift backend, `expect/actual`, lifecycle wrappers или новый DSL синтаксис ради этого среза. Для S2 чистая функция решает commit и направление; sticky preview, однократная отправка, тап, scroll и timing остаются на своих хостах.

## DSL и правило остановки

Текущий `biome-dsl` `.contract` описывает типы FACT/связи для чистых решений, `.logic` компилирует policy/read plan и Kotlin policy, но нет готового переносимого Unicode trim/NFC/locale/UTF-16 pipeline, host gesture lifecycle или Swift Logic target. Поэтому на S1/S2 **нет обоснованных NEW** `.logic`, `.contract`, `.examples`, `.feature`, `biome.project` или generated artifacts. Не писать JSON как human-authored конфигурацию. Если после native baseline появится конкретный чистый поднабор с двумя реальными потребителями и экономией против helper при тех же гарантиях, отдельное решение должно назвать `NEW` продуктовые DSL sources, facts, bindings, generated read plan и реальные host consumers до правки; проектные contracts станут источником типов, а артефакты генерируются, не исправляются вручную. Новый синтаксис DSL 1.x — только после сравнения, независимых ожиданий и измерения compile/startup/runtime/review cost. `COMMAND`/`WIRE` остаётся отдельным первоочередным экспериментом с NO-GO для грамматики сейчас.
