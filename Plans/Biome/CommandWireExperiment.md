# COMMAND/WIRE: stop-rule experiment for the training tab

Status: **bounded stop-rule executed; helper candidate STOP and removed; independent review APPROVED_WITH_MINOR (pending-status wording corrected)**. Product base: `db0728e` (`experiment/tab-wire`), separate from the existing B worktree and its user changes. Compiler audit: `biome-dsl` A9 accepted. This experiment changes no shipping wire behavior and authorizes no new DSL construct.

The bounded comparison used the unchanged direct-literal control and one temporary Kotlin common `TrainingTabWire` helper exported by the existing KMP framework. Literal command/snapshot fixtures were frozen before the candidate; separate one-sided Swift command and key drift probes did not ship either rename. The actual checks and STOP decision are below. Native jobs ran only under the coordinator's named grants; absent iOS runtime and UI/device checks remain NOT RUN.

## Scope and consumers

Measure one seam: the `"tab"` command with one `AppTab` value, and the `"tab"` string in the training snapshot. `AppTab` has `Training`, `Vocabulary`, `Matrix`, `Progress` in `kotlin/shared/src/commonMain/kotlin/polski/presentation/AppUiState.kt`; `AppAction.SelectTab` is in `AppAction.kt`. `TrainingStore.dispatch` owns the state change and Matrix-entry selection reset. Kotlin `IosSession.dispatch` and `MacSession.dispatch` translate strings to that action. `IosSnapshot.kt` and `MacSnapshot.kt` encode the field. Native SwiftUI consumers are `kotlin/iosApp/PolskiGrammar/PolskiGrammarApp.swift` and `kotlin/macosApp/PolskiGrammarMac/PolskiGrammarMacApp.swift`. This is one product with two Apple hosts, not two independent products. Unity MCP is excluded; no second real consumer has been identified.

## Actual compiler boundary and decision

The merged `implementations/typescript/packages/biome/src/support/contract-dsl.mjs` parses a **line DSL** `.contract`: `CONTRACT`, `COVERAGE`, `MODULE`, `FACT`, `LINK`, `INPUT`, `CONSUMER`, `CHECK`. Its facts bind pure decision inputs. `implementations/typescript/packages/dialects/logic/src/logic-compile.ts` produces dependency/root-fact read plans for decisions. `implementations/typescript/packages/languages/kt/src/logic-kotlin.ts` emits a Kotlin `Policy`, checked decision inputs and results; `logicArtifacts` writes the `.inputs.json` read-plan artifact. None models a host command envelope, snapshot key, JSON decode behavior or Swift declaration. There is no Swift Logic target. A `FACT tab enum=...` would describe an input to a decision; it would not generate these bridges. Hand-authored repository contracts must remain line DSL; a JSON descriptor is not an eligible DSL authoring route.

**NO-GO now for `COMMAND`/`WIRE` grammar or Swift compiler target.** One field in one product cannot establish a return for parser, AST, validation, printer, project wiring, generated Kotlin/Swift copies and review cost. The existing read-plan API is useful for pure policies, not this wire seam. Reconsider only when an identified second independent consumer needs the same command/snapshot contract, its independent behavior fixtures are frozen, and both consumers show an upkeep saving against native helpers with equal guards. That future decision belongs in the product's `AI/decisions.md` and the compiler's decision record before any syntax change. This is a stop decision, not a claim that a DSL candidate passed tests.

## Native contract and smallest experiment

First freeze the observed behavior in independent tests, then make a product-owned native helper candidate. Proposed **NEW** `kotlin/shared/src/commonMain/kotlin/polski/presentation/TrainingTabWire.kt` holds the command token and snapshot key as plain constants and offers `decodeTabCommand(command: String, value: String): AppAction.SelectTab?` and `tabWireValue(tab: AppTab): String`. The former accepts only the exact token and four exact enum names, returning `null` for unknown command, unknown/empty value. It returns a decision; sessions retain lifecycle ownership and call `TrainingStore.dispatch` only for a non-null action. Snapshot encoders retain `buildJsonObject` and write the helper's key and value. No logic predicate mutates state; no persistence or async work is added. Extract this helper only if the baseline/probe measurements justify its extra file and references; the current native `AppTab.entries.firstOrNull` is the lower-cost control.

Swift route: use the existing Foundation decoders with the smallest **NEW**, product-owned `TrainingTabWire.swift` constants/known-value accessor for each actual Xcode target, or one shared file only if both project generators and target memberships prove it is genuinely shared. The Swift wrapper must preserve the raw tab string. Do not use a closed raw `Codable` enum as the snapshot field: an unknown string currently parses on both hosts. iOS `Record.string("tab")` yields `""` for missing/wrong type; malformed JSON leaves the previous record. macOS `TrainingSnapshot.tab: String` requires a string; missing/wrong type/malformed JSON fails decode and retains the previous training state while setting an error. Unknown string remains available to existing selection/render logic. Keep those host-specific responses. A cross-language fixture/integration assertion must catch a one-sided Kotlin or Swift token/key rename; Swift constants alone do not prove coupling to Kotlin. Do not introduce a JSON descriptor or generator solely to move these literals.

The public Kotlin-to-Swift boundary remains `IosSession`/`MacSession.dispatch(command:value:)`, `currentSnapshot()` and `onState`; source names are not proof of generated Swift symbol spelling. `PolskiShared` is a static framework for `iosArm64`, `iosSimulatorArm64` and `macosArm64` (`kotlin/shared/build.gradle.kts`). Verify generated headers and compiled Swift calls when implementing. Both `generate_project.rb` scripts enumerate Swift source files, so adding a helper requires updating them and regenerating the project files; count those edits.

## Equal baseline and maintenance probes

Before either probe, capture hand-authored expected results independent of generated output. Cover all four tab values and initial `Training`; unknown command, unknown/empty value and repeat dispatch; entry into Matrix resetting selection. For snapshot parsing, cover each known tab, missing key, wrong type, unknown string and malformed JSON on **both** Swift hosts. Capture deterministic `currentSnapshot()` bytes when possible and parsed exact tab field/value separately; unrelated volatile fields and JSON object ordering do not belong to this oracle. A linked test or declaration is not execution evidence.

Run two independent, reset-to-baseline maintenance probes on isolated candidate branches, first on current direct native code and then on the smallest helper candidate if its baseline guards pass:

1. Rename command token `tab` → `selectTab` in both Kotlin parsers and both Swift senders. Four values still navigate; old token, unknown/empty value remain ignored; Matrix entry reset stays intact. Deliberately leave one Swift sender on the old token and require the integration assertion to fail before the full rename is accepted.
2. Reset. Rename snapshot key `tab` → `activeTab` in both Kotlin encoders and both Swift readers. Preserve values and each host's missing/wrong-type/malformed behavior. Deliberately leave one Swift reader on the old key and require an assertion to fail. Reset the probe; neither rename is a shipping requirement.

Record exact baseline/variant commits, changed authored/generated/reference files and lines, number of independent edit locations, manual edit time, cold/warm generation/build time and review burden. Hash emitted bytes if generation exists. Record startup, runtime dispatch/decode latency and allocations only if directly instrumented; do not infer them from a compile. Static token counts are not LLM usage; report provider usage only when actually metered. The native candidate wins only if it passes the same semantic and drift controls and reduces upkeep after its helper, Swift copies, Xcode wiring and tests are counted. Otherwise retain the direct code and independent contract tests. No DSL route is scheduled while its stop conditions fail.

## Actual bounded stop-rule result (2026-10-07)

The direct source control at `db0728e` passed `TrainingStoreTest` 23/23 on desktop and `MacSessionTest` 7/7 on macOS Native, including the new literal tab case. The iOS Native source/test compiled, but `iosSimulatorArm64Test` could not execute because this Xcode installation rejected simulator tests for `ios_simulator_arm64`; iOS runtime is **NOT RUN**. Candidate `TrainingTabWire` compiled into the real macOS framework, exported `TrainingTabWire.shared.command/snapshotKey/select(value:)`, and passed the same MacSession 7/7. The exact production `MacModel`/`TrainingSnapshot` prefix, compiled against the framework with a fresh owned data root, passed both direct and candidate probes; deliberate one-sided stale Swift command and `activeTab` producer inputs each failed as expected. Original rapid sequential tab probe failed identically on direct and candidate source, consistent with queued host callbacks; the corrected probe used a fresh model per tab. Rapid sequential switching remains **UNPROVED** here, not attributed to the helper. iOS Swift sender runtime, app/UI/device tests are **NOT RUN**.

The direct command rename needs two Kotlin parser and three Swift sender edits; the helper variant reduces the future token rename to its one constant only after adding a 10-line common object and touching five Kotlin plus two Swift production files (16 helper references/imports). The direct snapshot-key rename needs two Kotlin encoders, four iOS reads and the macOS `TrainingSnapshot` decoder; the helper centralizes Kotlin/iOS key use but leaves macOS automatic `Decodable` keyed to `tab`. Equal key-rename guarantees would require additional decoder code and review. Direct Mac Swift probe elapsed 4.745 s; candidate probe suite with two extra deliberate mutants elapsed 16.001 s, so these are **not paired performance measurements**. Manual edit/review time was not metered. No measured equal-guarantee upkeep saving exists; **STOP the helper candidate and NO-GO new `COMMAND`/`WIRE` DSL syntax or Swift compiler target** for this single product. Keep the original shipping wire and independent Kotlin controls; further consumers/modules require a separate decision.
