## Decision and actual live seam

The smallest useful **isolated live-consumer experiment** is the **skill/noun/profile/registry family for both language packs**, not another generated-value test. `kotlin/shared/src/commonMain/kotlin/polski/core/PlEngine.kt::PackEngine` currently defaults to `parseCurriculum(generatedCurriculumJsonByLang[langId])`; `kotlin/shared/src/commonMain/kotlin/polski/training/Curriculum.kt::plCurriculum` takes the same old map. `kotlin/shared/build.gradle.kts::generateCoursePackSource` embeds those files as string constants. The candidate `BiomeCurriculumConsumerTest` instead injects `{ generatedCurricula[language] }` into a test-only `PackEngine` and proves only that the real engine *can* consume the candidate; it does not switch the default engine. The candidate curriculum build still reads `lang.json` and `lexicon.json`, and its compiler pin `175ded7f42286f2bca25a82d8cc476a60b56b71d` was unavailable to a clean fetch. A local Kotlin pass cannot cure either blocker.

`CourseData.kt::CoursePack.skills`, `presentations` and `styleContent` separately read `skills[]` from the v1/pair documents. The 32 old skill records overlap the typed curriculum in `id`, `level`, order and `prerequisites`; they also carry title, group, formula, theory, hint, focus/methods and style content. `CoursePackLoader.fromV2Layers` brings the English pair into the same reader, and `packRegistry.active.skills`, `TrainingStore`, `Lifehack` and host screens consume it. A one-line replacement of `PackEngine.skills` would therefore violate P7 even if `generateBiomeCurricula --check` passes. `PackEngine` also reads old forms, recipes and realization, and `CoursePack` reads old lexicon, pair and editorial data. This experiment can prove a **live typed skill/noun path** while those other families remain transitional; it cannot be merged as the no-JSON product or claim NJ03/NJ08 release acceptance.

The source authority for a skill is `courses/lang/{en,pl}/curriculum.core-data` with one shared `SKILL` construct/type and derived `Fixed` keys from `courses/core/registry.core-data`. Keep `SkillSpec` in `:core-model`. Add a **project** `SKILL_COPY` typed declaration, one ordered record per skill in `courses/pairs/{en-ru,pl-ru}/skill-copy.core-data`: `skillRef` is a foreign key to the authored curriculum ID; the record owns only title/group/formula/theory/hint, teaching focus/methods and optional style content. `level`, `prerequisites`, ID order and the `Skill` identity are **derived** from `SkillSpec`; no second editable copies. Use existing Core typed record/list/null forms and project CONSTRUCT/TEMPLATE/printer patterns; first microprobe full-length multiline/escaping-sensitive text and nested style records. If current Core cannot retain their exact bytes and UTF-16 spans, compare a small typed Kotlin build helper with the same guarantees before any shared syntax change. Do not encode prose as opaque JSON or add a Polish-specific Core parser.

The only active profile/feature authority is typed `LANGUAGE_PROFILE` plus Core registry. Typed noun facts must supply all referenced noun IDs/genders and their actual forms, not a small manually copied ID whitelist. The accepted 28-noun/224-form design and frozen corpora are in [NJ03NounFormsVerticalSlice.md](NJ03NounFormsVerticalSlice.md); the adjective agent's 14-row/497-form work does not supply noun facts and its files are outside this cutover. This is a dependency: promote profile and noun producers into the isolated integration branch **after their own independent review**, then change `scripts/nj03/curriculum/{build,verify,validate}.mjs` to call the one typed catalog composition `readCoreCatalog → readLanguageProfile → readNounCatalog → validateCurriculumSource`. Remove `historicalLanguageCatalog`, the `JSON.parse` calls and old `lang.json`/`lexicon.json` from this producer's input list and manifest. Keep project semantic checks for `usesFeatures`, Case, construction, focus/fixed, nounId/gender, prerequisites and cycles; Core handles type/shape/source locations. Do not add a second registry or `Fixed` whitelist.

## Independent proof of a live change

The first behavior RED must run through the **default** production factory, not the test injection hook: with a compiling harness, an independently frozen skill edit changes the expected `PackEngine("en")`/`PackEngine("pl")` exercise or fails a checked reference; before switch the old JSON-backed factory cannot reflect it. GREEN must show exact frozen exercise output and `plCurriculum`/`PackEngine.skills`/`CoursePack.skills` IDs, levels, prerequisites and order from the same typed facts for both packs. A second mutation to a copy-only field must change only the displayed `Skill`/presentation, not `SkillSpec`; a typed ID/order change must fail the copy foreign-key check before Kotlin generation. A wrong noun reference and a missing language feature must fail with authored path and UTF-16 leaf span before the app builds. A corrupted generated Kotlin file, stale manifest, absent compiler pin and a reintroduced old JSON skill read must each fail their respective freshness/static guards.

Execute real `ExerciseGenerator.generateForSkill` on `en:role.object` and `case.acc.f` with the frozen complete expected `Exercise`, and `generateChain` for the accepted Polish 12×5 corpus once typed adjective/recipe/form/pair dependencies are ready. ## Cost, pin and release boundary

Before mass transcription of copy/noun records, execute an equal-guarantee comparison with one readable non-JSON Kotlin build-time helper: identical 32 skills, 32 presentation rows and 28 nouns/224 forms; same type, reference, diagnostics, UTF-16, freshness and real Kotlin consumers. Count one-time project construct/template cost once, then marginal form/copy/language edit sites, generated/authored LOC, review places, defects, compile/startup/runtime separately. Use the frozen noun and registry/curriculum P23 N=10/100/1000 workloads; freeze a separate presentation workload and fixed limits before timings, run the actual reader → validator → printer → Kotlin consumer and the helper in alternating CPU samples, require linear trend and ≥2× time/step headroom at N=1000. A faster helper with equal guarantees can own mechanical text/printing; it cannot become a second domain table.

The compiler pin must name a clean **fetchable immutable** revision and verified built-artifact digest. The old `175ded7f` local pin is a stop condition until replaced; a local sibling checkout or ignored `dist` is not clean-CI reproducibility. New compiler P14 syntax is used only after its own current full and fast gates; the product does not silently fetch a moving branch. Distinguish this bounded isolated live-consumer proof from final release: the remaining 101 tracked JSON inventory violations at the baseline, old save writers, Apple bridges, root TS/React, all-host execution and full FP/NJ requirements remain open. The final cutover removes every application JSON input/output and the obsolete TS product; only exact-path tool configurations and sealed input-only old-user migration controls may remain. Record the delivered maintainability comparison only after that full system is accepted.
