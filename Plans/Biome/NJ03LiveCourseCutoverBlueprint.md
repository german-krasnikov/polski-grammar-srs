## Decision and actual live seam

The smallest useful **isolated live-consumer experiment** must close the **skill, presentation, registry, profile, noun, residual-form and pair-port dependencies for both language packs**; a narrower step remains a generated-value or transitional fixture test. `kotlin/shared/src/commonMain/kotlin/polski/core/PlEngine.kt::PackEngine` currently defaults to `parseCurriculum(generatedCurriculumJsonByLang[langId])`; `kotlin/shared/src/commonMain/kotlin/polski/training/Curriculum.kt::plCurriculum` takes the same old map. `kotlin/shared/build.gradle.kts::generateCoursePackSource` embeds those files as string constants. The candidate `BiomeCurriculumConsumerTest` instead injects `{ generatedCurricula[language] }` into a test-only `PackEngine` and proves only that the real engine *can* consume the candidate; it does not switch the default engine. The candidate curriculum build still reads `lang.json` and `lexicon.json`, and its compiler pin `175ded7f42286f2bca25a82d8cc476a60b56b71d` was unavailable to a clean fetch. A local Kotlin pass cannot cure either blocker.

`CourseData.kt::CoursePack.skills`, `presentations` and `styleContent` separately read `skills[]` from the v1/pair documents. The 32 old skill records overlap the typed curriculum in `id`, `level`, order and `prerequisites`; they also carry title, group, formula, theory, hint, focus/methods and style content. `CoursePackLoader.fromV2Layers` brings the English pair into the same reader, and `packRegistry.active.skills`, `TrainingStore`, `Lifehack` and host screens consume it. A one-line replacement of `PackEngine.skills` would therefore violate P7 even if `generateBiomeCurricula --check` passes. `PackEngine` also reads old forms, recipes and realization, and `CoursePack` reads old lexicon, pair and editorial data. This experiment can prove a **live typed skill/noun path** only after pair-bound port binding and non-JSON form generation are in place. Until then it remains a generated-value/fixture test; even afterward it cannot be merged as the no-JSON product while other JSON-fed families and the v2 JSON merger remain active.

The source authority for a skill is `courses/lang/{en,pl}/curriculum.core-data` with one shared `SKILL` construct/type and derived `Fixed` keys from `courses/core/registry.core-data`. Keep `SkillSpec` in `:core-model`. Add a **project** `SKILL_COPY` typed declaration, one ordered record per skill in `courses/pairs/{en-ru,pl-ru}/skill-copy.core-data`: `skillRef` is a foreign key to the authored curriculum ID; the record owns only title/group/formula/theory/hint, teaching focus/methods and optional style content. `level`, `prerequisites`, ID order and the `Skill` identity are **derived** from `SkillSpec`; no second editable copies. Use existing Core typed record/list/null forms and project CONSTRUCT/TEMPLATE/printer patterns; first microprobe full-length multiline/escaping-sensitive text and nested style records. If current Core cannot retain their exact bytes and UTF-16 spans, compare a small typed Kotlin build helper with the same guarantees before any shared syntax change. Do not encode prose as opaque JSON or add a Polish-specific Core parser.

The only active profile/feature authority is typed `LANGUAGE_PROFILE` plus Core registry. Typed noun facts must supply all referenced noun IDs/genders and their actual forms, not a small manually copied ID whitelist. The accepted 28-noun/224-form design and frozen corpora are in [NJ03NounFormsVerticalSlice.md](NJ03NounFormsVerticalSlice.md); the adjective agent's 14-row/497-form work does not supply noun facts and its files are outside this cutover. This is a dependency: promote profile and noun producers into the isolated integration branch **after their own independent review**, then change `scripts/nj03/curriculum/{build,verify,validate}.mjs` to call the one typed catalog composition `readCoreCatalog → readLanguageProfile → readNounCatalog → validateCurriculumSource`. Remove `historicalLanguageCatalog`, the `JSON.parse` calls and old `lang.json`/`lexicon.json` from this producer's input list and manifest. Keep project semantic checks for `usesFeatures`, Case, construction, focus/fixed, nounId/gender, prerequisites and cycles; Core handles type/shape/source locations. Do not add a second registry or `Fixed` whitelist.

## Pair-bound engine and residual-form closure

`langId` alone is not an engine identity. `PlEngine.kt:66,82–83,97–100,112` chooses skills, recipes, templates and forms by language, but reads seeds, noun gender, copy, patterns, case prefixes and pronouns through `packRegistry.active` at different times. Constructing `PackEngine("en")` while pl-ru is active can combine English rules with Polish ports; switching the active pack after an engine or generator is constructed can change those ports mid-exercise. A passing direct `PackEngine(langId)` assertion is therefore not pack parity. Before live activation, add a checked `PackRegistry.requireByPair(pairId)` lookup over its registered immutable packs (`PackRegistry` currently exposes only `active`, `select`, `contains` and `options`); it must resolve the requested pair without changing `active`. Define an immutable, validated `PackContext(pairId, targetLanguage, nativeLanguage, skills, seeds, nouns, morphology, templates, recipes, copy, patterns, casePrefixes, pronouns, ...)` from that exact pair and its typed language catalog. A `langId` constructor must not guess a native language or borrow the active pair; callers pass an explicit pair ID, and the public active wrappers pass `packRegistry.active.pairId`. The ellipsis is an inventory obligation, not permission to leave a global callback: enumerate every `ExerciseGenerator` and `chainSteps` port in `PlEngine.kt` and bind it to the captured pair or an explicitly language-only catalog. Reject pair/language mismatch and missing referenced keys before `ExerciseGenerator` creation. The physical Kotlin provider may be small; the facts and decisions stay in typed sources. `PackEngine` receives this context, caches by **pair ID plus immutable source identity** rather than only `langId`, and its lazy values and callbacks never call `packRegistry.active`. `activeEngine` resolves the currently selected pair on each new request. A generator already handed to a session retains its captured context through that session; a later pair selection affects newly created generators, not an in-flight one. `enMorphology` remains a language-only table accessor independent of active pair, not a hidden pair engine. Keep `PackRegistry` as the owner of selection and invalidation, with explicit lifetime tests.

Removing nouns from old `course.json`/`lexicon.json` while `scripts/build-pack.mjs` and `scripts/build-pack-en.mjs` still run is invalid: they read those old nouns and write `courses/pl-ru/forms.generated.json` and `courses/lang/en/forms.generated.json`. `kotlin/shared/build.gradle.kts::generateFormsFixtureSource` then embeds their JSON in `GeneratedFormsFixtureJson.kt` and `GeneratedRecipesFixtureJson.kt`, and `PlEngine.kt:76` parses the former. The generated tables also contain adjective, possessive, verb, pronoun, auxiliary, preposition and negation forms; simply removing `noun:*` entries leaves a JSON-generating and JSON-reading path. **Do not remove old noun authorship or activate the typed noun consumer until the residual form family is ready in the same cutover transaction.** Read all form categories from their one typed Biome/project fact authority, materialize the accepted bundle→form table in a build-only, deterministic producer, and emit a typed Kotlin table or a typed non-JSON source consumed directly by `TableMorphology`. A mechanical materializer may be native, but cannot retain the domain choices in `build-pack*.mjs` or invent a missing form. Preserve both English `verb:<id>` bundle shapes (exercise and matrix), `aux:*`, `prep:*`, `neg:not`, Polish future/past/person/gender and all accepted old lookups; reject duplicate `(lexeme,bundle)` keys. Validate against independently frozen form cases, including the current core-golden grammar behavior after its JSON fixture is replaced by text/DSL expectations. Retire `pack:build`, `pack:build:en`, their `--check` scripts, both `forms.generated.json` files, `generateFormsFixtureSource`'s JSON embedding and `parseForms` only when equivalent generation, freshness and real morphology/exercise/matrix checks execute. No replacement producer writes an application JSON document or serializes JSON in a Kotlin string.

The bounded skill/noun experiment may be developed in isolation before all residual sources are ready, but it must **not** be called a live no-JSON cutover or merged as such. If the full typed form family or pair-bound context is missing, stop at independent typed-value and explicitly transitional fixture tests. A production no-JSON activation also requires replacing `CoursePackLoader.fromV2Layers`'s runtime `JsonObject.toString()` and all other active app JSON; the skill/form transaction is only the first dependency-closed part of that broader release.

## Cost, pin and release boundary

Before mass transcription of copy/noun records, execute an equal-guarantee comparison with one readable non-JSON Kotlin build-time helper: identical 32 skills, 32 presentation rows and 28 nouns/224 forms; same type, reference, diagnostics, UTF-16, freshness and real Kotlin consumers. Count one-time project construct/template cost once, then marginal form/copy/language edit sites, generated/authored LOC, review places, defects, compile/startup/runtime separately. Use the frozen noun and registry/curriculum P23 N=10/100/1000 workloads; run equal-guarantee form materialization and pair-context lookup probes with their own predeclared limits; freeze a separate presentation workload and fixed limits before timings, run the actual reader → validator → printer → Kotlin consumer and the helper in alternating CPU samples, require linear trend and ≥2× time/step headroom at N=1000. A faster helper with equal guarantees can own mechanical text/printing; it cannot become a second domain table.

The compiler pin must name a clean **fetchable immutable** revision and verified built-artifact digest. The old `175ded7f` local pin is a stop condition until replaced; a local sibling checkout or ignored `dist` is not clean-CI reproducibility. New compiler P14 syntax is used only after its own current full and fast gates; the product does not silently fetch a moving branch. Distinguish this bounded isolated live-consumer proof from final release: the remaining 101 tracked JSON inventory violations at the baseline, old save writers, Apple bridges, root TS/React, all-host execution and full FP/NJ requirements remain open. The final cutover removes every application JSON input/output and the obsolete TS product; only exact-path tool configurations and sealed input-only old-user migration controls may remain. Record the delivered maintainability comparison only after that full system is accepted.
