# NJ02 selective registry review: isolated experiment, no product merge

The selective Kotlin registry candidate `experiment/nj02-registry-selective-integration@92cf3654afa599a11e7e33197490f1fe02a1f13a` is a **bounded, independently tested experiment**. It is **not accepted for the canonical product branch** and does not close NJ02 or the no-JSON migration. The implementation [receipt](NJ02RegistrySelectiveIntegrationReceipt.md) and independent [tester receipt](NJ02SelectiveIndependentTesterReceipt.md) give exact commands, source/output hashes and target counts. The read-only reviewer approved only the experiment's technical scope and rejected the product merge for the blockers below.

**Major P7/P11 — two active authored registries.** The candidate adds 14 facts in `courses/core/registry.core-data`, while `courses/core/constructions.json` and `features.json` remain active inputs of root `course:validate` through `scripts/validate-pack-v2.mjs:176–183` and of the old tests. An edit could change the Kotlin and old product paths independently. [The NJ02 plan](NJ02KotlinLiveRegistryPlan.md) explicitly forbids merge while two maintained tables or the old registry reader remain in the accepted path. Continue on an isolated cutover branch; migrate the remaining course consumers and old-validator guarantees to the typed authority, then retire the old authored tables from active product use in the same reviewed cutover. The old bytes may remain only as sealed, read-only historical controls during development, not as a second product authority.

**Major clean-build reproducibility.** `scripts/nj02/biome-compiler.pin` names compiler commit `175ded7f42286f2bca25a82d8cc476a60b56b71d`, but a fresh shallow fetch from its declared origin returned `upload-pack: not our ref`. A local clean worktree and 104-artifact SHA pin do not make this revision available to clean CI. Use a fetchable, immutable compiler revision and rerun the artifact/freshness checks before product acceptance.

The independently executed Desktop tests passed 15/15 and Wasm catalog/registry tests 8/8. JS task failed after a Karma ping timeout: only nine passing test cases appeared in XML; the other selected cases were not proved by that run. The developer's separate JS run passed 12/13 with one 10-second test timeout, reproduced on the old baseline, and is still a failed target. Source/binding/output R9 mutations and ignored compiler-artifact tamper all failed the read-only check and recovered green. Developer macOS/iOS native 13/13 each were not rerun by the independent tester. Live `PackEngine` checks construction/focus/fixed but does not pass `usesFeatures`, so R7 remains test-only on old inputs. P14 whole-language differential, P23 actual reader→validator→Kotlin printer→consumer N=10/100/1000, Android/device UI, full compiler gate, clean CI and no-JSON acceptance remain open.

The next NJ03 curriculum work can use this **isolated** registry branch as an experimental base to remove the double authority; it must not cherry-pick the registry code into canonical early. The independent 32-row corpus and new [N02/N03 project rules](NJ03NewSemanticRules.md) remain the expectations. Finish a single-authority cutover, fetchable pin and missing execution gates before a reviewer reconsiders NJ02 product integration.
