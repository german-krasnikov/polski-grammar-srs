Exactly 28 noun facts and 224 form values are the *real course*, with exact IDs, Unicode, order, Polish five-way gender and English absent gender. Neither a scaled workload nor a generated Kotlin value becomes a new course oracle. The old authored Polish `courses/pl-ru/course.json` (SHA-256 `7255e8c686ceee17a72d280e5876b0cf6776dd9a1743884cd75c724fb8180dcc`) and English `courses/lang/en/lexicon.json` (SHA-256 `f96da7fc14e569d2e061a9f0b39a6d97ead26eb7f21d6521d9ed457a8d0abd80`) are read-only historical inputs to those frozen expectations. They cannot enter the final build, runtime or benchmark input path.

The candidate source contract, from the vertical-slice plan, is two project `NOUN {…}` `.core-data` sources plus one `.construct` surface and typed `PlNoun`/`EnNoun` Core declarations. **NEW** `scripts/nj03/nouns/validate.mjs` must call the actual `core.parseSurface` and `core.readLocatedExprValueResult`, then check unique/nonempty IDs, gender, nonempty required forms and references. **NEW** `scripts/nj03/nouns/build.mjs` must call that validator and the real project Kotlin printer, publish immutable ordered typed facts and the derived `noun:<id> → FeatureBundle → form` table, and own a plain-text hash manifest/`--check`. The proposed typed Kotlin seam is `CoursePackLoader.fromBiomeNouns(languageId, generatedCatalog)` returning ordered immutable rows plus an ID lookup owned by that catalog; the benchmark resolves every ID through this actual entrypoint. The form derivation uses existing `FeatureBundle` names: Polish `noun:<id>` maps `Number=sg/pl` plus `Case=nom/gen/dat/acc/inst/loc/voc`, and English maps `Number=sg/pl` with no `Case`. `TableMorphology.form` is called on those exact bundles. The helper never guesses a Polish form from gender or an English plural from a lemma. ## Equal-guarantee native control

Build an **isolated, Kotlin/JVM build-time control**, **NEW** `scripts/nj03/native-nouns/` (source and invocation to be fixed in the developer blueprint). It is a genuinely compiled command-line helper, not a paper design and not a production fallback. It reads one readable, non-JSON UTF-8 text table per language: header fixes `language,id,lemma,meaning,gender,sg.nom … pl.voc` for Polish and `language,id,lemma,meaning,sg,pl` for English; one row per noun; tab-separated cells with explicit `\\`, `\t`, `\n` escaping. A bare `null` is rejected in every required text cell. Missing/extra columns are shape errors. The helper's small lexer must retain the physical UTF-16 start and length of each cell and reject malformed escapes, non-UTF-8 input and unpaired UTF-16. No application JSON input, intermediate, emitted Kotlin string or output is allowed. Its table is materialized in memory from the *independent frozen 28 rows*, using the same cyclic `j` and ID transform as above, and sealed by its own byte hash; the native helper must not call the candidate parser or consume candidate IR. The helper's grammar and escaping rules are a benchmark control only; do not ship a second maintained noun authority.

The control enforces the **same subject guarantees** before emission: complete and nonempty fields, exact `sg/pl`/Polish seven-case shape, legal five-way Polish gender, English gender absent, unique/nonempty IDs, source-order retention, exact Unicode, one lookup per transformed reference, unknown reference refusal, and a source path plus first offending UTF-16 line/column for every frozen negative category above. For a syntax category with different spelling, compare the *semantic error class and offending cell/path*; never claim byte-identical diagnostics across two different grammars. It emits the **same Kotlin ABI and values** as the Biome arm to isolated output directories, using its own narrow Kotlin emitter; compare normalized generated file bytes and all 28/224 independent values before any timing. Any unavoidable header/path difference is recorded explicitly and excluded from the byte comparison, not silently ignored. Both arms provide a manifest naming complete source, schema/type/helper or definition, printer and output hashes; `--check` must fail after independent mutation of source, contract/schema, printer/helper or output. Both generated sources must compile and execute the *same* typed loader and morphology tests. If the native helper cannot deliver a guarantee, it is not an equal control and no A/B speed or maintainability claim is valid.

This control tests the user's P8/P13 alternative: a small native static build helper can win for a bounded data family. Its own authoring/tooling LOC, parser/validator/printer LOC, concepts, semantic edit sites, duplicated authorities, review surfaces and observed defects are counted alongside the Biome arm. Report a single irregular form edit (`wife` English plural), one Polish gender edit and one identity/reference edit on disposable copies through both complete source→freshness→compiled-consumer paths. Keep user-facing expectations fixed, count the actual edits and rerun the same negative cases. Static token counts are **not** LLM usage.

## Logical work units and exact increment sites

The following names and accounting rules are fixed here; the completed `.cases` records source-file/line anchors after implementation. Add optional test-only counters to the existing loops, never to emitted runtime data or production limits. Time **uninstrumented** calls; rerun each sealed input in instrumented mode and require byte-identical output and diagnostics. Count each event once per actual occurrence, not `N` by formula:

| Counter | Increment at actual site |
| --- | --- |
| `preprocessUnits`, `preprocessLineVisits` | Charge every **actual invocation**, including the nested calls from `surfaceName`: at Core `surface.ts::parseSurface`'s optional `unquote`, `version.ts::stripVersion`, `surface.ts::uncomment`, every `lines.ts::toLines` called by `surface.ts::first` or `uses.ts::scanDeclarations`, `surface.ts::blank`, and the one-line `surfaceName` regular expression. The fixed UTF-16 charges are respectively `2× input.length` for `unquote`, `1×` for `stripVersion`, `2×` for `uncomment` (replace plus line scan), `3×` for `toLines` (split, per-line trim/offset, result construction), `2×` for `blank` (search plus copy), and `1× firstLine.length` for `surfaceName`'s match. Increment `preprocessLineVisits` once per line actually inspected by each `first(...).find` call. These are conservative, deterministic material-traversal work units, **not** measured CPU instructions; if a pass is absent, charge zero. Count repeated whole-source passes separately rather than charging one source length and hiding preprocessing. Instrument the named function entries/call sites, including the header path, before any P23 step verdict. The native helper must likewise count any whole-table preprocessing it adds instead of hiding it inside `nativeUnits`. |
| `surfaceUnits`, `bodyUnits` | One per UTF-16 source code unit advanced by Core `scanDeclarations`/`parseSurface`'s **declaration tokenizer** and Kit `tokenizeData`'s body tokenizer respectively; record these separately from `preprocessUnits`, including delimiters/whitespace. The native lexer counts its own physical advances as `nativeUnits`, never pretends its flat table has a Biome body pass. |
| `literalTokens` | One per token consumed by Kit `readDataValueInternal` when it advances `ps[i]` for a key/value/delimiter; the native control counts each decoded cell or separator token as `nativeTokens`. Lexing and parsing are distinct counters; no double-counting within one counter. |
| `typedValues`, `typedMembers` | Core `checkLocatedExprValue` / `expr/materialize.ts::checked` visits each scalar/list/record value and each record member during the type walk; the control counts its field-schema visits at the corresponding validation loop. The expected 135/1,350/13,500 `typedMembers` above excludes any optional extra traversal; deviations must be explained before a verdict. |
| `idInserts`, `refLookups` | At the project noun validator's real `Map.set` after duplicate check, and at each `Map.get`/`has` for a supplied typed noun reference. The native control increments at its equivalent map operations. For the scaled positive workload these are exactly `N` and `N`; all other reference checks have separate receipts. |
| `printerValues`, `printerUnits` | At each typed noun/form value visited in the real Kotlin printer, and at every UTF-16 code unit appended to the *escaped emitted Kotlin text*. The native emitter counts the same kinds of events. `printerUnits` includes escaping expansion; do not substitute input bytes or an output-length estimate. |
| `catalogRows`, `catalogForms`, `loaderLookups`, `morphLexemeLookups`, `morphBundleLookups` | At each row and form inserted when the actual typed `CoursePackLoader.fromBiomeNouns` builds its catalog, at its ID lookup, and at `TableMorphology.form`'s outer `forms[lexeme]` and inner `get(bundle)` respectively. The selected Kotlin test constructs `N` rows/`8N` form entries, makes `N` ID lookups and `8N` form calls (`80/800/8000`); both morphology counters therefore equal `8N` on success. A wrapper or precomputed lookup table outside these actual methods is not evidence. |

Only common semantic counters (`typedMembers`, ID/reference, printer visits/units, catalog construction, loader and morphology) may be compared numerically across arms; different source grammars have separate lexer counters. The reported total logical work for each arm is the sum of its named counters, with each component and exact increment site shown. The counter implementation must be reviewed for accidental repeated full scans and disabled-path overhead. Do not raise Core `PROGRAM` defaults or the data nesting limit of 64 for this family.

## Predeclared envelopes and measurement protocol

These are **admission envelopes**, not product execution caps; each measured N=1,000 result must have at least **2× headroom**, hence meet the right column. A reviewed amendment committed *before* any first measured run is the only way to change them. Apply the same envelopes to candidate and built native control; failure of either arm is reported, never hidden by a faster median. CPU is process CPU for Node/JVM build-time functions, JVM thread CPU for the in-process Kotlin consumer, and complete process-tree CPU for compiler/Gradle jobs. Unavailable CPU is **NOT RUN**, not zero or a pass.

| N=1,000 stage, per arm | Fixed wall / CPU / counted-step envelope | Admission with 2× headroom |
| --- | --- | --- |
| Warm full source reader + shape/type/project validation + actual Kotlin printer, excluding file I/O/hash/manifest | 6,000 ms / 6,000 ms / 6,000,000 named steps | ≤3,000 ms / ≤3,000 ms / ≤3,000,000 steps |
| Warm manifest/freshness check over real files, reported separately from compilation | 2,000 ms / 2,000 ms / 20,000,000 byte/hash/check steps | ≤1,000 ms / ≤1,000 ms / ≤10,000,000 steps; include every input/output byte in the named byte-work count |
| In-process generated Kotlin catalog construction + `N` typed loader ID lookups + all `8N` actual `TableMorphology.form` calls, after class load | 2,000 ms / 2,000 ms / 100,000 named steps | ≤1,000 ms / ≤1,000 ms / ≤50,000 steps |
| Fresh generated N=1,000 Kotlin compilation and selected executable Desktop consumer on a proven no-application-JSON graph | 900 s / 900 s complete process-tree CPU / no logical-step claim | ≤450 s / ≤450 s; configuration, Kotlin compilation and test launch separately itemized |
| Cold Node/JVM helper launch + one source validation/print + freshness, with tool already built | 120 s / 120 s complete process-tree CPU / step count reported separately | ≤60 s / ≤60 s; startup never folded into warm per-record time |
| Fresh compiler package or native helper build | 900 s / 900 s complete process-tree CPU / no logical-step claim | ≤450 s / ≤450 s, reported separately for each arm |

The fixture records actual source/output sizes before timing. A model that emits more than 10,000,000 hashed bytes per freshness call fails the predeclared headroom; a pre-measurement amendment needs independent review, never a post-hoc limit raise. Large generated output is therefore visible as a cost, not erased by a fast hash implementation.

Run one worker, no competing Gradle/compiler job, fixed machine/OS/tool versions and clean revisions. First compile/build both helpers and generated outputs; perform correctness/freshness/negative checks outside the timed segment. For warm timing use at least seven rounds rotating size order `10→100→1000`, `100→1000→10`, `1000→10→100`; within each size alternate Biome/native order, 100/10/1 whole-pipeline repetitions respectively, and reverse the first arm on alternating rounds. Each timed call receives fresh text and constructs new maps/output strings; it may reuse an already loaded module/JVM but never a parsed AST, generated source or cached validation. Record all seven raw wall and CPU values per arm/stage/size plus median/minimum, not a single best run. Cold launch and fresh build/compile each get at least three alternating samples where feasible, with every sample shown. Log checks after each batch. For Kotlin consumption, run each arm's generated source in a separate clean build directory and the same typed test; report class load/construction separately from lookup loop and any test-launch overhead. Do not run parallel Gradle builds.

For each counter and median per-call wall/CPU, require N=100 ≤12× N=10 and N=1,000 ≤12× N=100, with a 1 ms floor only for clock noise; report per-noun and per-form ratios. Compare arms only for the equal-guarantee full path, with their different source formats and runtimes plainly identified. Report build/startup/runtime/review as separate costs, never a single misleading speedup. A faster control does not automatically choose native if Biome removes a second semantic authority or adds an executed guarantee; a DSL win likewise requires measured benefit. The decision records P7/P8/P13/P23 separately.
