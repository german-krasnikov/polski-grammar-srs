[ReviewCreditExperiment.md](ReviewCreditExperiment.md), [CourseTablesPilotResult.md](CourseTablesPilotResult.md) and [CommandWireExperiment.md](CommandWireExperiment.md) are bounded NO-GO results, not implementation starting points or permission to reintroduce their artifacts.

## Owner constraint and acceptance boundary

The owner has clarified **zero JSON for application-owned authored sources, generated artifacts, runtime/interchange messages, user storage, and new exports/imports**. The only application-data exception is **read-only, one-time parsing of an existing user's legacy JSON save to migrate it to the new text format**. A successful or failed migration must never write a new JSON document, export JSON, or store a newly serialized JSON backup. Preserve the exact original legacy bytes during a migration attempt so every failure can recover; after validated text readback and a durable text receipt, remove the old JSON key/file **and its old JSON backups**. A failed or unsupported migration keeps the original bytes in recovery without overwriting them and cannot be reported as a completed zero-JSON state. Existing `.json` test/course artifacts may be read as frozen historical oracles during development, but the accepted product and its new tests must not require, produce or ship them. Never turn a historical JSON fixture into a newly authored source.

**Tool-required manifests/configuration are allowed exceptions**: `package.json`, `package-lock.json`, `tsconfig*.json`, Xcode asset-catalog `Contents.json`, and temporary manifests required by an external build tool. Their contents must be tool configuration, not a hiding place for app course facts, requirements, generated read plans or user data. List every exception and its requiring tool in the release inventory; a generic `*.json` exemption is disallowed. Third-party packages may use their own private formats; the app may not treat those as application interchange. If a build tool starts emitting an app-owned JSON file, this exception does not cover it.

This explicit owner constraint takes precedence over biome-dsl `AGENTS.md`'s prior allowance for generated/machine JSON. Preserve its independent expectations and execution rules, and apply `AI/PRINCIPLES.md` P4/P5/P7/P8/P10/P15–P18/P23: appropriate DSL source, one authority, measured native comparator, no silent expectation edits, no hand-fixed generator output, real executed gates. The target is a complete product preserving FP01–FP11 from [FullPortPlan.md](FullPortPlan.md), not a claim that every UI callback or codec operation becomes DSL. Native Kotlin/Swift/TypeScript may implement mechanical encoding, effects, scheduling arithmetic, input handling and platform lifecycle; authored domain rules and requirement examples need a justified DSL home.

The review-credit pilot also tested the wrong abstraction size: `typedCorrect ?: (rating != Rating.Again)` and its TypeScript equivalent could have been rendered by one construct with two target templates, but even that adds generation and fact bindings for two native one-line decisions. Keep this rule in the existing reducers with shared independent behavioral expectations unless a later measured consumer shows a real guarantee or maintenance gain. A target of “everything in DSL” does not override P8.

## Proposed textual source and output contract

The current `.tables` `ROWS` grammar cannot satisfy this requirement. Its 16-row English pilot encoded `focus`, `fixed`, `lexicalFilter` and `prerequisites` with `{...}` and `[...]` literals, and `renderTablesJson` generates JSON. Parent/child columns conflict, while the curriculum needs both explicit null and nested values, plus an empty `fixed` object. Splitting into many `ROWS` blocks would hide order and add syntax without eliminating JSON-like lists. The measured pilot retained one semantic edit site, increased review surfaces and failed P8. `DECLARE`/SURFACE currently reads on JS only; `TEMPLATE` renders output and is not a typed nested course reader. No existing surface should be represented as capable of the whole no-JSON conversion.

First test whether current **construct-only `.feature` authoring with `DECLARE`, `ITEM ROW` records and TS/Kotlin `TEMPLATE` outputs** can represent a bounded typed curriculum without JSON-shaped literals or a separate handwritten parser. That is a candidate, not a proven product path: verify the actual parser, nested/optional/empty values and record order, then compile *and execute* both target outputs. A particularly important compiler gap is Kotlin string escaping for all course content (`$`, quotes, backslashes, line separators, lone surrogates); a TS success or one ASCII row is inadequate. If the existing constructs cannot express these cases, propose a **reusable Core record/list declaration capability** with the smallest general extension and independent conformance, rather than a Polish-only grammar. The following is a *desired semantic shape, not accepted compiler syntax*:

```text
SKILL en:mixed
  CONSTRUCTION core.composite
  FOCUS NONE
  FIXED EMPTY
  FILTER NONE
  LEVEL B1
  REQUIRES en:possessive.my
  REQUIRES en:verb.pastSimple
END

SKILL en:role.recipient
  CONSTRUCTION core.argument.case-role
  FOCUS Case Obj -> To
  FIXED Tense TEXT Pres
  FIXED Person TEXT 1
  FIXED Number TEXT Sing
  FILTER noun nounId wife husband friend son dog cat child
  LEVEL A2
  REQUIRES en:role.instrument
END
```

The general mechanism must represent ordered records/lists, optional versus explicitly absent values, empty maps/lists, string values such as `Person = "1"`, Unicode and multiline explanatory/citation text without inline JSON syntax. Text blocks require unambiguous escaping or length delimiters, source spans, validation and stable round-trip. Use separately named reusable constructs for nouns/paradigms, recipes, lifehacks, styles and editorial copy; do not flatten the 64,573-line human-classified inventory into one unreadable row or invent a Polish-only parser. Emit typed TS/KT values from a common validated IR, preferably sharded by pack/domain to avoid compiler or Kotlin constant limits. Generated files are build outputs, never edited; a text manifest pins compiler revision and checked generator inputs. Kotlin `:core-model`/`:pack-format` types and current public entrypoints remain compatible through adapters while JSON parsers are retired. Source order, null/empty distinction, exact Unicode and content strings, and all accepted invalid-reference diagnostics need independent expectations frozen **before** the first source move.

For acceptance, no generated course artifact or test fixture may contain an application-data JSON object encoded as a string. A source extension change alone is not migration. If a Core typed record capability is too costly or unavailable, evaluate an established non-JSON textual format with a strict shared schema and typed emitters against the same guarantees and P8 comparator; do not quietly build separate TS and Kotlin parsers. Record any Core change as general, independently conformed compiler work, with boundary and representative host checks required by biome P2/P9/P10.

## New text save, migration and bridge contract

Choose one versioned UTF-8 **text record wire** for new progress, vocabulary and preferences files and cross-host import/export; the proposed extension is `.polski`, header `POLSKI-DOC 2 <kind>`, followed by typed records with canonical ordering and a specified escape/length rule for arbitrary text, tabs, newlines, backslashes, Unicode and user-authored words. These names are provisional until a frozen wire specification and independent decoder fixtures exist. Records must distinguish absent from empty, preserve integer/floating point FSRS values and timestamp precision, reject malformed/duplicate fields/IDs, and retain unknown extension fields where compatibility requires it. A checksum or digest must cover exact committed bytes; do not use locale-dependent formatting. The shared KMP codec serves Kotlin hosts; a TS codec for the retained React baseline uses the same versioned specification and independent cross-decoder corpus. The physical storage adapter remains platform-owned. Snapshot wire, if typed Swift bridging fails, is a separate `snapshot` kind with revision/effect IDs and bounded size, not a save-document parser reused blindly for UI.

The **sole legacy exception** is a read-only JSON decoder for an existing user's `progress-v1`, `vocabulary-v1` and preferences files/keys, invoked only when no valid new-format document exists or during explicit import of an old user save. No call path may serialize legacy JSON for new saves, backups or exports. Migration order: detect new document and receipt; if absent, read and preserve original old bytes without mutating them; strictly validate legacy version/content and all known and unknown fields; convert to typed model, including representable unknown fields as typed text extension records; reject unknown data that cannot be converted without loss; encode new text; write to a *new key/path*; read back and decode; compare every semantic field and extension plus checksum against the in-memory model; write a durable idempotent **text receipt**; then delete the old JSON key/file and any old JSON backup. A crash between receipt and deletion resumes cleanup without re-importing or duplicating reviews/custom words. On parse/write/readback/receipt/delete failure, do not overwrite old bytes or an earlier valid new document, and surface recovery; the presence of old JSON remains an incomplete migration, never a claimed successful zero-JSON state. The legacy decoder must have no normal read path after committed cleanup. Do not overwrite a legacy save with a fresh empty document. Never expose a newly generated JSON download. Old imports are read-only input to this path; exported downloads and file picker labels/MIME types are new text format only. The changed requirement for legacy byte-identical JSON export is recorded separately by ADR-51, not silently patched into old independent expectations (P15).

One-time migration must be proved for browser localStorage, Android app-private files, Compose Desktop, iOS and native macOS, plus cross-host text import/export. Test missing/unsupported/corrupt/truncated old bytes, duplicate IDs, unknown skills, all FSRS states and timestamps, local midnight/DST, partial marker/backup/readback failures, interrupted writes, retry, rollback and cancel. Preserve current user progress, vocabulary cards in both directions, preferences and existing old-format data until the transaction is recoverable. If a platform cannot safely read its existing legacy data and commit a new document, that platform blocks the release.

## Stop, rollback and review

Stop a slice if text authoring merely embeds JSON under a new extension; a second human-maintained fact copy appears; Kotlin/TS generation requires manual semantic bindings; a generated file is hand-fixed; null/empty/order/Unicode/forms differ; the legacy decoder writes JSON or destroys old bytes; an interrupted migration cannot safely retry; a compiler/backend cannot execute in a required consumer; an independent expectation is rewritten to match output; host execution is missing but reported PASS; an app-owned JSON artifact remains; or the equal-guarantee native solution wins P8. Retain NO-GO evidence. Roll back experimental source/build changes without touching legacy saves or unrelated inventory repair; after a released migration, never downgrade a new-format user document by writing JSON. Review each change against the named P principle, concrete file, failing case and consequence. A local prototype, clean compile, generated plan or linked test is not proof of FP01–FP11 or NJ01–NJ10 completion.
