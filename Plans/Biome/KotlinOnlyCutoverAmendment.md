# Kotlin-only product cutover amendment

Status: **owner scope decision and execution plan; no Kotlin-only cutover has run**. At product branch biome/full-port-2026@f1facd3 the owner explicitly required removal of the old React/TypeScript product: the delivered application is Kotlin. This amendment supersedes any final-target sentence in FullPortPlan.md, NoJsonFullPortPlan.md, NJ02Blueprint.md, or an older receipt that calls for a maintained React runtime, TypeScript course module, TypeScript save codec, or a published /react/ rollback copy. Historical TS/React behavior and test results remain evidence; their expectations are not silently rewritten. The separate biome-dsl compiler remains its own project and may be implemented in TypeScript; using that external tool does not make TypeScript an application target.

## Boundary and current facts

The shipped primary web app is already Kotlin Compose JS/Wasm at the site root. Android and Desktop use Kotlin; the shared domain engine is Kotlin Multiplatform. Existing iOS and macOS apps contain SwiftUI host shells. This decision removes the obsolete React/TypeScript application and its duplicate domain implementation; it does not silently delete an Apple host or pretend that its SwiftUI code is Kotlin. Swift remains limited to host UI, OS integration and bridging; domain facts and decisions have one Kotlin/DSL owner. Replacing the Apple UI framework itself would be a separate requirement.

At the recorded baseline the root package builds Vite/React, has src/**/*.ts(x), tests/**/*.ts(x), scripts/**/*.mjs or mts, browser specs, TypeScript configs, npm manifests and a /react/ deploy step. These paths are an **inventory to classify**, not a deletion list to apply blindly. Some scripts validate course data or generate inputs consumed by Kotlin Gradle; removing them before equivalent Kotlin/DSL checks exist would erase a guarantee. The existing 268 root tests and historical React output are migration controls, not a second accepted runtime. The current Kotlin app and its host behavior are the final acceptance subjects.

The strict application-data rule from NoJsonFullPortPlan remains: no authored, generated, runtime, storage or interchange JSON in the final app. Only read-only one-time legacy-user JSON migration and exact-path, byte-hashed, input-only test controls are allowed. Tool-required configuration remains allowed while its tool is needed; the npm and TypeScript manifests stop qualifying once the corresponding root toolchain is retired. No old React asset, JS bundle, JSON course file or JSON save writer may ship as a fallback.

The owner also requested Biome's shared-variable path for Logic and tests. Freeze one fact/type/binding contract; Logic reads those names, while independent `.examples` or `.sources` rows own expected results. The existing `.given` `PORTS FROM file.contract` derives typed `QUERY` ports from contract `FACT`s, and shared `LET` values can be reused as `$name` in test plans. It does not derive fixture/action signatures or a Logic decision-result port. Derive any EditMode `TESTCASE` bindings and typed Kotlin test inputs from the same contract and independent requirement source with a checked project adapter; never hand-maintain a second Kotlin map of facts or expected values. First prove this on one representative, economically useful decision with an undeclared or wrongly typed variable negative and a stale-binding mutation. The current Kotlin plan printer supports EditMode JUnit and rejects PlayTest; Kotlin PlayTest remains **NOT RUN** until an execution-layer runner is implemented and exercised. A generated plan alone is not Kotlin execution. Compare the whole path with a small Kotlin helper before scaling: the prior one-line review-credit/`typedCorrect` Logic experiment was a measured NO-GO, and the current Logic artifact command emits forbidden application `.inputs.json`. Keep browser, storage and platform lifecycle assertions in actual Kotlin host tests even when a DSL scenario describes the expectation.

## Ordered cutover

1. **Freeze the old evidence without making it a new authority.** At baseline product f1facd3, make a reviewable mapping table with one row per old test assertion or validator guarantee: old file/test ID and source SHA, independent expected-case source/hash and FP/NJ ID, replacement DSL example or Kotlin test file, Kotlin target/host, command and selected/executed/skipped/failed count. Inventory every root TS/React file, script, test, browser spec, generated artifact and deployment edge by actual consumer. Mark deliberate Kotlin differences and old defects separately. Freeze independent text/DSL expectations and old-user byte-hashed inputs before retiring their executable oracle. Preserve old source and receipts in Git history and non-JSON reports. A linked or previously passing TS test does not prove a Kotlin test ran.
2. **Keep the compiler experiments isolated.** NJ01 Node measurements and NJ02 TS printers compare general compiler behavior and escaping, but are not final product backends or live Kotlin integration. The accepted product generator emits one typed Kotlin course/registry/read-plan output from one Biome authority, with source/binding/output freshness. Inspect and retire the JSON embeds and duplicate authority in kotlin/shared/build.gradle.kts lines 7–19, 49–111 and 138–177 along with their derived validators/generators; no second maintained course fact survives. The real Kotlin CoursePackLoader, Curriculum, PlEngine and web/Android/Apple/Desktop consumers must execute the output. A generic compiler extension still needs independent second-consumer, compatibility, boundary, full-gate and P23 proof.
3. **Replace every active root guarantee in Kotlin before deletion.** Move course/schema/negative-reference checks to Biome contracts and Gradle/Kotlin validators; move accepted grammar, FSRS, review, vocabulary and presentation expectations to independent DSL examples plus Kotlin tests; run Kotlin JS/Wasm, Native and JVM targets. Use a Kotlin/JVM browser harness with Gradle-pinned com.microsoft.playwright:playwright:1.63.0, following the official Playwright Java API (https://playwright.dev/java/docs/intro). Before retiring any TS browser spec, prove this driver can launch pinned Chromium, Firefox and WebKit binaries and run one observable current Kotlin web assertion in each; record exact versions and selected/executed counts. Then map every accepted old browser assertion to Kotlin-authored tests of the Kotlin JS/Wasm app. Browser UI proof is separate from Android, iOS/macOS and Desktop host execution. Keep an old TS test read-only until its corresponding Kotlin replacement passes and an independent reviewer checks the assertion map. Do not transfer a known React-only defect as a requirement.
4. **Switch the one authority and storage path.** Complete the no-JSON course, text-wire, old-user migration and all-host checks from the main plan. Remove JSON-generating Node pack scripts only after Kotlin/DSL generation and freshness replacements execute. Withdraw /react/ publication and exclude its assets from the new bundle, but recognize that an already open old React tab can continue writing legacy keys. The new Kotlin store must distinguish a verified receipt awaiting cleanup from a cleanup-complete marker: before completion, a matching receipt permits only idempotent cleanup; after completion, any reappearing legacy key (even the same bytes) or unknown legacy application key enters RecoveryRequired before save/delete and preserves both old and new bytes. Browser tests must interleave old-tab write after new text commit, reload, failed cleanup and retry. No release claims zero residual JSON while an old writer can still write; if no enforceable old-writer quiescence or safe recovery policy is demonstrated, NJ06/NJ11 stay open.
5. **Delete the retired product stack in a reviewed slice.** Remove old React src, root TS/TSX tests and browser specs, Vite config/assets, obsolete Node generators/validators, root TypeScript configs, npm dependencies/manifests only when no remaining Kotlin Gradle JS/Wasm task, compiler CLI or CI step requires them, and /react/ copy/build/deploy logic. Before deleting any Node/npm file, record a Gradle task/dependency trace and clean CI run classifying its actual tool role; a required tool manifest may remain but cannot contain app facts. Remove or rewrite README, documentation and CI instructions that promise React or JSON export. Keep Kotlin, Apple SwiftUI host shells and independent accepted behavior controls. Build the site from Kotlin only. Scan tracked files and emitted bundles for first-party TS/TSX/React/Vite/old JSON writers, with every tool exception named by path and requiring tool.
6. **Prove cutover and measure maintenance.** On one immutable product/compiler pair run Kotlin unit, JS/Wasm browser, Desktop, Android, iOS Simulator and macOS checks, actual UI/browser and migration paths, full relevant compiler gates, clean CI build, freshness, no-JSON and no-old-stack scans. Selected/executed/skipped/failure counts and device scope are explicit. Run the same independent requirement-change probes against a good Kotlin helper control, amortized project construct/template and existing DSL. The final report separates authored and generated LOC, semantic edit sites, duplication, reviewer surfaces, defects, compile/startup/runtime, P23 headroom and the cost of retiring React. No React parity run is required after its oracle is retired; all accepted behavior must have Kotlin evidence.

## Exit gate and rollback

Cutover is **NOT RUN** until every active TS/React guarantee has an independently reviewed Kotlin/DSL replacement, the old UI and publication path are gone, and the final Kotlin product plus hosts pass the existing FP/NJ requirements. A red no-JSON inventory or stale generator blocks release. If a Kotlin replacement is missing, leave the old code only in the isolated migration branch/history and report the specific gap; do not publish a dual runtime and call the cutover complete. Remove the old published rollback only after the Kotlin build, storage recovery and old-tab policy pass; a rollback must use a safe Kotlin artifact with the text data contract, never restart a JSON writer.
