## Case notation

Each `CASE id` ends at `END`. `source` cites a requirement. `arms A B C` means the same typed expectation applies to all arms. A `tree` block is an ordered, indented tree: `map`, `list`, `string`, `i64`, `f64bits`, `bool`, `null`. A named child begins `key <quoted escaped text> =>`; a list item begins `item =>`. `string` and `key` quotes use only `\\`, `\"`, `\t`, `\n`, `\r`, `\uXXXX` (uppercase hex) and literal printable UTF-8. Escape pairs are interpreted as UTF-16 code units, so `\uD800` is a lone high surrogate. `absent <path>` asserts no child, distinct from null. `f64bits` is exactly 16 lowercase hexadecimal digits. `i64` is exact decimal, not a floating-point value. `order` lists decoded keys in required order, not implementation sort output.

`input` is a byte oracle. `utf8-lines` means the displayed following lines joined with LF and **one final LF**, with no indentation or escape processing. `utf8-lines-terminal-ht` is the same, except a terminal `<HT>` on a line denotes one final byte `09`; the marker is not part of the wire. `hex` is whitespace-separated exact bytes (`empty` means zero bytes); `utf8-literal` means exactly the quoted printable text with no LF. `NOT FROZEN` means there is no runnable byte oracle. `derive A <id> <edit>` denotes a negative mutation of an independently frozen A byte stream, including a digest recomputation only when stated. This is a fixture operation, not an encoder result. `expect` names the observable result. A SHA-256 digest in an A example is calculated from the independently typed prefix through its final LF. An arm's parser must reject a semantically defective stream even if its digest is recomputed correctly.

The A header's wire/schema version, tags and escape spelling are specified in `TextWireDesign.md`. Only **3 of 12** A tree cases have canonical bytes; the other 9 are **NOT FROZEN**. B's exact table fields, pinned printer behavior and C's exact length grammar remain unspecified, so **all 12 B/C tree bytes are NOT FROZEN**. A also lacks numeric depth/row/string/total-byte ceilings; N26 cannot have an exact byte or boundary oracle until those limits are fixed. N16's malformed A/B/C row bytes are also NOT FROZEN. Document schema field order/version and receipt syntax are not yet accepted, so domain and transaction cases record semantic states, not fabricated save bytes. The partial corpus is **not authorization to start codec implementation** or to call NJ05 frozen.

`corpus.sha256` hashes the four exact `.cases` byte streams. Under P15, a later expectation change needs its own documented reason and separate commit; a backend result cannot supply that reason. Neither the hash nor a linked case proves execution (P17).

These are corrections of the independent baseline against existing source and the accepted design, not changes to fit a candidate codec.
