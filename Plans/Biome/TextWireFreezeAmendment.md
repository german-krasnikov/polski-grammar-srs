## Common semantic contract and bounds

`WireTree` is an ordered map/list with string keys and string values as exact UTF-16 code units, signed i64, finite binary64 **bits**, boolean and null. Map keys are unique after decoding; absent is represented only by no child. Root is a map. Header kind is exactly `progress`, `vocabulary`, `preferences`, or `snapshot`; wire version is `1`; schema version is a shortest, positive decimal integer no greater than `2147483647`, carried opaquely by the generic codec. The P01–P11 test header uses kind `progress`, schema `2`; P12 uses `snapshot`, schema `1`. Neither implies an accepted document schema.

All arms have the **same decoded limits**, inclusive: at most `10,000,000` complete input bytes including digest and final LF; at most `100,000` value rows including root; at most `64` value nodes on any root-to-leaf path (root depth `1`); at most `1,000,000` UTF-8 bytes in the *canonical A escaped representation* of any one key or string value, excluding `K:` and row separators. The cross-arm string metric prevents C's hex representation or B's TOML escaping from changing semantic admission. Count it incrementally from UTF-16 units without building an unbounded string. At `limit + 1`, reject `Bound`; exactly at the limit, pass this limit and continue other validation. A document owner may impose a lower limit, notably the existing 1 MB preferences import and 10 MB progress/vocabulary imports; its check is separate. The input-byte check precedes UTF-8 decode or TOML library invocation; a streaming reader stops after byte `10,000,001`. A decoder must bound row accumulation and decoded units before library/object allocation. Thus B is ineligible if its library requires unbounded parse allocation under these ceilings.

All input is strict UTF-8, no BOM/CR and a final LF; A/C use TAB row separators, while B uses TOML 1.0 syntax. Compute SHA-256 over every byte before the terminal digest field, including the LF immediately before it. Digest is 64 lowercase hex digits. Reject noncanonical bytes by exact re-encode equality after structural validation and digest verification. An error label in the frozen corpus identifies the defect; the implementation may use its own internal diagnostic type if the public result maps to that label without accepting input. Check framing/bounds before digest when input is too large; for otherwise well-formed framed inputs, compare digest before trusting a tree. Invalid UTF-8 must be reported without replacement characters. Neither digest nor byte equality authenticates hostile rewrites.

Rows use preorder: root row ordinal `0`; each container's children occupy the following complete subtrees in source order. Container count is a nonnegative shortest decimal integer, at most remaining row budget. The root and list children have no named key; map children have exactly one key. No decoder sorts an existing map. When a *document owner* introduces previously absent extension fields, that owner orders only those new keys by unsigned UTF-16 units, shorter equal prefix first (P24).

## A: `POLSKI-TEXT` native static codec

The exact grammar and canonical printer are [TextWireDesign.md](TextWireDesign.md): header `POLSKI-TEXT<TAB>1<TAB>kind<TAB>schemaVersion<LF>`; preorder `M/L<TAB>key<TAB>count`, `S/I/D/B<TAB>key<TAB>payload`, and `N<TAB>key`, each ending LF; final `H<TAB>sha256<TAB>digest<LF>`. Use `-` only at root/list child and `K:` plus escaped UTF-16 text only at map child. `I` is shortest signed decimal i64; `D` is 16 lowercase hexadecimal digits with nonfinite exponent patterns rejected; `B` is `0` or `1`. Escaping is uniquely `\\`, `\t`, `\n`, `\r`, uppercase `\uXXXX` for other excluded controls and lone surrogates; a valid pair prints its scalar as literal UTF-8. This is a deliberately small native lexer/printer, not a DSL grammar or document validator. P01–P03 existing bytes anchor this arm; tester calculates the other nine independently.

## B: TOML 1.0 library-printer feasibility arm

The restricted *semantic* TOML layout is a top level `wire_version`, `kind`, `schema_version`, followed by one `[[record]]` table per preorder row and a terminal `[integrity]` table containing `sha256`. The version fields are TOML integers (`1` and the positive schema version); `kind` is a TOML string. Every row has `parent` (root `-1`, otherwise zero-based parent ordinal), `index` (zero-based child position; root `0`), `tag` (`M,L,S,I,D,B,N`), and exactly the tag-specific fields below. `M/L` have `count` as a bounded TOML integer. `I` has `integer` as a quoted shortest decimal string; `D` has `bits` as a quoted 16-digit lowercase string; `B` has `boolean` as a TOML boolean; `S` has `text` or `units`; `N` has neither. A named row has `key` or `key_units`; root/list rows have neither. `key_units`/`units` are arrays of decimal unsigned 16-bit code units, used **only** if the sequence contains an unpaired surrogate; ordinary sequences use TOML strings. Exactly one alternative is present. Empty string is `""`; empty unit array is forbidden. Arrays retain order. The validator rejects extra fields, duplicate fields/tables, inconsistent parent/index/count, TOML 1.1-only syntax, bare `null`, dates, floats, and parser coercion. The digest covers the exact bytes from `wire_version` through the LF after `[integrity]`; the next and last line is the library-printed `sha256 = "<digest>"` plus LF. Library parsing is followed by this strict profile validation.

The required canonical printer is the maintained library's own printer: `smol-toml` for TS and `ktoml-core` for KMP, with exact versions **to be pinned by the developer's dependency feasibility check before fixture freezing**. The wrapper prints once with a 64-zero digest placeholder, hashes the exact prefix ending at `[integrity]` LF, then asks the library to print the same model with the real digest. The final output must have exactly that prefix and digest line. It must print the above insertion order, LF, final LF and exact digest placement, and both libraries must emit byte-identical output for every P01–P12 tree. A native wrapper may assemble the ordered table model and check bytes, but may not post-format TOML, implement a TOML lexer/printer, or maintain a second output grammar. This is a conditional arm, **currently NO-GO for codec implementation**: neither version pin, required Android/Wasm/Native variants nor byte-identical library printer has been proved. If even one printer emits different bytes, TOML 1.1 syntax, or unsupported structure, record B NO-GO with the case and cost; do not fabricate B byte oracles or relax equality. [smol-toml](https://github.com/squirrelchat/smol-toml) currently advertises TOML 1.1, so the TOML 1.0 rejection profile must be tested explicitly; [ktoml](https://github.com/orchestr7/ktoml) advertises KMP but its exact target artifacts remain to be checked. No release is accepted from these pages alone.

## C: fixed code-unit rows, native static helper

C is a deliberately smaller, ASCII-only length-delimited comparison; it gives up human-readable string payloads but retains the same tree. Header is `POLSKI-UNITS<TAB>1<TAB>kind<TAB>schemaVersion<LF>`. Each preorder line has `tag<TAB>keyToken` followed by `TAB payload` for `M/L/S/I/D/B`; `N` has no payload. `keyToken` is `-` at root/list children, otherwise `K` followed by the code-unit token below. `M/L` payload is shortest unsigned decimal child count; `I/D/B` payload spelling and range are identical to A. `S` payload is a code-unit token. A code-unit token is `U` followed by shortest decimal code-unit count, `:`, then exactly that many groups of four **uppercase** hexadecimal digits with no separators; `U0:` is the empty string. For example key `-` is `KU1:002D`, empty key `KU0:`, string `A😀` is `U3:0041D83DDE00`, and a lone high surrogate is `U1:D800`. Reject lowercase hex, redundant count zeros, missing/excess units and raw Unicode in tokens. This length is in UTF-16 units, not UTF-8 bytes; common A escaped-byte and total C byte bounds still apply. Final line is the same `H<TAB>sha256<TAB>digest<LF>` as A. The canonical printer emits exactly these uppercase unit groups, no optional whitespace or normalization. It is a small native helper, not a general text parser or a document schema.
