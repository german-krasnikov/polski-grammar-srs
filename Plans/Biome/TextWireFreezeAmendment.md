## Common semantic contract and limit gate

`WireTree` is an ordered map/list with string keys and string values as exact UTF-16 code units, signed i64, finite binary64 **bits**, boolean and null. Map keys are unique after decoding; absent is represented only by no child. Root is a map. Header kind is exactly `progress`, `vocabulary`, `preferences`, or `snapshot`; wire version is `1`; schema version is a shortest, positive decimal integer no greater than `2147483647`, carried opaquely by the generic codec. The P01–P11 test header uses kind `progress`, schema `2`; P12 uses `snapshot`, schema `1`. Neither implies an accepted document schema.

The previously proposed generic caps of 10,000,000 wire bytes, 100,000 rows, depth 64 and 1,000,000 escaped bytes per string are **withdrawn**. They were not derived from accepted legacy behavior. The Android UI picker limits progress input to `10,000,000` bytes before repository import, while direct `AndroidProgressRepository.importJson` has no pre-write input cap and its `readUtf8Limited` gate applies on readback; iOS/macOS progress repository imports have a `10,000,000`-byte pre-write cap. Vocabulary imports on the named hosts accept up to `10,000,000` **legacy input bytes**; iOS/macOS preferences imports use `1,000,000` legacy bytes. See `AndroidSessionViewModel.kt:241-251`, `AndroidProgressRepository.kt:61-80,126-134`, `IosProgressRepository.kt:60`, `MacProgressRepository.kt:59,90`, `VocabularySession.kt:159-160` and `IosPreferencesSession.kt:158`, plus the source correction in [NJ05AndroidImportCorrection.md](NJ05AndroidImportCorrection.md). These limits belong to distinct legacy/document/host paths, not to the new generic wire. `ProgressCodec.source` retains unknown `JsonObject` values, so a valid old progress file under 10 MB can contain a single field over 1 MB or a much deeper/larger tree than the withdrawn generic caps. Host limits differ; the accepted envelope must be recorded per actual import path before a new document limit is chosen.

**Equal admission invariant:** for every representable tree obtained from a valid, accepted legacy document at an in-scope host, and every new tree admitted by its document owner, A, B and C must encode/decode that same tree with exact code units and order, or the failing arm is NO-GO. A one-time migration may return `RecoveryRequired` with the original bytes untouched for an unrepresentable legacy value or a separately accepted product requirement change; a codec-size expansion alone is not an authorized reason to discard, truncate, or newly reject a formerly accepted document. A valid legacy input's 10 MB limit is never reused as a 10 MB output limit: C prints four hex digits per UTF-16 unit, so an accepted 7.5 MB ASCII value can require roughly 30 MB of C payload. B can be larger still because each row is a TOML table. The generic wire must not promise equal tree admission by merely setting equal physical byte numbers.

Before accepting numeric ceilings, the independent tester freezes **valid accepted legacy controls** just below and exactly at each host's current byte limit, including a large unknown progress string, many unknown nested values/rows, a deeply nested unknown value actually accepted by the existing reader, multilingual/escaped UTF-16 text, large vocabulary text within its real domain rules, and preferences at its actual limit. Confirm the old decoder accepts each on the named host; distinguish host size rejection from document validation and from runtime stack failure. Convert them through a pure typed tree oracle and calculate each arm's canonical output size independently. Add boundary controls for each proposed semantic limit (depth/row/string) and each arm's physical byte limit. Only then choose **numeric** depth, row and string ceilings common to all arms and **arm-specific** physical byte ceilings with headroom that admit every accepted control. Freeze the exact-at-limit and limit-plus-one cases; at exactly the ceiling pass that limit and continue validation, at plus one return `Bound`. If a valid legacy control exceeds any proposed ceiling, raise it, reject that arm as NO-GO, or obtain an explicit owner-approved change to the migration requirement with recovery behavior. Until this gate, N26 numeric oracles and codec implementation remain **NOT FROZEN / NOT RUN**. This is a deliberate unresolved contract, not a claim that an arbitrary large number is safe.

Preflight each arm's own physical byte ceiling before UTF-8 decode or library parse; a streaming reader stops after its limit plus one byte. A/C count rows, depth and decoded string units incrementally before unbounded allocation. B needs a library-supported bounded parser or an independently reviewed bounded preflight that does not become a product TOML lexer; otherwise B is NO-GO. The chosen limits must have measured memory/step headroom on required hosts (P23). Document owners may enforce their own accepted limits at the domain boundary, but cannot silently narrow legacy admission during migration.

All input is strict UTF-8, no BOM/CR and a final LF; A/C use TAB row separators, while B uses TOML 1.0 syntax. Compute SHA-256 over every byte before the terminal digest field, including the LF immediately before it. Digest is 64 lowercase hex digits. Reject noncanonical bytes by exact re-encode equality after structural validation and digest verification. An error label in the frozen corpus identifies the defect; the implementation may use its own internal diagnostic type if the public result maps to that label without accepting input. Check framing/bounds before digest when input is too large; for otherwise well-formed framed inputs, compare digest before trusting a tree. Invalid UTF-8 must be reported without replacement characters. Neither digest nor byte equality authenticates hostile rewrites.

Rows use preorder: root row ordinal `0`; each container's children occupy the following complete subtrees in source order. Container count is a nonnegative shortest decimal integer, at most remaining row budget. The root and list children have no named key; map children have exactly one key. No decoder sorts an existing map. When a *document owner* introduces previously absent extension fields, that owner orders only those new keys by unsigned UTF-16 units, shorter equal prefix first (P24).

## A: `POLSKI-TEXT` native static codec

The exact grammar and canonical printer are [TextWireDesign.md](TextWireDesign.md): header `POLSKI-TEXT<TAB>1<TAB>kind<TAB>schemaVersion<LF>`; preorder `M/L<TAB>key<TAB>count`, `S/I/D/B<TAB>key<TAB>payload`, and `N<TAB>key`, each ending LF; final `H<TAB>sha256<TAB>digest<LF>`. Use `-` only at root/list child and `K:` plus escaped UTF-16 text only at map child. `I` is shortest signed decimal i64; `D` is 16 lowercase hexadecimal digits with nonfinite exponent patterns rejected; `B` is `0` or `1`. Escaping is uniquely `\\`, `\t`, `\n`, `\r`, uppercase `\uXXXX` for other excluded controls and lone surrogates; a valid pair prints its scalar as literal UTF-8. This is a deliberately small native lexer/printer, not a DSL grammar or document validator. P01–P03 existing bytes anchor this arm; tester calculates the other nine independently.

## B: TOML 1.0 library-printer feasibility arm

The restricted *semantic* TOML layout is a top level `wire_version`, `kind`, `schema_version`, followed by one `[[record]]` table per preorder row and a terminal `[integrity]` table containing `sha256`. The version fields are TOML integers (`1` and the positive schema version); `kind` is a TOML string. Every row has `parent` (root `-1`, otherwise zero-based parent ordinal), `index` (zero-based child position; root `0`), `tag` (`M,L,S,I,D,B,N`), and exactly the tag-specific fields below. `M/L` have `count` as a bounded TOML integer. `I` has `integer` as a quoted shortest decimal string; `D` has `bits` as a quoted 16-digit lowercase string; `B` has `boolean` as a TOML boolean; `S` has `text` or `units`; `N` has neither. A named row has `key` or `key_units`; root/list rows have neither. `key_units`/`units` are arrays of decimal unsigned 16-bit code units, used **only** if the sequence contains an unpaired surrogate; ordinary sequences use TOML strings. Exactly one alternative is present. Empty string is `""`; empty unit array is forbidden. Arrays retain order. The validator rejects extra fields, duplicate fields/tables, inconsistent parent/index/count, TOML 1.1-only syntax, bare `null`, dates, floats, and parser coercion. The digest covers the exact bytes from `wire_version` through the LF after `[integrity]`; the next and last line is the library-printed `sha256 = "<digest>"` plus LF. Library parsing is followed by this strict profile validation.

The required canonical printer is a maintained library's own printer. The isolated [feasibility probe](NJ05TomlPrinterFeasibility.md) pinned `smol-toml@1.9.1` and `ktoml-core@0.7.1`; that pair is **NO-GO** because all seven desktop exact-byte comparisons failed, while Android/Wasm/Native execution was not attempted. The wrapper proposed for any future pair prints once with a 64-zero digest placeholder, hashes the exact prefix ending at `[integrity]` LF, then asks the libraries to print the same model with the real digest. The final output must have exactly that prefix and digest line. It must print the above insertion order, LF, final LF and exact digest placement, and both libraries must emit byte-identical output for every P01–P12 tree. A native wrapper may assemble the ordered table model and check bytes, but may not post-format TOML, implement a TOML lexer/printer, or maintain a second output grammar. If a separately reviewed new pair differs in bytes, emits TOML 1.1 syntax, or cannot support every required target, keep B NO-GO; do not fabricate B byte oracles or relax equality. The TOML 1.0 rejection profile still needs explicit negative tests if B ever reopens. No release is accepted from these pages alone.

## C: fixed code-unit rows, native static helper

C is a deliberately smaller, ASCII-only length-delimited comparison; it gives up human-readable string payloads but retains the same tree. Header is `POLSKI-UNITS<TAB>1<TAB>kind<TAB>schemaVersion<LF>`. Each preorder line has `tag<TAB>keyToken` followed by `TAB payload` for `M/L/S/I/D/B`; `N` has no payload. `keyToken` is `-` at root/list children, otherwise `K` followed by the code-unit token below. `M/L` payload is shortest unsigned decimal child count; `I/D/B` payload spelling and range are identical to A. `S` payload is a code-unit token. A code-unit token is `U` followed by shortest decimal code-unit count, `:`, then exactly that many groups of four **uppercase** hexadecimal digits with no separators; `U0:` is the empty string. For example key `-` is `KU1:002D`, empty key `KU0:`, string `A😀` is `U3:0041D83DDE00`, and a lone high surrogate is `U1:D800`. Reject lowercase hex, redundant count zeros, missing/excess units and raw Unicode in tokens. This length is in UTF-16 units, not UTF-8 bytes; C's physical byte ceiling is chosen independently after the equal-admission controls. Final line is the same `H<TAB>sha256<TAB>digest<LF>` as A. The canonical printer emits exactly these uppercase unit groups, no optional whitespace or normalization. It is a small native helper, not a general text parser or a document schema.
