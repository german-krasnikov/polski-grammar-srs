## Independent requirements and ownership

The preimplementation oracle is [NJ03CurriculumIndependent.cases](NJ03CurriculumIndependent.cases) and its [provenance/rejection ledger](NJ03CurriculumIndependent.md): 16 English and 16 Polish ordered records, all seven required fields, nested field/list order, explicit null, present empty record/list, and all prerequisite edges. The exact old input hashes are `courses/lang/en/curriculum.json` = `4c8f1c21595479a1b49ebb38a6fa4df9fff15f02bbe6d6cdd2b8ed4ecaf0afe6` and `courses/lang/pl/curriculum.json` = `4f98cb4e0a5bc5b5f21890120fe25e077cedc2ba5e65852bff4b1e252b4234b7`. The old files are read-only historical controls and must not feed the accepted generator. The separate [Polish noun/seed/chain corpus](NJ03SeedsNounsChains.md) freezes 14 nouns, 12 seeds, five steps and 60 sentence pairs; it is a later consumer requirement, not proof supplied by 32 compiled skill values.

One Biome source per language, proposed `courses/lang/{en,pl}/curriculum.core-data`, owns the 32 ordered skill facts. Reuse the project `SKILL` declaration, typed Core record reader and Kotlin text printer already exercised by the NJ02 E1–E3 experiment; use one shared type/definition contract where both languages have the same shape. `courses/lang/en/curriculum.core-data` currently holds **three experimental English rows**, not all 16 and not an active course. Replace those rows in the independent 16-row order and add Polish 16 in a separate source; do not append a second authority or treat the E1–E3 generator as a live pack. The current `curriculum-types.program` only permits `Tense/Person/Number` fixed keys and `nounId` filters. Extend its type declaration for every **observed** fixed feature key and both observed lexical `where` keys (`gender`, `nounId`); preserve `Person` values such as `"1"` as text. Resolve `focus`/`fixed` feature keys and values against the generated core registry plus the language's `usesFeatures`. Resolve lexical `where` keys by the lexical-filter contract and their `gender`/`nounId` values against the language lexicon. `CoreCatalog` does not perform lexical resolution. Do not add a generic stringly feature map or silently drop a key.

The compiler Kit/Core layer reads typed record/list/null syntax, checks types and carries source locations. A narrow build-only **project** validator owns unique skill ID, required field presence, focus no-op, prerequisite resolution/cycle, construction/feature/value/`usesFeatures` and filter noun/gender references. [NJ03NewSemanticRules.md](NJ03NewSemanticRules.md) fixes the separate N02 filterable-slot and N03 focus/fixed-axis requirements before their candidate mutations are frozen. The validator returns decisions and source diagnostics; it does not mutate training state, add product names to compiler Core, or perform a second token walk. Once typed language declarations and noun catalogs exist, use those Biome facts for relation checks. An isolated interim experiment may read old language/lexicon bytes only as explicitly labelled transitional inputs and cannot be accepted as the final no-JSON build. The Kotlin printer lowers one validated typed IR to immutable `List<SkillSpec>` values; Kotlin target spelling and escaping are printer-owned, not semantic decisions.

The live seam is `kotlin/shared/build.gradle.kts::generateCoursePackSource`, `kotlin/shared/src/commonMain/kotlin/polski/training/Curriculum.kt::parseCurriculum/plCurriculum`, and `kotlin/shared/src/commonMain/kotlin/polski/core/PlEngine.kt::PackEngine.skills`. Keep existing `SkillSpec`/`FeatureFocus`/`LexicalFilter` call sites and generator behavior. A candidate generated file under `kotlin/shared/build/generated/biome/kotlin/polski/data/GeneratedCurricula.kt` and a readable text manifest are proposed outputs; exact paths must be locked in the developer blueprint before RED. No application JSON output, embedded JSON string, second Kotlin fact table, TS product module, or JSON-shaped cell is permitted. Swift remains a thin host shell.

## Stop and cost gates

Stop the production switch if an authored skill exists in two maintained tables; a printer invents a semantic default; `focus=null`, `fixed={}` or `prerequisites=[]` collapses; a `Person` text value becomes numeric; a diagnostic points only at the file/declaration instead of the offending leaf; a stale input/output passes; English or Polish `PackEngine` still reads embedded curriculum JSON; or a Kotlin test merely compiles without executing. R7 `usesFeatures` cannot be called complete while its language declaration remains active JSON. The current 14-fact NJ02 `CoreCatalog` is a small pure Kotlin helper and is not itself shared-variable Logic or PlayTest proof.

Measure the actual reader → validator → Kotlin printer → Kotlin consumer pipeline at N=10/100/1000 with fixed limits and at least 2× headroom in both time and logical steps at N=1000, separating compile, startup and runtime. Compare the same 32-skill and one marginal rule/content change against a good typed Kotlin/text helper with equal checks; count authored/generated lines separately, independent semantic edit sites, review surfaces and defects. Static token counts are not LLM usage. A shared DSL path advances only when it removes a duplicate authority or adds an executed guarantee at acceptable cost; a small static native helper remains the correct owner where it wins that comparison. Full compiler `gate:all`, final fast gate, clean fetchable compiler pin, all Kotlin host gates, no-JSON inventory and the application-wide maintenance report remain separate later acceptance work.
