## Decision and ownership

Use a **typed retained numeric lexeme** in the candidate generic ordered tree, instead of coercing an unknown old number to `Long`, `Double` or `String`. This is a provisional, additive **wire value/tag**, not new Biome DSL syntax and not a selected app format. The E2 sealed old progress input contains five distinct unknown numeric tokens: `9223372036854775808`, `1e10000`, `1.0`, `1e0` and `-0`. Its reader exposes each as an ordered non-string `JsonPrimitive` with the original `.content` on Desktop JVM, macOS Native and iOS Simulator. The wide integer exceeds i64 and loses precision as binary64; `1e10000` exceeds finite binary64; the last three need distinct spellings. Replacing the unknown value with a string or binary64 would fail the frozen [legacy-representability.cases](../../tests/fixtures/textwire/legacy-representability.cases). The old 683-byte [input](../../tests/fixtures/textwire/inputs/legacy-representability-progress.input) and its path/hash seal stay unchanged and input-only.

The proposed **NEW, test-only** tree variant is `RetainedNumber(token: String)`. It is disjoint from `I` (signed i64), `D` (finite binary64 bits) and `S` (user string). The token is the exact ASCII sequence accepted from an old *number* node; no numeric conversion, exponent expansion, trimming, case folding or negative-zero normalization occurs. A single-pass native validator accepts only `-?(0|[1-9][0-9]*)(\.[0-9]+)?([eE][+-]?[0-9]+)?` over ASCII bytes, with the whole nonempty token consumed. In particular `1e10000`, `1E+00000`, `1.0`, `1e0`, `-0` are distinct typed values; `+1`, `01`, `.5`, `1.`, `NaN`, `Infinity`, whitespace, a sign alone and non-ASCII digits are invalid. The regex describes the contract; an implementation must scan linearly with bounded allocation, not use a potentially expensive backtracking matcher on an untrusted large token. The token grammar is a numeric scalar grammar, **never a serialized JSON document**. It cannot carry a map, list, quoted string or arbitrary old-byte blob.

For the A/C feasibility probes only, reserve row tag `R` for this variant: `R<TAB>key<TAB>token<LF>` with A's escaped `K:` key or sentinel and C's `KU…` key or sentinel. The payload is ASCII as above, not an A escaped string or C `U…` code-unit token. The existing header, ordering, digest, LF and key-position rules are unchanged. A/C decoding returns `RetainedNumber` and re-encoding must reproduce the exact token; a malformed token rejects **before** domain admission and cannot be interpreted as `S`, `I` or `D`. The positive P01–P12 and negative N01–N16 frozen bytes remain unchanged. The new tag and its byte literals require an **independent reviewed requirement freeze before prototype code**. This tag is a candidate wire extension; do not add it to `commonMain` or modify existing corpus/hash files in the E3 experiment. If a simpler equal-guarantee representation is demonstrated, return to architecture review before changing the independent expectation.

Only the progress **legacy migration projection** may initially construct `RetainedNumber`: walk the ordered `ProgressDocument.source` and identify unknown-field numeric nodes. Known progress/FSRS counters and dates still pass their existing typed validation and document-owner mapping; the owner must explicitly decide whether any known raw spelling is a retained requirement before normalizing it. A document validator must reject `R` in known typed fields and in new user input positions where it has no declared extension meaning. New saves cannot call `ProgressCodec.encodeLegacyV1` or carry `JsonObject` through a normal runtime API. The migration adapter may read the old parser only on the one-time path. Existing `ProgressCodec.decode` and its source tree are sufficient for a **test-only** E3 projection probe, but they do not prove that all valid legacy inputs are lossless: duplicate object keys may have collapsed, and browser/Android/JS/Wasm behavior has not been established. Those cases require a later reviewed read-only preflight or `RecoveryRequired`, never a guessed reconstruction.

Unknown vocabulary `padding` is currently discarded by `VocabularyCodec.decode`; E2 grants it **no implicit preservation contract**. Preferences rejects unknown fields. Their document owners must make separate decisions before a universal extension model is claimed. The retained-number helper is reusable if those owners actually need it, but this single observed progress use does not justify a new Core dialect or project template.

## E3 handoff in order

1. **Freeze independent requirements first.** A tester, in a separate requirement commit, copies no generated output and leaves E2's exact input/hash and `positive.cases`, `negative.cases`, `document.cases`, `transaction.cases`, `corpus.sha256` and `legacy-representability.sha256` untouched. Add **NEW** `tests/fixtures/textwire/retained-number.cases` plus an exact-path SHA-256 ledger and a checker that seals both the new cases and the referenced E2 input. The `.cases` file states ordered typed trees, all five E2 token/code-unit values and their paths; hand-authored A/C literal bytes and SHA-256 of the covered prefix for a small root-map example; then negative mutations with recomputed digest. Derive expected bytes independently from the written row grammar, not from a Kotlin encoder. An illustrative row `R<TAB>K:wide<TAB>9223372036854775808` is **not** an oracle until its entire document and digest are frozen. Keep expected values in text/typed Biome-style records where an existing reader accepts them; do not introduce an output JSON fixture or unproved DSL syntax. A duplicate-key old-user negative, if added, gets its own exact-path, SHA-256-sealed **input-only** file before execution; it is a later losslessness STOP, not a new application format.
2. **Freeze positive and negative distinctions.** At minimum prove five E2 tokens remain ordered and non-string through old reader → typed projection → A/C encode/decode → typed projection, including `-0` versus `I 0` and `D 8000000000000000`, and `1.0` versus `1e0`. Test ordinary `I`, `D`, `S` and null in the same tree so `R` cannot alias them. Negative rows include `+1`, `01`, `.5`, `1.`, `1e`, `--1`, `NaN`, `Infinity`, non-ASCII digit, embedded TAB/LF, oversized token under a proposed N26 limit, a valid `R` in a known typed field, wrong map/list key position, bad digest, and old parser data with indistinguishable duplicate object keys. Every negative names the expected error or `RecoveryRequired`, the earliest observable boundary, and unchanged old bytes. A token above a **not yet selected** limit remains a pending N26 case, not an invented failing threshold.
3. **Measure independent sizes before a prototype.** Extend **test-only** `tests/fixtures/textwire/check_numeric_sizes.py` or add a same-owner `check_retained_number_sizes.py`: count A/C header, each preorder row, key escaping/code-unit expansion, exact token ASCII bytes, digest and final LF from the authored tree without invoking a codec. For retained numbers the payload contribution is the token's ASCII byte count in both arms; do not expand `1e10000` mathematically. Compute output, retained old input, new document, readback copy, prior-text backup and temporary/receipt bytes **separately**. Preserve the already established A/C lower floors for accepted 10 MB progress examples; adding this variant does not authorize a 10 MB output ceiling. Include large accepted old controls and each required host's actual quota when available. If a host cannot allocate/persist with ≥2× P23 headroom, that arm is NO-GO or needs a reviewed representation change.
4. **Developer then writes only isolated probes.** Proposed **NEW** `kotlin/shared/src/commonTest/kotlin/polski/textwire/RetainedNumberPrototypeTest.kt` and private test-support classes under `commonTest/polski/textwire/`. They may call `ProgressCodec.decode` read-only, traverse the source tree, validate `RetainedNumber`, and implement minimal A/C row encode/decode **in test source only**. They may not call any old JSON writer/import/save/export/backup, write a new app document or production `commonMain` codec, create a JSON output, or mutate frozen fixtures. A test-only Kotlin helper is a mechanical printer/parser; no business acceptance decision lives there. Compare output to the independent exact bytes/hash and tree, including reject cases. The generic prototype does not select a format, freeze N26 or count as NJ05 migration GREEN.
5. **Target isolation and review.** Start with `:shared:desktopTest` exact named class; inspect XML selected/executed/skipped/failures. Repeat isolated `:shared:macosArm64Test` and `:shared:iosSimulatorArm64Test` only for the named class, one Gradle target at a time. JS/Wasm cannot use the earlier `--tests` assumption: a filtered JS run selected 64 classes/393 tests including prohibited old writer/import paths. First demonstrate a task/source isolation whose XML and build graph select only the new read-only probe, then run JS and Wasm separately. Android needs a focused read-only device path and nonempty device XML; Robolectric/compile is not device proof. For each target record exact source SHA, command/cwd, selected/executed/skipped, input SHA before/after, output bytes/hash produced **only in test memory**, and PASS/FAIL/NOT RUN. An independent tester reruns the frozen oracle and deliberate corruption controls, then a read-only reviewer checks P4/P7/P8/P11/P15/P17/P23/P24. No target is inferred green from another target's result.

## Choice against DSL and recovery boundary

| Option | Equal-guarantee scope and present decision |
| --- | --- |
| Existing Biome record/data and contract | Good place to author document shape, extension policy and independent examples once the actual Biome reader and Kotlin test consumer prove the typed values. Existing `.given PORTS FROM .contract`, contract `FACT`/`QUERY` and plan `LET`/`$name` can share fact bindings and setup for a later Logic/EditMode rule; keep expectations in `.examples/.sources`. Kotlin PlayTest printer and application JSON-free Logic output are not yet proved. These facilities do not replace a byte lexer, UTF-16 preservation, hash or atomic storage. No new syntax in E3. |
| One project CONSTRUCT/PATTERN/TEMPLATE | Revisit if repeated **semantic** document declarations need the same typed extension rule across progress, vocabulary and preferences and the generated Kotlin/test path measurably removes independent edit sites. No such repetition or compiler/runtime proof yet; a template for one numeric parser adds review cost. |
| Small static Kotlin helper | Provisional P8 choice for the one observed mechanical number token: one pure validator/value type, reused by A/C candidate printers and later migration adapter if selected. Measure implementation + generated lines, semantic edit sites, target behavior, startup, runtime and reviewer locations against the DSL options on the same frozen cases. Kotlin-specific physical code may remain native under P4, with document permission/merge rules outside it. |

If the read-only projection cannot distinguish number from string, preserve the five exact lexemes, retain order or UTF-16 code units on a required target, or if duplicate/unsupported old data cannot be represented, return `RecoveryRequired` **before any new write** and leave every old byte/key/file unchanged. That is a per-document outcome, not license to silently skip an accepted example or declare full migration done. A future successful one-time migration uses a distinct text key/path, byte-and-model readback, durable text receipt, then verified old-key/backup deletion; any write/readback/receipt/delete failure leaves an incomplete or recovery state and old bytes intact. Valid new text plus old bytes without a matching receipt is recovery before writes; a matching receipt permits only verified cleanup. Browser cross-tab and old-version-tab exclusion, Android device import semantics and Apple host snapshots remain separate NJ06/NJ08 gates. This E3 probe performs **none** of those transactions.

## Stop and acceptance for this slice

E3 can be reported as a bounded feasibility result only after a separately reviewed frozen oracle, exact A/C byte and typed-tree equality, all actual selected target counts, independent size arithmetic and a P8 comparison with the native helper. It cannot pass if expected bytes come from the prototype, if `R` is treated as a string or rounded number, if frozen P01–P12/N16 bytes change, if an old writer runs, if a required host silently normalizes a surrogate/number, or if a missing host result is called PASS. Return to architecture for any legacy semantic change or corpus contradiction. N26 ceilings, E4/P23 full measurements, production codec, document schemas, transaction protocol and the final zero-JSON scan remain open.
