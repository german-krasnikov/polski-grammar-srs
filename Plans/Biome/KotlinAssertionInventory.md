## What is actually counted

`vitest list --no-color --maxWorkers=2` collected **268 test cases in 41 files** without executing their bodies. [Family index](KotlinVitestFamilies.md) links to case ledgers [1](KotlinVitestCases1.md), [2](KotlinVitestCases2.md), [3](KotlinVitestCases3.md). Every case row gives old path, complete-file SHA-256, collected title/old assertion claim, count and source line of direct `expect(...)` syntax, a related Kotlin class if one exists, and a planned lane. Related classes are search leads, **not** one-to-one replacements: 242 cases have a plausible class and 26 have none; **all 268 remain NOT MAPPED** at assertion level. There are **zero** product `.examples`, `.sources`, `.logic` or `.contract` files at this baseline. The existing `.cases` controls are focused NJ/text-wire freeze inputs, not a migration of these 268 independent expectations.

The 268 case count is not an assertion count. An AST scan of test callbacks found **593 direct `expect(...)` call sites counted per expanded case**, including **118 cases with at least two direct sites**; the maximum is 16. Those 118 cases are individually identified by `Direct expect` ≥2 in the ledgers. Examples include the six distinct malformed verb-teaching rejections in `tests/course-validation.test.ts:78`, the six pronoun copy/form comparisons in `tests/course-reference-pronouns.test.ts:24`, and five frequency-coverage/UI checks in `tests/vocabulary-view.test.tsx:25`. Loops can execute one call site repeatedly, helpers can assert indirectly, and a single object comparison can contain several semantic expectations; therefore **593 is only a static decomposition signal, neither a lower nor an upper bound on executed assertions or the final replacement target**. Do not close a row from a class-name resemblance or one passing smoke.

The old test source itself holds many expected values, but no per-case independently authored DSL expectation and SHA has been reviewed here. Each collected title is a historical claim needing acceptance triage. In particular, JSON shape/output and React-specific rendering assertions cannot be copied verbatim into the Kotlin-only, text-wire product; preserve the accepted semantic behavior and record the intentional requirement change separately. Expected values must not be generated from the Kotlin/DSL backend being checked.

## Ordered implementation slices

1. **Freeze independent expected cases and split compound assertions.** Start with `course-validation.test.ts` (43 cases, 10 with ≥2 direct `expect` sites), `pack-v2.test.ts` (22) and the course/reference families. Move schema/fact/reference rejections to Biome/Gradle with one typed fact source and an explicit negative test. First prove one shared fact used by Logic and a real test executor; reject a missing/wrongly typed fact and stale binding. Preserve old source SHA and expectation provenance without importing JSON into the new application.
2. **Port pure decisions, not source-language mechanics.** Grammar, sentence, morphology, scheduling/parity, review and vocabulary behavior become independent DSL expectations plus Kotlin common tests; use the related-class paths only after comparing every input and expected result. Keep one-time old-user JSON bytes as exact-path/hash input-only controls, with no JSON output. Run Desktop, JS, Wasm and required Native targets with selected/executed counts.
3. **Replace UI/effect evidence with Kotlin-authored browser and host tests.** Prove the pinned Kotlin/JVM driver in three browsers, then port each accepted React and Kotlin-TS Playwright assertion, including storage failure/retry, old-tab write, keyboard/focus and responsive cases. Run JS/Wasm browsers and Android/Apple/Desktop hosts separately. Do not retire React/TS tests from the active branch until independent assertion review and actual execution pass.
4. **Retire validator and build dependencies after graph proof.** The Node course/pack/inventory scripts still own checks and some Gradle inputs. Replace each domain guarantee and generated-output freshness, trace the Gradle/CI task graph, then remove React/TS/Node app code and `/react/` deploy. Keep small native tooling such as the Python no-JSON path guard if it remains the measured simpler equivalent and stays outside the app. Run the final no-JSON and Kotlin-only scan on emitted bundles as well as tracked source.

## Reproduction and limits

The list commands used an untracked symlink from the isolated worktree to the canonical checkout's `node_modules`; the symlink is removed before commit. `vitest list` and three `playwright test --list` calls exited 0. The Kotlin and perf list commands set `KOTLIN_SPIKE_DIST` to an existing canonical Kotlin JS build directory and `KOTLIN_SPIKE_BRANCH=js` only to satisfy config loading; no web server or browser was started. The source SHA values were computed from bytes in the isolated checkout. A TypeScript AST read-only scan counted direct `expect` call syntax and source line in each test callback; no expectation was edited. Product tests, Gradle, browsers, validators, generated freshness and full gates were **NOT RUN** for this inventory. Historical green results in other receipts do not change these replacement counts.
