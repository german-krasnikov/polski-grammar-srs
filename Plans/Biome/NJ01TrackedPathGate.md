# NJ01 exact-path JSON scan

Status: **intentional RED at product `729bfb4`; NJ01/NJ08 NOT PASS**. This small native utility is the tracked/untracked path check in the [no-JSON plan](NoJsonFullPortPlan.md). It uses Git's path list and an exact ten-path tool allowlist. The two existing `react-progress-v1.json` resources are still candidate test-only exceptions, so they fail this gate until their full byte hashes, decoder-only use and shipped-bundle exclusion are independently accepted. No broad directory or filename exception exists. A future accepted legacy-user input needs its own exact path and reviewed SHA; this script's path allowance alone cannot verify its contents.

Run `python3 scripts/check-no-app-json-tracked.py` from any working directory for the violating paths and nonzero status. `--summary` prints counts. At this branch, `--summary` reported **111** JSON paths, **10** approved tool paths, **0** accepted legacy-input paths and **101** violations (exit 1). This is the expected failing baseline while migration is incomplete, not a reason to weaken the check. The script is not wired into current `npm test`/build; add it to the final release gate once the remaining app paths are removed or valid test-only inputs are frozen.

This scan does **not** inspect mandatory tool-file contents, ignored Gradle/npm output, JSON embedded in generated Kotlin strings, JS bundles, downloaded files, localStorage, app-private storage or JSON calls in source. It cannot alone prove the owner's zero-application-JSON requirement. Those require separate content, build, package and live-host checks in NJ01/NJ08. The native helper is smaller than a DSL declaration for this one filesystem/Git check and does not duplicate product facts (P8/P10).
