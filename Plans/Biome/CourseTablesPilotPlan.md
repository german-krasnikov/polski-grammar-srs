## Product contract and chosen file

The proposed integrated change moves `courses/lang/en/curriculum.json` (146 lines; current SHA-256 `4c8f1c21595479a1b49ebb38a6fa4df9fff15f02bbe6d6cdd2b8ed4ecaf0afe6`) from human-authored JSON to **NEW** `courses/lang/en/curriculum.tables` as its *single* human-authored source. The isolated experiment may try that arrangement within its worktree; the full-port branch continues to treat the original JSON as authoritative until the integration gate passes. Keep the JSON at precisely the same path as a tracked generated artifact if integrated. It contains an ordered root array of exactly 16 English `SkillSpec` objects, each with `id`, `construction`, explicit `focus` (`null` in four rows), `fixed` (including the final empty object), explicit `lexicalFilter` (`null` in fourteen rows), `level`, and ordered `prerequisites`. Two filters carry nested noun ID lists. IDs, field presence, value types, array order, Unicode and existing key order must be preserved; an omitted cell is not a substitute for explicit `null`. The English rows happen to contain no non-ASCII strings now, but the pilot's authoring/generator control must preserve Unicode in a synthetic row and must not normalize or locale-sort text.

This is the smallest substantive live source: a trivial `prepositions.json` proves syntax but not ordered skills, nulls, nested filters or multiple consumers. `courses/lang/pl/curriculum.json` remains authored JSON in this experiment. The existing `courses/pl-ru/course.json` remains the v1 source; its derived `courses/lang/pl/lexicon.json` and `courses/pairs/pl-ru/pair.json` remain under `scripts/migrate-v1-to-v2.mjs --check`. Do not convert forms, recipes, copy, schemas, imported frequency data or the large inventory audit as part of this slice. Moving data alone cannot satisfy the full-port goal of DSL-authored domain rules (P4/P10).

Current real consumers stay on JSON. `kotlin/shared/build.gradle.kts::generateCoursePackSource` scans `courses/lang/*/curriculum.json` and emits `generatedCurriculumJsonByLang`; `kotlin/shared/src/commonMain/kotlin/polski/training/Curriculum.kt::parseCurriculum` maps that JSON to `SkillSpec`; `kotlin/shared/src/commonMain/kotlin/polski/core/PlEngine.kt::PackEngine` feeds those skills to `ExerciseGenerator.generateForSkill`; Kotlin en-ru hosts and shared tests exercise that path. `scripts/validate-curriculum.mjs::validateCurriculum` checks schema, duplicate IDs, prerequisite references/cycles and no-op focus; `scripts/validate-pack-v2.mjs::validatePackV2` checks construction/feature/filter references against core, English language features and lexicon. `tests/pack-v2.test.ts` already freezes the 16 ID order and negative reference behavior; `kotlin/shared/src/commonTest/kotlin/polski/core/EnExerciseGeneratorTest.kt` executes all 16 skills; `EnRealizationTest.kt`, `EnEmphasisContractTest.kt`, `tests/lifehacks-en-ru.test.ts` and the browser English course specs exercise downstream content. The existing parser at `biome-dsl/implementations/typescript/packages/biome/src/support/dsl-tables.mjs` supports `ROWS`, `TABLE`, `SET`, `MATRIX`, nested values and diagnostics. `biome generate --authored` emits `JSON.stringify(parsed, null, 2)` with a trailing newline and `--check` compares freshness (`packages/biome/src/commands/check.mjs`). The direct `--authored` path bypasses a `biome.project` pin, which is why the project step above is needed. `biome generate --check` with only a pin and no `GENERATE` step is expressly invalid. This route uses existing syntax and JSON interchange. `DECLARE` is a JS-only surface/grammar reader, and `TEMPLATE` has no proven schema-aware nested curriculum model; do not build a custom course language for this pilot. The `ROWS` seven-column line should be measured for clarity against the original 16 JSON objects, including long nested filter cells.

## Stop and rollback

Stop the isolated experiment if the project step cannot enforce its pin, `.tables` requires a giant nested JSON-like cell or new syntax/parser, no net reduction in independent edit sites/defects survives the native comparison, generated JSON changes semantics or loses order/null/string type, a stale file or broken reference escapes checks, or a required local consumer fails. Even after local success, stop before product integration if the compiler is not fetchable in clean CI or its freshness/host checks fail. Leave the repaired inventory and full-port branch untouched throughout the experiment. Do not weaken existing validation, change an independent expectation, hand-patch generated JSON, or classify a NOT RUN host as passing. Report a bounded NO-GO like [review-credit](ReviewCreditExperiment.md) if the native JSON control wins.

For a rejected local candidate, retain the result report and discard the isolated worktree; the full-port branch's authored JSON stays untouched. If an integrated candidate later needs rollback, remove the new `.tables`/project step/adapter/CI wiring for this source and restore the frozen original `curriculum.json` from the pinned product revision; retain accepted tests that expose real regressions. Do not roll back the committed `courses/pl-ru/*inventory*.json` repair. The same JSON path and unchanged Kotlin loader and TypeScript importers make rollback safe; verify its hash and focused validators/tests on the rollback revision. Merge, deploy, React removal and full-app completion remain separate decisions.
