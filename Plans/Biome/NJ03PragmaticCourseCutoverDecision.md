# NJ03 decision: one typed course bundle, one Kotlin printer

Status: **plan amendment, not implementation or live proof**. Product baseline `biome/full-port-2026@14cdc6065267f5cfaa5feaff63e1b048d5ebcdf1`. This narrows the execution shape of [NJ03LiveCourseCutoverBlueprint.md](NJ03LiveCourseCutoverBlueprint.md); its independent requirements, pair-lifetime hazard, no-JSON acceptance and host gates still apply. Follow [NoJsonFullPortPlan.md](NoJsonFullPortPlan.md) and `AI/ProjectMigratioPrincipals.md` (P7/P8/P11/P14/P15/P17/P23).

## Decision and cost boundary

Use **one authored Biome course-data root** (proposed `courses/course.core-data`, with companion type/construct contracts only), one validated located course IR, **one project Kotlin printer**, one text freshness manifest and one Gradle generation/check task. The root owns both `pl-ru` and `en-ru` packs and their shared language/core facts. Keep physical shards only if the existing project reader supports them without a second fact authority and a measured edit/review benefit warrants them. Do not make a new DSL construct or generator for each noun, skill-copy, adjective, recipe, form or pair family merely to organize files. Use semantic templates only for actual repeated *meaning*; use static Kotlin/build utilities for deterministic indexing, escaping and form materialization. The printer lowers the validated IR, makes no language-policy decisions, emits no JSON and never reads historical inputs. Cross-record checks (IDs/kinds, references, order, prerequisite cycles, form keys, pair/language coherence) belong to one product build validator over the located IR, using Core's reader/type/span APIs; no product Biome parser.

The current blueprint proposes `SKILL`, `SKILL_COPY`, registry/profile/noun/etc. producers with separate generated Kotlin files, output directories, manifests and checks before a large activation. Today the live path already has two Gradle JSON embedders (`kotlin/shared/build.gradle.kts::generateCoursePackSource/generateFormsFixtureSource`), `CoursePack`'s `JsonObject` projection and `CoursePackLoader.fromV2Layers`'s parse/merge/serialize. The lean path has **one recurring authoring edit site per fact, one reader/validator/printer command, one Gradle generated-source dependency and one freshness check**; the historical JSON-to-Biome transcription is a one-time tool, not another build stage. Count actual edit sites and build/compile/startup/runtime costs before claiming P8 improvement.

**Scope the bytes by consumer, not extension.** At this baseline `course.json` is 145,063 bytes, pair files are 103,529/86,219, editorial files 224,109/225,906, and generated form tables 242,240/44,644. The much larger `source-inventory.json` (872,884), `inventory-decisions.json` (3,044,430) and `inventory-coverage.json` (4,345,581) are **audit machinery**, not a giant course catalog: `scripts/inventory-course.mjs` scans source literals into the first, and `scripts/check-course-inventory.mjs` joins human classifications into the last. No Kotlin course consumer reads them. Preserve the decisions' independent review value in a readable text ledger only if still needed for remaining literal migration; regenerate a text report or retire the other two with their checks when their job ends. Do not copy these three into `course.core-data`, count them as semantic authoring bytes, or keep active app JSON merely to maintain a historical report. Measure authored/live facts, derived forms, editorial content and audit artifacts separately.

Prefer a small immutable Kotlin `CourseValue` (`Record`/`List`/`Text`/`Number`/`Boolean`/`Null`, with ordered members and explicit absent versus null) emitted as constructors by the printer. Replace `CourseData.kt`'s `JsonObject` access helpers mechanically and retain its current domain projections/API, rather than making a separate printer constructor for every `Noun`, `Skill`, presentation, style and reference type. This is **typed IR lowered to Kotlin values**, not renamed JSON: no JSON text, JSON parser, `JsonElement`, or `toString()` reassembly may survive on the course path. The build validator must prove the shapes before emission; direct domain-constructor emission is preferable only if a measured small slice is actually simpler and preserves the same spans, order and validation. Keep `SkillSpec`, `TableMorphology`, `ExerciseGenerator`, `PackRegistry` and host-facing wrappers as their current owners.

## Smallest executable sequence

1. **Freeze, then transcribe once.** Freeze exact current source hashes and independent consumer outputs before editing. Read the old JSON **only** in an isolated one-time converter and comparison harness; emit Biome record/list syntax, never a new JSON document. Polish `course.json` is the v1 authority and `lang/pl/lexicon.json`/`pairs/pl-ru/pair.json` are derived projections; English `lang/en/lexicon.json` plus `pairs/en-ru/pair.json` are authored. `lang/{pl,en}/curriculum.json` overlaps each pack's skill IDs/level/prerequisites: join into one typed skill record, reject disagreements and do not transcribe two editable copies. Bring core registry, language profile, recipes/realization, prepositions, style, lifehack, frequency, metadata/editorial/reference and both form-producing lexicons into the same IR according to their actual owner. Preserve absent/null/empty, list and map order, long Unicode/multiline text, integer ranges and the English exercise **and** matrix form bundles. The converter is removed from the recurring build; frozen historical bytes stay in Git history or unshipped read-only controls, not in product outputs or new expectations.
2. **First RED/GREEN pilot (not live acceptance).** Before the printer, add independent Kotlin assertions for one nested, multiline `case.acc.f` presentation/skill and one `en:role.object` skill, including absent versus null, ordered prerequisites, escaping and a wrong-kind/missing-reference negative at the original Biome leaf span. RED is missing typed generated values, rejected bad references and a stale source/type/compiler/output manifest; GREEN is one Core read/type/validate → `CourseValue` printer → Kotlin value consumer with exact frozen fields. Reuse `NJ03CurriculumIndependent.cases` and existing independent course/engine cases; do not rewrite goldens from printer output. A fixture-only pilot is not a default `PackEngine`, host or no-JSON pass. If Core cannot represent the old value or retain the required diagnostic span, STOP and compare a small native helper at equal guarantees before extending syntax.
3. **Complete the one bundle and switch direct consumers.** Validate all 32 skills, both packs and form families. A deterministic Kotlin build utility materializes `Map<lexeme, Map<FeatureBundle, String>>` from the one typed lexical source, including Polish past/future and English `verb:*`, `aux:*`, `prep:*`, `neg:not` and legacy matrix bundles; `TableMorphology` remains the runtime lookup. Bind `PackEngine` to a captured immutable **pair** context: skills, forms, recipes, seeds, copy, patterns, prefixes, pronouns and noun lookup must come from that same pair; a later `selectCoursePack` changes new sessions only. Keep `enMorphology` explicitly language-scoped. Replace `CoursePack`/`PackRegistry`, `Curriculum.kt`, `PlEngine.kt`, `EnLexicon.kt`, `RecipeLoader.kt`, `StyleRecipe.kt` and `Lifehack.kt` backing sources with the generated bundle while preserving public Kotlin behavior. RED before the switch: old default path fails with retired JSON inputs and an invalid pair/reference is rejected; GREEN: both selected packs parse completely, the frozen `case.acc.f` and `en:role.object` **complete exercise outputs** match under fixed draw/seed/IDs, and matrix/training/lexical host views read the same pair's facts. A generator created before a pair switch must keep its old pair; a newly created one must use the new pair. Check negative wrong pair, missing form/copy, duplicate `(lexeme,bundle)`, and stale generator manifest. These tests must actually execute; linked cases or a successful compile are not proof.
4. **Retire each old producer at its replaced edge, with one final active-path transaction.** Once typed forms and their consumer tests pass, remove `scripts/build-pack{,-en}.mjs`, both `forms.generated.json` files and the forms half of `generateFormsFixtureSource`; once typed skills/lexicon/pair projections pass, remove `scripts/migrate-v1-to-v2.mjs`, active `course.json`/`lexicon.json`/`pair.json`/`curriculum.json` inputs, `CoursePackLoader.fromV2Layers`, `parseCurriculum`, and the course half of `generateCoursePackSource`; retire recipe/realization, style, lifehack, frequency and remaining course JSON readers/writers with their typed consumers. Replace old validators' guarantees before deleting their commands; change Gradle/CI from the two JSON embedders and old `pack:*`/`course:validate` to the one typed generator/check. Do not merge a partial **live** state with an old course JSON producer or duplicated authored fact. Slices may be developed and reviewed in the isolated branch with old input only as sealed historical oracle; the production default switch and removal of every active course JSON input/output are one reviewed transaction. Other save, preference and UI-snapshot JSON remain separate release blockers.

The true atomic dependency is the present **whole-pack JSON container plus pair-bound engine callbacks**: a skill-only default switch leaves `CoursePack.skills` and `PackEngine` using overlapping old facts, while `generateCoursePackSource` and `generateFormsFixtureSource` still ship JSON strings. The no-app-JSON course gate therefore needs both packs' active readers/writers replaced together. It does **not** require separately invented DSL families, separately tracked generators, or a single giant implementation commit. Keep intermediate probes explicitly fixture-only; do not call the course path live or the full product migrated until the actual Kotlin, browser/native host and no-JSON gates run.

STOP on a second active authority, JSON hidden in a string/DSL cell, a hand-edited generated file, changed independent expectation, loss of source span or absence/null/order/Unicode/form parity, an unresolved pair callback, unretired course JSON output, stale/empty receipt, or a P23 real-consumer N=10/100/1000 run without linear growth and at least 2× headroom at N=1000. The compiler must be pinned to a clean-fetchable immutable SHA with artifact digest; the old local-only pin in the blueprint is not acceptance evidence. Record each actual command/SHA/host and PASS/FAIL/NOT RUN; this document records **no executed gate**.
