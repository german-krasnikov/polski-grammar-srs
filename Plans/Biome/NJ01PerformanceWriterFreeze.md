## Requirements independent of the printer

P01 freezes two engines and four runs per engine, including alternate variant order, ordered positive frame intervals, nearest-rank p50/p95/p99, the strict `>25 ms` count, per-round paired p95 deltas, lower-ranked medians for two values, and exact typed `null` versus empty string. The future result must retain each actual frame interval; the current writer saves only `frames`, p50/p95 and `over25Ms`, so a parity check against its reduced old archive cannot establish this requirement. Its `intervals.filter(value => value > 0)` silently drops a nonpositive observed delta; N19 requires explicit rejection before publication instead. The browser's `backdropFilter` value is optional in the DOM and is currently represented by explicit `null` if the corresponding element is absent; a missing serialized field means the measurement was not recorded and is invalid.

P02 separates **generic numeric representation** from browser-domain validity. The listed finite binary64 values must round-trip by JavaScript `Object.is`, including negative zero and long decimals. The extreme values are not plausible frame durations. Field-domain checks still reject invalid durations, counts and intervals. P03 requires Unicode scalar and LF/TAB/U+0085 text fidelity with a safe canonical escape; an unpaired surrogate is rejected before writing. P04 defines a lower load floor of 1000 ordered runs and 30000 intervals; it is not a runtime benchmark or a chosen maximum. N01–N19 define explicit structural, type, derived-value, finite-number, version, truncation, resource and atomic-publication failures. Empty engine selection and a zero-frame run cannot become successful empty results, and a duplicate/missing run cannot be hidden by a summary.

The script currently accepts any positive integer `GLASS_ROLLOUT_ROUNDS`, finite `GLASS_ROLLOUT_DURATION_MS >= 500`, and comma-separated engine names if every token occurs in its available-engine map; it does not reject an empty selected list before writing or insist that frame intervals are nonempty. A new upper resource ceiling would narrow its accepted settings and therefore needs a justified P23 limit, not an arbitrary number copied from a generic codec. Before the writer is accepted, choose explicit per-field/row/total-byte ceilings, test the accepted boundary and boundary-plus-one with independent bytes, and measure the P04 load plus N=10/100/1000 rows with at least 2× headroom at 1000 as required by the plan. This freeze establishes the lower admission floor and rejection *at* any declared ceiling, while marking the numeric ceilings **NOT FROZEN**.

The P8 comparison must use these same semantic cases for both Kit `readData`/`formatDataValue` plus a project wrapper and a small static native text helper. Before selecting either, prove its delivery from a clean product checkout under supported Node 20.19.0 and 22.12.0, exact `-0` behavior, canonical bytes, startup/read/write cost, and no JSON emission. A local sibling checkout does not establish product delivery. After choosing the format, freeze exact complete `.measure` bytes independently of the selected printer: version, ordered names/rows, binary64 spelling, string escapes, LF policy, truncation mutations and a boundary-size document. **No output-byte golden exists yet.** A decoder returning the right value does not itself prove canonical lexical output.

The new writer must assemble and validate the full result before atomically publishing `Plans/Kotlin/artifacts/glass-rollout/web-matrix-scroll.measure` by default, without overwriting an old archive. A partially written temporary file cannot appear as a final accepted result. Historical archive removal, future writer changes, P8 selection, browser execution and complete no-JSON acceptance remain separate later steps.
