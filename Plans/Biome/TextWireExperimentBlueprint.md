## Boundary and equal guarantees

Compare three implementations of the **same** ordered typed tree, equal semantic admission, integrity check, and independent codec requirements. Each arm's physical byte ceiling is chosen only after accepted legacy controls; an identical byte ceiling would exclude different trees because the formats expand text differently. Document schemas and migration decisions are frozen separately, but their owners execute them in later slices; a generic codec cannot validate FSRS or vocabulary policy.

| Arm | Concrete mechanism | Question measured |
| --- | --- | --- |
| A: `POLSKI-TEXT` | The proposed versioned preorder records, strict UTF-8/LF framing, canonical escape rules, and trailing SHA-256 from `TextWireDesign.md`; a small static native codec in TypeScript and Kotlin common code. | Does a purpose-built readable wire give all required values and byte identity at acceptable implementation and review cost? |
| B: TOML 1.0 | A flat ordered `[[record]]` table sequence parsed **and printed by pinned maintained TOML libraries**: `smol-toml` in TypeScript and `ktoml-core` in Kotlin common code, subject to actual dependency and target checks. Each record carries parent row/index, child index, tag, optional key, and typed payload. An explicit `N` tag represents null; integer and binary64 bit payloads use canonical strings to avoid JS number coercion; a tagged UTF-16 code-unit array represents strings or keys TOML strings cannot preserve, including lone surrogates. A versioned header and terminal digest field cover exact preceding bytes. | Does reuse of established parsers/printers reduce total cost while retaining all tree, Unicode, order, canonical-byte, and recovery guarantees? |
| C: smaller text helper | One fixed versioned, length-delimited typed-row format with explicit uppercase UTF-16 code units for every key and string. It has no general TOML syntax or schema generator; it still has the same tree and digest, with its own physical byte ceiling under the shared admission rule. | Is a smaller native mechanical utility cheaper than A or B at equal guarantees? |

The TOML library must support both reading and **printing** the restricted ordered-record model on every required TypeScript/KMP target, including Android. The experiment must pin exact releases, audit license and target artifacts, and execute parser/printer behavior. TOML 1.0 does not provide null and does not promise ordering for ordinary table key/value pairs; the array-of-tables row order and explicit child index carry order. A library's permissive duplicate, numeric, escape or Unicode behavior receives an additional structural validator. Explicitly disable or reject permissive bare `null` parsing and TOML 1.1-only syntax when claiming a TOML 1.0 profile; positive tagged `N` rows are ordinary strings in the protocol schema, not TOML null. Parsing must first enforce total-byte bounds, then tree depth, row count and string limits before unbounded allocation; if a library cannot meet that boundary, B is NO-GO. The printer output itself must be canonical and produce **exactly the same bytes** for the same tree in TS and KMP. If it cannot, B is NO-GO unless an independently reviewed design revision identifies a maintained library printer that can. Do not quietly replace it with a product TOML lexer/printer, accept different bytes, or weaken the corpus.

Each arm needs a strict `decode(encode(tree)) == tree`, byte-for-byte `encode(decode(canonicalBytes)) == canonicalBytes`, verified digest, and an exact byte-and-semantic readback comparison. Decode of noncanonical alternatives fails. The digest detects corruption; it does not authenticate hostile rewrites. All three use the same independent expected tree; each arm has its own independently frozen canonical bytes because its wire syntax differs. No encoder supplies another arm's oracle. The generic tree preserves decoded child order; newly created extension keys use unsigned UTF-16 code-unit order. Later document owners define known-field schema order and reject unsupported document schema versions. Missing, null, empty string, empty list, empty record and zero remain distinct. Invalid UTF-8 and unsupported **framing** versions/kinds fail in this slice. A host unable to retain a required UTF-16 sequence is a target failure, not a reason to erase or normalize it.

The codec, escaping, hashing and physical I/O are static native mechanics (P4/P10/P13). The progress/vocabulary/preferences owners retain field meaning, FSRS validation, unknown-field interpretation, merge precedence, reset policy and mutation. No Logic predicate mutates state. A new DSL schema declaration belongs in a later comparison only if one declaration generates both TS and Kotlin validation/read plans and measurably removes semantic edit sites without adding a second authority (P7/P8). This experiment adds no DSL syntax, authoring import to app runtime, JSON fixture/output, production storage key, or user-data write.

## Frozen independent corpus before implementation

The existing `tests/fixtures/textwire/{positive,negative,document,transaction}.cases` and `corpus.sha256` are an independently reviewed **partial** semantic corpus; complete its missing canonical bytes and limits under [TextWireFreezeAmendment.md](TextWireFreezeAmendment.md), then obtain a second full-corpus review before candidate code. The `.cases` format is a readable text case manifest with literal input bytes represented through an explicit text-safe byte notation where raw invalid UTF-8 is required, expected typed tree, expected canonical bytes and expected error/state. The hash file freezes the current partial bytes; fixture updates require a separately explained requirement change (P15). These files contain no application JSON documents. If KMP browser/Native test runners cannot load shared resources, a test-only deterministic embed may consume these *same* files and have a freshness check; there is no second human-maintained Kotlin oracle. The codec experiment executes only `positive.cases` and `negative.cases`; `document.cases` and `transaction.cases` are independent requirements for later owner/repository slices and remain **NOT RUN** here.

Generic positive codec cases include nested ordered trees and unknown extension nodes; literal keys `-`, empty and `K:-`; ASCII, BMP U+E000, supplementary U+10000, and lone high/low surrogate keys in UTF-16 order; `-0.0`, finite binary64 bits and signed 64-bit edges; numeric-looking strings; multilingual text, emoji, tab/newline/backslash, controls and line separators; and zero/null/absence/empty list/empty record. Freeze progress across every accepted FSRS state/rating and exact timestamps, 32 prepared vocabulary cards, custom entries, homonyms and both directions, and preferences version/default/reminder/tint/early target-peek cases in `document.cases` for later domain-owner execution. A mechanically valid tree must never masquerade as a valid save.

Generic negative codec cases include malformed header, kind, framing version and digest; BOM/CRLF, invalid UTF-8, malformed/noncanonical escapes, illegal sentinel or key prefix, duplicate decoded map key, wrong parent/index/count, missing or trailing row, excessive depth/rows/string/total bytes, integer overflow and NaN/Infinity bits. Freeze domain negatives—wrong document schema, duplicate card/skill ID, bad FSRS state/date, unsupported preferences pack, invalid vocabulary pair/card wire and unconvertible unknown values—in `document.cases`, **NOT RUN** by the generic codec. The same generic cases apply to A, B and C where their syntax differs by using an equal semantic defect. For B, include bare TOML `null`, permissive null-value mode and TOML 1.1-only syntax as TOML 1.0-profile rejections. No old-user JSON fixture is added: existing exact-path old-user samples remain read-only and are outside this slice.

`transaction.cases` fixes **pure state-decision expectations** for the later repository slice, not a test implemented by the codec: valid new text plus legacy bytes without matching durable receipt returns `RecoveryRequired` before write/delete/save; malformed or mismatched receipt does the same and preserves both byte sequences; matching receipt after crash permits only verified cleanup; old backup conflict, readback mismatch, receipt-write/readback failure, delete failure and old-tab rewrite remain incomplete/recovery. Repeated load cannot replay reviews or merge custom words twice. This corpus freezes NJ06 safety expectations; it does not prove locks, atomic writes, cross-tab exclusion, power-loss durability or actual deletion. The old-version tab can rewrite JSON outside the new lock, so release remains blocked until a host policy/mechanism proves quiescence as required by `TextWireDesign.md`.
