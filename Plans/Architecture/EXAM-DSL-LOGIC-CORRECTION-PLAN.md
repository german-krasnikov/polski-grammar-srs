## Подтверждённые возможности и ограничение

Пять документов biome-dsl `AI/{ARCHITECTURE.md,BestPractice.md,PATTERN_DICTIONARY.md,PRINCIPLES.md,ProjectMigratioPrincipals.md}` требуют P4/P7/P10/P25: факт и пример в одном источнике; классификация/приоритет/вердикт — `DECISION`; модель владеет применением; PROGRAM только если слой выше не выражает вычисление и есть измеренный выигрыш минимум для двух хостов. Проверенный корпус `implementations/typescript/corpus/apps/booking/biome.project` использует `GENERATE logic logic generate --source ... --contract ... --target "kt ... AS <package>"`; CLI `packages/biome/src/generated/commands.mjs` перечисляет Logic targets TS/C#/Py/Kt, **не Swift**. Поэтому правила генерируются в Kotlin `commonMain`, iPad вызывает тот же Kotlin код через `:apple-bridge` и получает JSON snapshot/semantic actions. Никакого второго Swift scorer/reducer. `biome generate --check --project dsl/biome.project` должен ловить stale Policy так же, как typed rows. Не придумывать неподдерживаемые `.logic` конструкции: pilot ограничен `FACT`, `INPUT`, приоритетными `DECISION ... DEFAULT ... WHEN ... -> literal` из Booking; имена/generated API подтвердить компиляцией pilot до массового переноса.

## Первый пилот, конкретный и измеримый

1. Создать **NEW** `dsl/exam/answer-policy.{logic,contract}`. Контракт фактов одиночного ответа: `matchesCanonical: bool`, `variantQuarter: int` (0 если нет совпадения), `maximumQuarter: int`, `answerNonblank: bool`, `openManual: bool`; одно решение `answerDisposition` с приоритетом canonical → full variant → partial variant → unknown nonblank open → wrong. Типизированные `.core-data` строки сопоставляют disposition со статусом (`confirmed_full|confirmed_partial|pending_manual|wrong`) и источниками confirmed/pending (`maximum|variant|zero`). Три DECISION с повторёнными приоритетами отклонены при пилотной сверке P7: предикаты и порядок должны иметь одно место правки. Сравнение `variantQuarter == maximumQuarter` и `variantQuarter > 0` находится в DSL. `creditSource` — символ, механический Kotlin resolver берёт соответствующий уже проверенный факт; статус не пересчитывает. Не включать unordered set в первый diff.
2. В `dsl/biome.project` добавить **NEW** Logic GENERATE шаг по образцу Booking, target `kotlin/shared/src/commonMain/generated/kotlin/polski/exam/policy/ExamAnswerPolicy.kt` (имя/package уточнить по реальному printer). `ExamAnswerEvaluation.kt` использует generated Policy для single answer, сохраняя существующий `ExamAnswerEvaluation` API и quarter values. `GrammarExamScorer` и P11 reading/listening продолжают делегировать одному evaluator; старые constructors/defaults и frozen 2017/2019/2020 IDs не меняются. Не править generated `.kt` руками и не смешивать pilot с переносом всех session reducers. До объявления pilot завершённым добавить минимальный `:apple-bridge` consumer этой же Policy и Swift consumer check: передать фиксированный набор фактов, получить semantic status/quarter result через framework, сверить с DSL oracle. Это проверка второго хоста, не новый экран или тестовый backdoor в продукте; конкретный bridge entrypoint должен войти в будущий `IosExamSession`.
3. **NEW** независимые `dsl/exam/answer-policy.examples`/`.sources` с полным ключом, full/partial variant (включая 0,25), blank exact/open, неизвестным непустым exact/open, canonical-vs-variant precedence и границами `variantQuarter=0/maximum`. Прогнать Logic `examples`/`explain`/`mutants` доступным CLI и тот же fixture через generated Kotlin commonTest; ожидаемый статус и две четвертные компоненты авторятся в DSL, не снимаются с Kotlin output. Existing `dsl/exam-scoring/answer-evaluation.core-data`, `word-bank-constraint.core-data` и golden scorer tests остаются независимыми регрессиями. Негативный контроль меняет одно условие `openManual` или приоритет ветвей: тест обязан покраснеть.
4. Замер до/после: исходные `ExamAnswerEvaluation.kt` 112 строк; фактические общие потребители сейчас grammar/reading/listening, **iPad пока отсутствует**. Измерить число мест правки правила, author DSL/contract/examples LOC, generated LOC, Kotlin resolver LOC, compile/runtime overhead и класс устранённого drift. Зачёт P25 «два хоста» только после сборки Kotlin framework/header и реального Swift bridge consumer, проверившего тот же oracle; один лишь `commonMain` или будущий iPad UI этого не доказывают. Цель — один источник статуса/приоритета для web и iPad, не искусственное уменьшение общей суммы строк. Если pilot длиннее и не устраняет дубль/не проходит Kotlin backend, остановить массовый перенос, записать P25 stop-signal и дать владельцу фактические варианты; отсутствие Swift backend само по себе не блокирует Kotlin bridge.

Только после принятого pilot перенести unordered-set disposition/partial credit и provisional result, затем session action/timer disposition по одному срезу с независимыми DSL cases и сохранением каждого имеющегося P11 test. Мутация/clock/resource ownership не становятся .logic-кодом. Для `UnorderedSet` настоящие факты — accepted-key set, **required selection count**, selected size, duplicate/unknown membership и known count; правила invalid/full/partial/pending в DSL, quarter arithmetic в механическом resolver. Не выводить required count из размера ключа: B2/2024-06 Listening V/3 официально принимает любые два из трёх оснований, по 0,5 за каждое, максимум 1. Это source-backed строка для следующего среза, не часть pilot одиночного ответа. Особые B2/2020 и C1 conditions остаются source-backed refs/rows, а не inline Kotlin исключениями.

## iPad: реальный второй UI без копии правил

**Адаптеры данных до UI.** Сейчас шесть typed packages `kotlin/shared/src/commonMain/generated/kotlin/polski/exam/data/{b1y2017,b1y2019,b1y2020,b2y2017,b2y2019,b2y2020}/ExamRows.kt` и `polski.exam.ExamDataMapper` уже общие, но сборка каталога/модулей живёт только в `kotlin/composeApp/src/webMain/kotlin/polski/ui/ExamWeb.kt` (`ExamEntry`, `exams`), а четыре `examGrammarData`/`examReadingData`/`examListeningData`/`examWritingData` и их six-paper `map*` функции — в соседних webMain `ExamData.kt`, `ExamReadingData.kt`, `ExamListeningData.kt`, `ExamWritingData.kt`. Reading/Listening/Writing presentation data classes пока объявлены в `ExamReadingWeb.kt`, `ExamListeningWeb.kt`, `ExamWritingWeb.kt`. Перед native UI перенести **только** typed row → portable model adapters и каталог существующих шести IDs в **NEW** `kotlin/shared/src/commonMain/kotlin/polski/exam/ExamCatalog.kt`/`ExamSourceData.kt` (точное разбиение по размеру при реализации); webMain импортирует их вместо собственных map. Source-backed module config/order берётся из `.core-data`; каталожный `b1-sample` остаётся явным web-only legacy alias, без выдачи его за официальный седьмой экзамен. Направление: generated rows → shared adapters/models → shared session → apple-bridge → SwiftUI; webMain тоже зависит от shared adapters, **ни один shared/ios файл не импортирует `polski.ui` или DOM**. Адаптеры не должны по пути менять IDs, порядок, варианты, четверти, `answerMode` или `gradingMode`; parity по шести source snapshots до замены web consumer.

**Первый native экран после bridge pilot.** В `PolskiGrammarApp.swift` текущие `tabOrder`, `tabBarItems`, `tabContent` содержат только Training/Matrix/Progress/Vocabulary. Добавить вход «Egzaminy» через существующую навигацию с `NavigationStack` и view списка шести IDs → четырёх частей → вопроса/ответа/review; не создавать Swift массив официальных задач. `IosExamSession` snapshot должен содержать `examId`, `module`, `test/task/questionId`, source instruction/prompt, question type, ordered options/bank tokens, prompt image reference/alt, listening segment start/end и asset ID, selected writing set/tasks/word limits, answer draft/selection, current index/count, submitted, `confirmedQuarter`, `manualPendingQuarter`, `possibleQuarter`, status/visibility и deadline/remaining только при source-backed timed config. Семантические действия `selectExam`, `selectModule`, `answer`, `next`, `previous`, `selectWritingSet`, `submit`, `startTimed`, `tick`, `close` проходят через один Kotlin session; Swift только ввод, отображение и media. Image references из typed rows аналогично должны разрешаться в bundle, а не по web URL. iOS host владеет `AVAudioPlayer`/playback position и отменой на `close`; bridge владеет экзаменным состоянием/дедлайном. ## Gates и handoff

Developer сначала сохраняет текущий P11 WIP и реализует pilot в его изолированном worktree после принятия плана; main координирует изменение `dsl/biome.project` с P10/P12 ветками. Проверки после implementation: `biome logic fmt`/`logic generate`/`logic check` для source+contract, `biome generate --check --project dsl/biome.project`, existing exam oracle + targeted `:shared:jsBrowserTest :shared:wasmJsBrowserTest`, `:composeApp:compileKotlinJs :composeApp:compileKotlinWasmJs`, свежая web distribution и Playwright; **в pilot** `:apple-bridge:iosSimulatorArm64Test`, framework export/header и Swift bridge consumer с теми же cases; **после native UI** Xcode iOS Simulator build и UI test на установленном iPad simulator или подключённом устройстве. `xcodebuild` generic Simulator build не доказывает запуск. Tester независимо сравнивает DSL examples, четверти/status/partial/pending и iPad сценарий; Reviewer проверяет отсутствие второй Kotlin/Swift лестницы вердикта, корректный P25 замер, сохранённые IDs и NOT RUN gates. Публикация/Native app delivery отдельны. Архитектор не запускал эти проверки и не менял source/tests.
