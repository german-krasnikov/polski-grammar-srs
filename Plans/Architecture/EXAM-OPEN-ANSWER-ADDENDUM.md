# Экзамен: открытые ответы с ручной проверкой

Дата: 2026-11-08. Узкое дополнение к [NEXT-SESSION-EXECUTION.md](NEXT-SESSION-EXECUTION.md) и [EXAM-COMPLETION-ADDENDUM.md](EXAM-COMPLETION-ADDENDUM.md). Применить при восстановлении официальных 55 заданий/8 тестов B1/2019. По проверке разработчика `klucz.pdf` с. 6–7 у задания VI допускаются другие правильные трансформации; печатный ключ не задаёт исчерпывающий автоматический оракул. Те же правила применять к другим конкретным открытым пунктам только после чтения их ключа, не по одному имени `QuestionType`.

## Данные и контракт

Добавить в `dsl/exam.data-contract` поле `GrammarItemRow.gradingMode: enum exact|open_manual OPTIONAL`; отсутствие = `exact` для всех существующих 2017/2019/2020 строк. В `exams/pl/certyfikat-polski/B1/2019/grammar-items.core-data` пометить `open_manual` пять пунктов VI: после канонических трансформаций ключ с. 7 прямо требует принимать «wszystkie inne poprawne rozwiązania zgodne z poleceniem». V остаётся `exact` с явными scored variants из ключа с. 6: V/1 полный `Z czego?`, частичный `Z jakiej kapusty?` (0,25); V/4 четыре полных формулировки `Od kiedy?`, `Jak długo?`, `Od jak dawna?`, `Odkąd?`; V/5 полный `Jakich?`, частичный `Których?` (0,25). VI/4 содержит три известных полных варианта и при этом открыт для других правильных решений. Проверить соответствующие itemId по `ExamBin/pl/B1/2019/arkusz.pdf` и `klucz.pdf`; число 55/8 и 30 баллов — контроль полноты, а не основание пометить всё открытым. `correctAnswer` и существующие `GrammarAnswerVariantRow` остаются подтверждёнными полными/частичными примерами с точными четвертями, не объявляются полным множеством допустимых решений у VI. Не добавлять выдуманные ключи и не заменять `correctAnswer` пустой строкой.

`kotlin/shared/src/commonMain/kotlin/polski/exam/grammar/GrammarExamModel.kt`: `GrammarItem` получает `gradingMode` с default `Exact`. `ExamDataMapper.kt` и `kotlin/composeApp/src/webMain/kotlin/polski/ui/ExamData.kt` передают enum из generated rows. В `GrammarExamScorer.kt` один чистый `grade(item, answer)` возвращает `ConfirmedFull(maxQuarter)`, `ConfirmedPartial(earnedQuarter)`, `Wrong(0)` или `PendingManual(maxQuarter)`; порядок: нормализованный полный ключ → scored variants → пустой ответ → для `open_manual` непустой неизвестный pending → для `exact` wrong. `score(item, answer): Boolean` и `earnedQuarter` для прежнего exact-оракула сохраняются; `earnedQuarter` не должен превращать pending в доказанный ноль в итоговой логике. Нормализатор и четвертные веса остаются в одном месте. `GrammarExamSession.kt` на Submit хранит снимок ответов и агрегированный provisional result; повторное Submit не удваивает баллы и не превращает pending в wrong.

`GrammarExamResult` сохраняет `earnedQuarterPoints` как **подтверждённый нижний предел** и `possibleQuarterPoints` как общий максимум, добавляет `manualPendingQuarterPoints` (сумма максимумов ожидающих пунктов) и вычислимый `isFinal = manualPendingQuarterPoints == 0`. Верхняя граница = `earnedQuarterPoints + manualPendingQuarterPoints`, не выше общего максимума. Старые `correct`/`total` и `percentage` остаются совместимыми для полностью автоматических экзаменов; при pending `percentage` нельзя выводить как окончательный процент/вердикт. Если нужен видимый процент, назвать его явно «подтверждено не менее X%»; pass/fail для экзамена с pending отсутствует. Ручную самооценку/ввод дополнительных баллов не добавлять без отдельного требования и правил владения. Pisanie уже оценивается человеком и не получает фиктивный автоматический балл.

Политика нужна второму потребителю: по проверке разработчика ключ B2/2017 Listening V принимает любые ответы, согласующиеся с транскриптом (`lub inne odpowiedzi zgodne z transkrypcją!`). В пункте 1a печатный пример `młodą (osobą)` и в 1b `miłą (osobą)` получают по 0,5 балла, пункты 2–8 — по 1; официальный ответ/вес каждого слота живёт в DSL, `open_manual` относится к неизвестному непустому ответу каждого слота. Поэтому разместить общий результат `ExamAnswerEvaluation` **NEW** в `kotlin/shared/src/commonMain/kotlin/polski/exam/ExamAnswerEvaluation.kt` (status `confirmed_full|confirmed_partial|wrong|pending_manual`, `confirmedQuarter`, `pendingQuarter`) и одну чистую функцию для режима `Exact/OpenManual` и списка подтверждённых вариантов. `GrammarExamScorer` делегирует ей после своего `GrammarItem` mapping; `ExamListeningWeb.kt` использует тот же evaluator после mapping `ListeningQuestionRow.gradingMode` (новое OPTIONAL поле, default exact) и своих вариантов/типа вопроса. Таким образом неизвестный непустой ответ Listening V тоже pending, а пустой — 0. Не превращать весь Listening UI в shared и не привязывать общий результат к грамматическому `QuestionType`. В `dsl/exam.data-contract` добавить `gradingMode` к ListeningQuestionRow вместе с GrammarItemRow, а в oracle дать хотя бы один listening open case. Общий статус имеет два реальных module consumers; отдельное Logic DECISION остаётся кандидатом только после замера против этой короткой функции (P25).

В B2/2017 Listening IV печатный A={1,2} — пример, а оцениваемые ключи B={1,2}, C={2}, D={3,4}, E={1,2,4}, F={3}, G={1}. Поэтому `unordered_set` из [EXAM-COMPLETION-ADDENDUM.md](EXAM-COMPLETION-ADDENDUM.md) не должен кодировать константу «два выбора»: максимум выборов выводится из числа distinct токенов `correctAnswer` (от одного до трёх здесь), а `pointsQuarter`/`creditPerCorrectQuarter` задают точный балл. Проверить по ключу политику лишних/неверных ответов до включения этой сдачи. Это отдельная форма ответа, она не меняет смысл `open_manual`.

`GrammarExamCardModel.kt`: добавить `gradeStatus` (или тип результата) для submitted item; нынешний `isCorrect: Boolean?` не способен отличить partial от pending, поэтому оставить его только для старого потребителя или убрать после проверки usages. `ExamGrammarWeb.kt`: review показывает отдельные confirmed full/partial/wrong/pending; pending не окрашивать как ошибку, сохранять введённый ответ, показывать официальный образец (`correctAnswer` и варианты) и явное объяснение «требуется ручная проверка». Score header показывает подтверждённые баллы и отдельно максимум, ожидающий проверки; не показывает финальный процент/сдал-не сдал при pending. Текст новых статусов и пояснения дать через `UiCopy` и существующие pack-aware каталоги в `PlRuTypedPack.kt`/`EnRuTypedPack.kt`, а не литералом в DOM; если соответствующий каталог переносится в `.core-data`, источник строк должен быть один и пройти generate/check.

## DSL-first и проверка

Сами `gradingMode`, официальный ключ, варианты и баллы — данные DSL. В `dsl/exam-scoring/` добавить новый record oracle (либо расширить существующий quarter oracle аддитивно) с `mode`, `fullAnswer`, `scoredVariant`, `answer`, `expectedStatus`, `expectedConfirmedQuarter`, `expectedPendingQuarter`; сгенерированные строки используют `GrammarExamScorerTest.kt`. Обязательные независимые случаи: exact неверный непустой = wrong; open известный полный = full; open известный частичный = partial; open пустой/пробелы = wrong/0; open неизвестный непустой = pending/0 confirmed/max pending; Submit с несколькими пунктами правильно суммирует нижнюю/верхнюю границы и не даёт окончательный процент. Один браузерный Playwright/PlayTest сценарий B1/2019 VI вводит нетабличный непустой ответ, возвращается к пункту, Submit и проверяет pending, образец, отсутствие красной ошибки и финального процента; другой проверяет известный официальный ответ и сохранение старого exact 2019 поведения.

По P25: статусная таблица четырёх случаев живёт в DSL oracle и `gradingMode` row как проверяемое требование (V3/V4); текущая короткая последовательность сопоставлений в Kotlin — общий domain helper для scorer/card/UI (S1 против отдельного Logic DECISION emit). Если появится второй язык-потребитель этой политики и измеренный выигрыш, поднять её в DECISION, не переписывать в PROGRAM построчно. DOM, focus и ввод — native. `biome generate --check`, targeted common tests, browser artifact и независимая сверка PDF обязательны до включения B1/2019 как полного экзамена.
