# Module design: P11 result and session policy in DSL

## Scope and consumers

This is the next ordered slice after the accepted single-answer policy, set policy and six-paper published catalog in [EXAM-DSL-LOGIC-CORRECTION-PLAN.md](EXAM-DSL-LOGIC-CORRECTION-PLAN.md) and [EXAM-DSL-SET-AND-CATALOG-PLAN.md](EXAM-DSL-SET-AND-CATALOG-PLAN.md). It moves **result visibility and action/timeout decisions** from handwritten Kotlin into authored Biome Logic, generated for `:shared` Kotlin. It is an incremental migration of the current P11 behavior, not a replacement session architecture. Do not activate the 11 P9 author drafts, change source answers, add Desktop features, or change frozen scoring expectations as a side effect.

The current consumers are `kotlin/composeApp/src/webMain/kotlin/polski/ui/ExamWeb.kt` (timed reducer, clock, controller teardown), the four `Exam*Web.kt` part screens (result display), and `kotlin/apple-bridge/src/iosMain/kotlin/polski/ios/IosExamSession.kt` with `kotlin/iosApp/PolskiGrammar/NativeExamView.swift` (currently Grammar only). The iOS native work still needs Reading, Listening, Writing, and timed sitting; this plan gives them the same shared policy path. Physical iPad validation is deferred by the owner; an installed iOS Simulator app remains a required native UI gate. The macOS/JVM Desktop freeze remains in force.

## Public contract

Retain the existing Kotlin surface: `ExamPartScore`, `GrammarExamResult`, `reduceGrammarExam`, `reduceReadingExam`, `reduceListeningExam`, `reduceWritingExam`, `ExamSessionState`, `ExamSessionAction`, `ExamPartAction`, `reduceExamSession`, and `examSessionCardModel`. The `ExamSessionCardModel` fields and the bridge's existing Grammar JSON keys remain compatible. New policy adapters are internal to `:shared`; hosts continue to send semantic actions and an explicit `nowEpochMs: Long`. No scorer or Swift view computes a second verdict.

Author three distinct decisions, introduced in order:

1. **Result visibility** in `dsl/exam/result-policy.logic` **NEW** with `result-policy.contract` **NEW** and typed `result-policy-outcomes.core-data` **NEW**. Facts: `resultReady`, `sittingCompleted`, `manualPendingQuarter`, `possibleQuarter`, and `scope` (`part` or `sitting`). The decision yields one disposition such as `hidden`, `provisional`, `final`; the outcome row supplies **separate** `isFinal` and `showFinalPercent` fields. For a part, an existing result with zero pending is final **even when `possibleQuarter == 0`**; for a timed sitting, completion is additionally required. `showFinalPercent` requires finality **and** a positive denominator for `ExamPartScore.finalPercent`. Pending credit always hides the final percentage, including confirmed partial credit plus pending credit. An absent result stays hidden. Kotlin only sums exact quarter units and computes the existing truncated integer percentage when the policy permits it. Preserve `ExamPartScore`'s full official denominator and `GrammarExamResult`'s legacy whole-point fields. `GrammarExamResult.isFinal` likewise depends only on zero pending; its existing `percentage` is `0.0` at a zero denominator, rather than a nullable `finalPercent`. Preserve that public value and bridge projection unless a separate corrective requirement is accepted. This decision belongs to DSL; arithmetic and formatting remain native mechanics.
2. **Part action permission** in `dsl/exam/part-action-policy.logic` **NEW** with contract/examples/outcome rows **NEW**. Input facts include part kind, action kind, `submitted`, valid target ID, valid selected writing set, target belongs to the currently selected set, and first/last index. A single ordered disposition grants `apply_answer`, `select_set`, `move`, `submit`, or `ignore`; it does not mutate state. `null` Writing set selection remains valid, keeps existing drafts, and resets the index. A wrong/unknown question, task, or set is ignored; submitted parts ignore later actions; boundary navigation is a no-op. `Submit` stays idempotent. The policy applies to direct part reducers as well as a part action inside a timed sitting, after the timed policy permits dispatch. A typed action/outcome map is preferred over several mirrored Boolean `DECISION` ladders. The reducer copies answers/drafts, moves the index, invokes the existing scorer, and freezes the selected writing task IDs exactly once. Preserve current Writing behavior: when `maximumQuarter` is absent, direct `Submit` has no `ExamPartScore`; in a certified timed config, Writing reserves its full maximum for manual review even with no selected set or draft.
3. **Timed sitting event disposition** in `dsl/exam/session-policy.logic` **NEW** with contract/examples/outcome rows **NEW**. Inputs: event kind (`start`, `part_action`, `finish_part`, `tick`), `completed`, `started`, `moduleMatchesCurrent`, and `deadlineReached` derived from supplied `nowEpochMs` and the stored deadline. Ordered outcomes: ignore completed; repeated `Start` ignores; first `Start` sets deadline; an unstarted non-start event ignores; a `PartAction` or `FinishPart` for a stale module ignores **before** deadline evaluation; a matching event or `Tick` at/after deadline freezes the current part; a matching `FinishPart` before deadline freezes it; a matching `PartAction` before deadline dispatches; a predeadline `Tick` does nothing. The current action at the deadline is not applied. Every event freezes **at most one** current part at its observed `nowEpochMs`; the next deadline is that observed time plus the next source duration, not an old deadline plus duration. Later stale or backward-clock events do not thaw a frozen part. On the fourth freeze, mark the sitting complete. Module order, seconds and maximums come from `ExamModuleRow`/`ExamSessionConfig`, not from policy literals. A malformed certified config still fails its existing validation; deadline overflow still fails explicitly rather than wrapping.

The Logic contracts name facts and outputs, not Kotlin implementation fields invented for the plan. Confirm the generated Kotlin symbol spelling with a minimal generation/compile step before editing all consumers; use the already working `answer-policy`/`set-policy` `DECISION` plus outcome-row pattern. If a fact combination or typed outcome cannot be expressed by the current Logic backend, record a narrow Biome Core gap and stop that sub-slice. Do not restore the business verdict as a handwritten fallback.

## State and resources

`ExamSessionState` is the authority for current module, answer snapshots, deadline and frozen results. Part states own answers/drafts, selected set and submitted result. The host owns wall clock delivery, repeating timer, media and teardown; the reducer is synchronous and has no coroutine or timer resource. A tab switch may retain the iOS scene session; explicit `close()`/new sitting disposes it. A timed browser exit stops its interval and part controllers. Policy inputs are derived from the current state and one event, not mutable caches. Copy caller maps when freezing or exposing snapshots so later edits cannot alter a result. `Start` and `Submit` are idempotent, and frozen results cannot be replaced by late/stale events.

## Decisions and tradeoffs

This is a **DECISION + typed outcome data** migration, following Biome P4/P7/P10/P12/P15/P25 and the accepted answer/set pilot. A wholesale reducer written in `PROGRAM` would duplicate mutation mechanics and obscure time/resource ownership; a native helper that returns `canSubmit`, `isFinal`, or `shouldAdvance` would leave business decisions outside DSL. Keep only fact extraction, safe integer/time arithmetic, copying and physical IO in Kotlin/hosts. Do not introduce FLOW just for a synchronous one-event reducer; revisit it only if a real cancellable/lifetime workflow appears and a measured pilot supports it. Record authored/generated/native LOC, rule-change touchpoints, generation/compile time and real web plus iOS bridge consumers per P23/P25. A shorter native implementation is not a reason to duplicate the policy, because the owner expressly requires DSL business decisions.

## Verification and ordered implementation

1. **Result slice:** author DSL contract/decision/outcome and independent examples first; generate/check, then adapt `ExamPartScore`, `GrammarExamResult`, score/card and bridge projection without changing quarter sums. Cases: full automatic part; confirmed partial plus pending; blank/open manual; Writing full pending and no false final; incomplete sitting with zero pending; completed sitting with zero pending; `ExamPartScore(0, 0, 0).isFinal == true` with `finalPercent == null`; zero-denominator `GrammarExamResult.isFinal == true` with its existing `percentage == 0.0`. Preserve frozen `dsl/exam-scoring/*` expected values. An intentional inversion of pending/final disposition must make a DSL example fail.
2. **Part action slice:** author independent cases and generated policy before changing four reducers. Cases: known answer, unknown ID, first/last navigation, repeated Submit, answer after Submit, valid/null/invalid Writing set, inactive-set task, drafts retained across set changes, Writing timeout before set choice. Explicitly pin the Grammar unknown-ID correction, since current common reducer accepts it while the iOS bridge rejects it. Compare all current `ExamSessionFlowTest` and `GrammarExamSessionTest` behavior; do not rewrite frozen expectations from generated output.
3. **Timed slice:** author independent `session-policy.examples` with start/restart, prestart events, matching/stale module, deadline equality, deadline precedence over answer/finish, early Finish, Tick, backward time, overflow and completion. Then replace priority logic in `reduceExamSession` and exercise the real `ExamWeb.kt` consumer. Keep observed-time next deadline and one-part freeze. Use a negative control that swaps stale-module and deadline precedence; it must fail.
4. **Host integration after shared slices:** web browser scenario with timer, late input, next part, score and teardown; iOS Simulator bridge/framework/header plus installed SwiftUI app scenario. The bridge currently exposes Grammar only, so Reading/Listening/Writing/timed UI needs its own subsequent implementation and cannot be claimed by shared Kotlin tests. Verify audio lifecycle separately. Physical iPad remains NOT RUN by owner decision.

Use the actual `dsl/biome.project` tasks and `biome generate --check --project dsl/biome.project`; run relevant `:shared` JS/Wasm browser tests, `:apple-bridge:iosSimulatorArm64Test`, web compilation/browser acceptance, and iOS framework plus Simulator app checks when each consumer exists. `kotlin/shared/src/commonTest/kotlin/polski/exam/session/ExamSessionFlowTest.kt` and the existing policy tests are regression consumers; new expected dispositions originate in authored `.examples`/source cases, not Kotlin output. Report PASS/FAIL/NOT RUN separately for DSL, Kotlin tests, builds, browser and Simulator/device. This architecture task has run none of those checks.
