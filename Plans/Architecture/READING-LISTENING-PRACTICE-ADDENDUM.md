# P14: обратная связь внутри групп чтения и аудирования

2026-11-13. Дополнение к принятому [контракту P14–P16](EXAM-PRACTICE-FEEDBACK-DESIGN.md), только для Reading/Listening. Grammar vertical slice уже реализован в этой ветке. Это design handoff; production и тесты не менялись и не запускались.

## Проверенная граница

`ReadingExamCardModel` возвращает `questions` текущего `ReadingPassage` в source order; `ListeningExamCardModel` возвращает текущий `ListeningTask`, у которого уже есть упорядоченные `questions`. Оба web контроллера сейчас рисуют **все** вопросы группы одновременно. `ReadingExamAction.Next` и `ListeningExamAction.Next` меняют `currentIndex` **группы**, а не вопроса. Поэтому callback через 2000 мс не должен dispatch `Next` после отдельного ответа. Контроллер хранит `focusedQuestionId` для подсветки/фокуса DOM; reducer и route остаются на той же группе. `ExamReadingWeb.kt` сегодня делает полный `redraw` после выбора; `ExamListeningWeb.kt` после выбора меняет только классы кнопок. В Listening полный `redraw` удаляет и снова добавляет `<audio>` через `innerHTML`; смена `renderedTaskIdx` запускает `seekToTask`, который останавливает запись. Ответ или автофокус внутри той же задачи не должны вызывать ни один из этих audio effects.

**Решение о конце группы:** автоматический переход разрешён только к ближайшему ещё не committed вопросу *текущей* группы после подтверждённой оценки. На последнем незавершённом вопросе группа остаётся открытой, feedback остаётся виден, timer не ставится. Следующий passage/task открывает только уже существующая явная кнопка «Далее»; на последней группе «Завершить». Это конкретизирует формулировку «последний вопрос остаётся» из принятого контракта и защищает непрерывность аудио. Пустые/непроверенные вопросы нельзя пропустить: если после текущего нет uncommitted, но есть более ранний в той же группе, target — первый такой вопрос в source order; если нет ни одного, `mayAutoAdvance=false`. Явная навигация остаётся доступной по текущим reducer permissions, но отменяет timer/overlay. Никакой авто-submit.

## Время, фокус и media lifetime

При `FeedbackView.mayAutoAdvance` host ставит один cancellable `setTimeout(2000)` по `(part instance, groupId, questionId, generation)`. Перед callback и перед `advanceGroupedPracticeFocus` сверяются те же IDs, текущий `state.currentIndex`, `submitted=false`, видимость страницы и живой root. При следующем ответе, ручном Next/Previous, route/module change, reset, submit, hidden, `close()` и смене preference timer очищается, `clearPracticeFeedback` увеличивает generation; прошлый callback ничего не делает. Пользовательская навигация до 2 секунд имеет приоритет. Фокус нового вопроса делается по стабильному `data-question-id`, с `scrollIntoView` только внутри уже отрисованной группы и доступным `focus()`/`tabindex=-1` на heading/row; сам переход не dispatch `Answer`/`Next` и не обнуляет соседние draft ответы. На последнем вопросе фокус и feedback сохраняются до явного действия; при уходе overlay скрывается, committed остаётся.

Listening сохраняет **тот же** `HTMLAudioElement` и текущий `currentTime`/`paused` при grade, подсветке и автофокусе внутри task. Не вызывать `redraw()`/`seekToTask()`/`disposeAudio()` на этом пути; изменять только классы/текст соответствующих question rows, notice и focus. `seekToTask` остаётся только при реальной смене `currentTaskIdx`, explicit replay/seek — только от пользователя, dispose — при route close/reset. Если требуется перестроить player controls, не удалять media element из DOM для того же task. В Reading можно обновить row in place для устойчивого keyboard focus и чтобы введённый текст не исчезал.

## Проверка до реализации и после

**Исполнимый RED:** новый `tests/browser/kotlin-exam.spec.ts` Playwright test через реальный Kotlin web route `/#/exam` выбирает опубликованный `B1 Certyfikat 2017` Reading с ≥2 вопросами в первом passage, включает default ON, кликает неверный вариант первого вопроса и проверяет сразу выбранный красный + официальный зелёный + отдельный текст, затем через 2 с фокус второго вопроса при неизменной `Задание 1` и без `Submit`; текущий browser controller не умеет этот feedback, поэтому это поведенческий RED (а не compile-missing API). Для Listening использовать `B1 Certyfikat 2019` с реальной раздаваемой записью и ≥2 вопросами задачи: `play`, зафиксировать `audio` node identity/currentTime/paused, неверный click, дождаться фокуса второго, убедиться, что node/segment/playback сохранились. Existing `dsl/exam-web/listening.playtest` и `listening-replay-cycles.playtest` дают source-backed media route; добавляемые DSL PlayTests размещать в `dsl/exam-web/` и запускать через `runExamPlaytest`, не генерировать ожидания из текущего DOM.

После GREEN: commonTest для valid/current group, первого commit и double click, next uncommitted после текущего и earlier gap, последнего вопроса без auto, wrong/full/partial/pending, unordered incomplete/slot count, open Check, timed/OFF и frozen ReviewRow (выбранное неверное + все official variants/quarters). Browser PlayTests: grouped Reading choice/true-false/matching, Listening choice/unordered/text; 1999/2000 мс граница через controlled Playwright clock при необходимости, ручной Next/Previous, reset, hidden, close, stale callback, last group; для listening запись продолжает играть внутри task, а **явный** Next меняет task/segment как прежде. Настоящий выбранный неправильный текст виден после Submit и Reading, и Listening; пустой ответ обозначен `NoAnswerEntered`, pending/manual честен. Source IDs/верные ответы брать из `exams/pl/certyfikat-polski/…/*.core-data` и сверенных существующих fixtures, не из generated expected. Компиляция common/JS, `biome generate --check`, Chromium/Firefox/WebKit и iOS Simulator обозначаются PASS/FAIL/NOT RUN только после реального запуска; эта архитектурная запись не является их результатом.
