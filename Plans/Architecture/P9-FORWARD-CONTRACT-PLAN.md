### Pair grading through the existing DSL verdict

The current single-answer `dsl/exam/answer-policy.{contract,logic}` takes `matchesCanonical`, `variantQuarter`, `maximumQuarter`, `answerNonblank`, `openManual`. Its generated `Policy.disposition` and `ANSWER_POLICY_OUTCOME_ROW_ROWS` already map a documented full variant to `confirmed_full`, unknown nonblank open text to `pending_manual`, and blank to `wrong`. Reuse that decision. Refactor `ExamAnswerEvaluation.kt` so an internal `evaluateAnswerPolicyFacts(...)` accepts those five validated facts and performs the existing generated policy/outcome lookup; existing `evaluateExamAnswer(...)` only computes normalized canonical/variant facts and delegates. This is a narrow seam, not a second public grader or new native status branch. No new pair policy is required unless an independently verified source case cannot be expressed by these five facts.

`GrammarTest` gains a read-only list of **NEW** `GrammarAnswerPair` domain values and `GrammarItem` gains a read-only `pairedWithItemId: String?` marker supplied by the generic mapper. The marker is necessary because `GrammarExamScorer.grade(item, answer)` and `score(item, answer)` are public context-free APIs: without it they would falsely confirm an individually canonical I/8 or I/9 form. For a paired item, `grade(item, answer)` supplies `matchesCanonical=false`, `variantQuarter=0`, `openManual=true`, and the normalized `answerNonblank` to the same policy: nonblank is pending for that item's maximum; blank is wrong. `score(item, answer)` returns false for a paired item because a boolean context-free answer cannot establish a valid pair. Unpaired item behavior remains byte-for-byte/frozen-oracle compatible.

`gradeInAttempt(test, item, answers)` first finds that item's declared pair group. It normalizes both answer strings, finds at most one matching authored `GrammarAnswerPair`, then supplies `matchesCanonical=false`, `variantQuarter=matchedPair.firstEarnedQuarter/secondEarnedQuarter` for the current item (or 0), `maximumQuarter=item.maximumQuarter`, `answerNonblank` from this item's text, and `openManual=true` to `evaluateAnswerPolicyFacts`. Thus a matching pair with `(2,2)` yields full/full; any unlisted two-nonblank pair yields pending/pending; one blank yields wrong for the blank and pending for the other; both blank yield wrong/wrong. In particular `kilku/przyjaciół` and `kilkorgiem/przyjaciółmi` cannot pass through the individual canonical or variant path. B2/2020 and C1/2022-11 `onlyIfNotUsedBy` retain their existing complete-attempt path for unpaired items. `scoreAttempt`, `GrammarExamCardModel` and session Submit use `gradeInAttempt` so their totals and finality reflect the same DSL result; a pre-submit change to either field re-evaluates both from the current snapshot.

The generic mapper validates each pair group before evaluation: two distinct items of one test; one partner per paired item; same partner IDs across all rows in that group; unique normalized answer tuples; nonblank answer strings; earned quarters in `1..item.maximumQuarter`. The source-specific oracle checks that C1/2024-04 has two-quarter item maxima and all three tuples grant `(2,2)`. A malformed group fails source loading instead of falling back to individual auto-grading. Keep authored `correctAnswer` and any existing variants for source fidelity; the pair marker prevents them from bypassing pair context. The three allowed tuples in `p9/grammar-answer-pairs.core-data` are the complete positive list for this group, not a product of per-slot alternatives.

Add the independently transcribed typed pair oracle **NEW** `dsl/exam-scoring/c1-2024-pairs.core-data`: the three permitted tuples, both forbidden crossed tuples, one blank in either position, both blank, and a change of only I/9 that changes I/8's verdict. Assert status, confirmed and pending quarters for both items, as well as `grade(item, canonical)` pending and `score(item, canonical)==false`. A separate negative control removes the pair marker or changes one partner and must fail. Preserve all existing `answer-policy.examples`, old grammar scoring cases and B2/2020 conditional tests unchanged. Browser and iOS results must consume these shared evaluations; they do not reimplement the pair verdict.

4. **Other forward shapes:** B2/2024-06 Listening V/3 accepts any two from three facts; C1/2023-11 Listening IV has six required choices from twelve and V/1,2,7 have accepted fact pools/aliases.
