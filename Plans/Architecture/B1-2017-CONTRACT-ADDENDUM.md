## Контракт данных

Уточнение после сверки чтения B1/2017: та же схема четвертей применяется к `ReadingQuestionRow`. В чтении 34 ответа: задания I–IV — 5+7+7+7 по одному баллу, V — 8 по половине; всего 30 баллов (120 четвертей). Mapper и итог чтения должны сохранять и суммировать веса, а не число ответов. Legacy `points` допускает отсутствие при заданном `pointsQuarter`; хотя бы одно поле обязательно для каждой оцениваемой строки. Это расширение того же механизма, а не новый способ оценивания.

В `dsl/exam.data-contract` добавить к `ListeningQuestionRow` и `GrammarItemRow` поле `pointsQuarter: int OPTIONAL`. Старое `points: int` оставить ради 2019 и прочих сдач; effective maximum = `pointsQuarter ?: 4 * points`, где единица равна четверти балла. Для новых дробных B1/2017 строк записывать точное `pointsQuarter` (2 для 0,5; 3 для 0,75; 4 для 1). У `GrammarItemRow` с частичным ответом `pointsQuarter` задаёт максимум (2 для 0,5). Старое `points` при наличии `pointsQuarter` — только legacy fallback, не второй авторитет: по возможности не делать его обязательным для новых строк; если контрактная совместимость требует обязательности, явно считать его legacy, не применять в scorer. Не использовать `Double` как источник точности четвертей.

Добавить `GrammarAnswerVariantRow KEY variantId COUNT 1..` с `variantId: string`, `itemRef: ref GrammarItemRow`, `answer: string`, `earnedQuarter: int`. Генерировать только в B1/2017 через `--rows GrammarAnswerVariantRow exams/pl/certyfikat-polski/B1/2017/grammar-answer-variants.core-data` **NEW**. В `GrammarItemRow.correctAnswer` остаётся полный ответ из ключа; variant содержит только дополнительные допустимые ответы с точными баллами, включая `z kim`/`dlaczego` по 1 четверти, если PDF подтверждает соответствующий itemId. `z którym`/`po co` — полный ответ по 2 четверти, если это именно ключ для этих items. Не угадывать прочие варианты; уникальность `(itemRef, normalized answer)` и `0 < earnedQuarter <= maximum` проверять при загрузке/тесте. Если `COUNT 1..` при непереданном `--rows` мешает прежним 2019 шагам, проверить поддерживаемую optional-record форму в biome и применить её; не добавлять фиктивные варианты 2019.

К `WritingTaskRow` добавить `setId: string OPTIONAL` (для B1/2017 значения `I`, `II`, `III`; отсутствие означает старый линейный список 2019). Расширить enum `genre` на `invitation|wishes|story|report` рядом с существующими `letter|description|argument|essay`. `taskNumber` внутри набора — 1 или 2. Шесть строк в `exams/pl/certyfikat-polski/B1/2017/writing.core-data`: I invitation 20 + essay 180, II wishes 25 + story 175, III description 60 + report 140 слов; точный текст инструкций — из PDF. Не создавать отдельный `WritingSetRow`: `setId` в двух строках достаточно для трёх наборов; три набора × две задачи валидировать в тесте.

## Потребители и ownership

- `kotlin/shared/src/commonMain/kotlin/polski/exam/grammar/GrammarExamModel.kt`: `GrammarItem` получает максимум и список scored variants (immutable); старые конструкторы/2019 rows используют default `pointsQuarter = points * 4`, variants empty. `ExamDataMapper.kt` и web `ExamData.kt` передают новые поля. Не копировать таблицу вариантов в Kotlin.
- `GrammarExamScorer.kt`: нормализация остаётся единой; точный `earnedQuarter(item, answer)` ищет полный ответ первым, затем варианты, иначе 0. `score(item, answer): Boolean` для старого 2019 oracle остаётся признаком полного совпадения; он не выражает частичные баллы. `scoreAttempt` суммирует integer quarter units и percentage из них. `GrammarExamResult` добавляет authoritative `earnedQuarterPoints`/`possibleQuarterPoints` с default из старых целых полей; прежние `correct`/`total` сохраняют старое значение для целочисленных экзаменов и не используются для дробного UI. Для B1/2017 `ExamGrammarWeb.kt` показывает форматированное `earnedQuarterPoints / 4` без лишних `.0`; review различает полный/частичный/нулевой ответ. Если сохранение legacy Int-полей для дробного результата требует округления, считать их deprecated legacy view и документировать; не использовать округление в percentage или UI.
- `kotlin/composeApp/src/webMain/kotlin/polski/ui/ExamWritingData.kt`, `ExamWritingWeb.kt`: `WritingTask` получает optional `setId` и genre из generated row; выбор ровно одного из I–III до первого текста; `drafts` остаются keyed by taskId, навигация и Submit видят только две задачи выбранного набора. При смене набора не смешивать черновики. `setId == null` оставляет последовательность 2019 как есть. Отображение жанра/длины — из rows, DOM и textarea остаются native.
- `ListeningQuestionRow.pointsQuarter` пока не терять в `ExamListeningData.kt`: добавить его в `ListeningQ`; текущий `ExamListeningWeb.kt` считает вопросы, а не баллы. До появления weighted scorer не показывать 37/30 и не объявлять Listening оцененным корректно. Реализовать маленькую чистую функцию суммирования quarter units с тем же правилом нормализации/true-false; не переносить HTMLMediaElement в shared.

По P25: веса/варианты/выбор набора — `.core-data` как единственный источник; арифметика quarter units и нормализация — короткая Kotlin-механика с одним потребителем (S1/S4), DOM — native (S5). Ожидания для full/partial/zero и группировки — `dsl/exam-scoring/scoring.core-data` (расширить отдельным типом record либо новым oracle contract, не переосмысливать старый boolean `ScoringCaseRow`) и generated commonTest; UI flow — реальный Playwright/условный PlayTest пилот из основного плана.

## Приёмка

1. Суммы по заданиям B1/2017: Listening I–V = 7+7+5+6+5 = 30; Grammar I–VII = 5+2,5+5+2,5+7,5+2,5+5 = 30. В формулировке handoff «37/30» означает 37 вопросов на 30 баллов, а «50/30» — 50 вопросов на 30 баллов; не трактовать 37/50 как баллы. Проверить фактическое число строк каждой секции/сумму четвертей против PDF, включая частичные варианты IV/2 и IV/3.
2. Полный ответ получает 2/4 четверти по своему максимуму, `z kim`/`dlaczego` получают 1 четверть только у своих itemId, неверный/пустой — 0. 2019 `score`, старые integer result и отображение остаются неизменными. Неподтверждённые ключи — blocker включения B1/2017 в `ExamWeb.kt`.
3. Pisanie показывает три варианта, выбранный вариант содержит ровно две задачи, черновики не смешиваются, Submit не выдаёт автоматический балл; существующее письмо 2019 остаётся доступно в прежнем порядке. Проверка в production web browser и DSL data generate/check.
