# Exam web PlayTest pilot — 2026-11-08

## Contract and implementation

The authored browser expectations are in `dsl/exam-web/*.playtest`. The narrow Playwright host is `tests/browser/exam-playtest-host.ts`; it compiles those sources through the public `@biome-dsl/dialect-test` `compilePlan`, `createRuntimeRegistry`, and `runPlaymodePlan` API. `tests/browser/kotlin-exam.spec.ts` provides a fresh Playwright page per case. The host performs natural clicks and keyboard input, reads DOM/media state after actions, and keeps no business answer table. `BIOME_DSL_TS_ROOT` may point at the sibling checkout; the default resolves `../../Python/biome-dsl/implementations/typescript` from this repository.

## Initial P25 boundary measurement

The initial pilot had five authored PlayTest scenarios in `dsl/exam-web/` (63 lines). The typed action/query registry and runner receipt give a declarative, independently reviewable assertion source (V4), and the same scenarios can run against Wasm and JS distributions without copying expected strings (V1, pending JS execution). The native Playwright host plus spec is 195 lines and still has only one browser host, so this pilot hits S1/S4 on code size/consumer count. Keep it narrow; no new syntax, general adapter framework, or claim of measured code-size savings. Media transport, DOM selection, browser isolation, and cleanup remain native.

## WebKit media replay correction

The independent tester observed two full-run WebKit failures on the real B1/2019 MP3: one at initial Play and one at replay after seeking to the task end. In both, `audio.paused` remained true for the 10-second assertion window; the replay trace showed the player at `0:00 / 3:26` after the click. The failing runs are `/tmp/polski-exam-corrected-crossbrowser.log` and `/tmp/polski-exam-focus-3browser.log`. Isolated passes did not close this intermittent defect.

`ExamListeningWeb.kt` now owns an explicit play intent and request generation. It observes the `play()` Promise, waits for an in-progress seek to finish, avoids a stale end-boundary pause during replay seek, and cancels pending intent on user pause, task change, submit, or route exit. A genuine playback rejection shows `Не удалось воспроизвести аудиозапись` and leaves the button available for a user-initiated retry; it does not retry automatically. The final player disables Play only while metadata is unavailable or a media error is present. During a seek, a click records the play intent and playback waits for the seek to finish.
