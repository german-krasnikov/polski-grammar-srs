# P14–P16: контракт обратной связи при самостоятельном экзамене

2026-11-12. Детализация принятого [P13–P19 плана](EXAM-LEARNING-QUALITY-PLAN.md). Объём: мгновенная проверка по умолчанию для самостоятельного прохождения, выбранный неверный ответ в отчёте, отменяемый переход через 2 секунды и очистка старого feedback. Это handoff для Developer → независимый Tester → Reviewer, не реализация. Первый исполнимый срез — web grammar `ChooseForm`; расширение остальных controls после него. Предыдущие official exam score, FSRS и timed session остаются источниками истины.

## Проверенные зависимости и граница

`reduceGrammarExam`, `reduceReadingExam` и `reduceListeningExam` сейчас разрешают `Answer` до `Submit`, после которого immutable результат создаётся из `answers`. Разрешение действий даёт `dsl/exam/part-action-policy.logic`; дедлайны и заморозку timed сдачи — `dsl/exam/session-policy.logic`. `GrammarExamScorer.gradeInAttempt` учитывает paired answers и `onlyIfNotUsedBy`; `ReadingExamScorer`/`ListeningExamScorer` и `dsl/exam/{answer-policy,set-policy}.logic` владеют оценкой, включая `PendingManual`. Новый слой не классифицирует правильность самостоятельно и не меняет существующие score oracles. `ExamWebController` держит отдельные контроллеры частей и timed; в web чтение/аудирование показывают несколько вопросов одной задачи, грамматика — один item. `IosExamSession` владеет нативным shared snapshot; SwiftUI `NativeExamView` только вводит и рисует данные. На Android в текущем `MainActivity.kt` экзаменного consumer нет, а JVM Desktop заморожен для новых функций.

### Состояние и последовательность

1. **Practice ON.** Один click по `ChooseForm`/single-choice или одному слову word bank (в bank хранить выбранный `tokenId` для UI и его source `text` в `answers`) вызывает policy. Для завершённого простого ответа dispatch `Answer` один раз, фиксирует `CommittedAnswer` и grade существующего scorer, показывает выбранное. Ошибка: выбранное красное, source-backed правильное зелёное, плюс текст/значок и доступное объявление; успех: зелёный выбранный. Повторное нажатие не меняет `answers`, `committed` и quarter points. Если preference OFF, обычное редактирование до submit сохраняется.
2. **Составные ответы.** `UnorderedSet` можно менять до официального числа выбранных элементов; auto commit только когда все обязательные слоты заполнены и нет неоднозначного open ответа, иначе явная кнопка «Проверить». Текстовые `FillGap`/`Transform` и открытые множества получают commit по «Проверить», никогда на каждый keystroke. Для парных/условных grammar answers `dependenciesReady=false` до наличия зависимого ответа; первый answer фиксируется, раннего wrong/auto нет. После второго commit grade **полного** snapshot можно показать обоим, не переписывая первый выбранный текст; баллы вычисляются тогда, когда зависимости известны. `PendingManual` и writing показывают честное ожидание без красного и автоматического перехода.
3. **Две секунды.** Policy разрешает `mayAutoAdvance` только после окончательного settled verdict. Хост (web timeout/SwiftUI Task) заводит ровно один cancellable timer 2000 мс по `(part instance, itemId, generation)`; при срабатывании сверяет token и только тогда вызывает `advancePracticeFocus`. Следующий вопрос выбирается из source order *в текущей задаче/пассажа*, сначала ближайший ещё не committed; переход `ReadingExamAction.Next`/`ListeningExamAction.Next` допускается лишь когда в группе не осталось незавершённых вопросов. На последнем вопросе остаётся видимое завершение, без бессмысленного таймера. В grammar следующий item — `GrammarExamAction.Next`. Никакого скрытого `Submit` от таймера.
4. **Отмена и очистка.** Manual Next/Previous, выбор другой задачи, reset, submit, timed finish, route change, смена курса, web `close()`/unmount, `visibilitychange` в hidden, iOS background/scene change отменяют timer и увеличивают `generation`; видимый feedback привязан к itemId и исчезает при уходе с него. При возврате сохранённый committed answer остаётся, stale overlay не восстанавливается и старый callback не продвигает новый item. Повторный быстрый tap и завершившаяся анимация после dispose не вызывают новое действие. `Motion.Reduced`/animations OFF отключают только эффекты; 2 секунды и доступное текстовое состояние сохраняются.
5. **Timed.** `ExamSessionState`/`reduceExamSession` получают старые editable ответы, не применяют practice commit/таймер и не выдают key до `FinishPart`/дедлайна. При результате берут frozen maps. Никакого изменения официальной длительности, четвертных баллов или partial/pending policy.

## Интеграция хостов

- Web: `WebPreferencesController.setImmediateExamFeedbackEnabled`, toggle в `SettingsWeb.kt`, чтение pref при создании `ExamWebController`; не кэшировать значение, которое не обновится при Settings import. `ExamGrammarWeb.kt` — первый vertical slice; при расширении `ExamReadingWeb.kt`/`ExamListeningWeb.kt` должны управлять focus внутри группы, а не делать `Next` целого passage/task после одного ответа. `ExamWebController.close()` закрывает timer каждого part controller наряду с audio. CSS `.exam-option` получает статусные состояния с text/aria; не полагаться на цвет или `transitionend`. `renderResult` трёх контроллеров использует `ReviewRow` с отдельными labels вместо одного `→`/контекстных скобок.
- iOS: `IosPreferencesSession.currentSnapshot`/`set` проецирует флаг; `PolskiGrammarApp.swift:IosSettingsView` показывает его и передаёт актуальное значение `NativeExamView`/scene-owned model. `IosExamSession` получает общий feedback/review snapshot, SwiftUI управляет cancellable `Task` и lifecycle, без повторной оценки. Текущий `grammarReviewItemJson` уже содержит `answer` и `officialExamples`; новые labels и статус применить и к reading/listening snapshot. iOS Simulator XCTest проверяет настоящий tap и teardown.
- Android: shared preference codec должен оставаться читаемым в `AndroidUserPreferencesStore`; нового exam UI в проверенном `MainActivity.kt` нет, поэтому не заявлять native feedback gate или добавлять пустой exam settings control до появления consumer. JVM Desktop: никаких новых функций; только регрессия декодирования portable preference при существующем импорте, если затронута.

## Проверка и передача

**Срез 1 (P14 web grammar).** Developer пишет поведенческий RED для нового/legacy default ON и explicit OFF roundtrip, неверного первого click + двойного tap + score, true/false feedback в practice/timed, 2000 мс/Manual Next/route/hidden stale cancellation; затем реализует DSL/общий reducer/preference/web wiring и наблюдает GREEN. Старые PlayTests, зависящие от свободного выбора до submit, явно ставят preference OFF в fixture через UI/хранилище, только если проверяют legacy mode; существующие score oracles не перенастраиваются. Tester независимо добавляет/запускает browser PlayTests через `dsl/exam-web/*.playtest` и `tests/browser/kotlin-exam.spec.ts`, а также codec/commonTest. Проверять текст, DOM/a11y, конкретный выбранный неправильный вариант и порядок событий, не только CSS class.

**Срез 2 (P14 остальные controls + P15).** Table cases: одиночный выбор; bank с повторяющимся text и разными token IDs; grouped reading/listening с ≥2 незавершёнными вопросами; unordered set частичный/полный/oversel; text/open manual; paired/conditional grammar; writing pending; final item. Review: wrong выбранный и правильный рядом, correct, partial, blank, accepted variant, pending, frozen after submit. Общие Kotlin tests + реальные web PlayTests + Apple bridge/Simulator при изменении NativeExamView.

**Срез 3 (P16).** Repro stale overlay и callback после ручной навигации, перезапуска части, hidden/background, смены курса, ухода со страницы, отключения анимации, быстрого повторного click; контролируемые часы для pure lifecycle и Playwright ожидание наблюдаемого UI состояния. Исправления проходят Developer → Tester → Reviewer. `biome generate --check --project dsl/biome.project`, изменённые Kotlin target tests/compilation, Playwright Chromium/Firefox/WebKit и iOS Simulator — отдельные фактические PASS/FAIL/NOT RUN. На Android/device не переносить PASS других хостов.

Текущие вопросы для реализации не требуют нового решения владельца: первый click фиксируется только при включённом practice режиме, полный timed скрывает оценку до submit. Авторизация владельца на этот объём уже дана. Архитектор не запускал тесты и не менял исходники.

### Срез 2: уточнение общего контракта реализации

`CommittedAnswer` дополнительно хранит `selectedTokenId` для bank: scorer получает исходный `rawAnswer`, а UI сохраняет идентичность выбранного токена даже при одинаковом тексте. `acceptGrammarPracticeInput` принимает `PracticeInputEvent.Choice` или `.Check`; текстовые grammar controls остаются draft до явного Check. `PracticeFeedbackState.evaluations` хранит уже определённые результаты scorer для всех committed items. После фиксации второго парного/условного ответа она пересчитывается из полного snapshot, так что первый answer получает определённую оценку без изменения первого raw answer. Видимый overlay по-прежнему только один и очищается при навигации; карта evaluations не восстанавливает старый overlay. `grammarReviewRows` строит read-only строки только из frozen `GrammarExamState.answers` после Submit.
