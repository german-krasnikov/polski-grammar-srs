## P10. Форма ответа следует официальному заданию

Факт: `dsl/exam.data-contract` сейчас разрешает грамматике `choose_form|fill_gap|transform|word_formation`, чтению `multiple_choice|true_false_not_given|match_heading|fill_gap|short_answer`, аудированию `multiple_choice|true_false|fill_gap|match`; `ExamModel.QuestionType` тоже не знает `word_bank`, `matching`, `gap_fill_fragment`, `question_formation`. В web `ExamGrammarWeb.kt`, `ExamReadingWeb.kt`, `ExamListeningWeb.kt` часть форм оказывается в обобщённом fallback. Сначала составить по подключённым PDF матрицу «пункт → тип → control → payload → проверка» и устранить только реально отсутствующие формы. Аддитивно расширить enum в `dsl/exam.data-contract` и `kotlin/shared/src/commonMain/kotlin/polski/exam/ExamModel.kt`; сопоставление строки с типом остаётся в `ExamDataMapper.kt`/web data adapters, без переименования старых tags или item IDs.

`word_bank` показывает напечатанный банк и сохраняет выбранный токен; доступность/повторное использование слова следует **только** инструкции и source-backed условию, не универсальному запрету повторов. `matching` и `gap_fill_fragment` связывают конкретный слот с напечатанными метками/фрагментами; set answers используют уже существующий `ExamAnswerMode.UnorderedSet` и размер официального ключа, в том числе B2/2017 Listening IV с 1/2/3 выбранными метками. `transform` и `question_formation` принимают произвольный текст, не теряя фокус; решение `Exact/OpenManual`, известные полные/частичные варианты и зависимость B2/2020 II/6→II/8 остаются в существующих общих evaluator/scorer. Не превращать неизвестный допустимый ответ в wrong. Неизвестный tag на уровне mapping — явная ошибка/недоступный пункт, а не немой generic control.

Приёмка P10: frozen DSL oracle для каждого реально встреченного control включает payload, четвертной результат и как минимум отрицательный случай; browser PlayTest вводит/меняет ответ, возвращается к пункту и видит тот же текст/выбор, затем различает confirmed full/partial/wrong/pending. Старые exact пункты и ID регрессируют без изменения. Source-backed условие C1/2024 I/8–9 из ключа с. 8 требует отдельного узкого `ref`/constraint oracle по образцу B2/2020, после проверки формулировки и порядка; **не** добавлять безусловные варианты или общее правило для всей рамки.

## P11. Четыре части в shared и полный сеанс

Факт: `kotlin/shared/src/commonMain/kotlin/polski/exam/grammar/{GrammarExamModel,GrammarExamSession,GrammarExamScorer,GrammarExamCardModel}.kt` уже задают чистый reducer и результат; `ExamAnswerEvaluation.kt` содержит `Exact/OpenManual`, `Single/UnorderedSet` и статусы. `ExamReadingWeb.kt`, `ExamListeningWeb.kt`, `ExamWritingWeb.kt` сейчас владеют mutable answers/drafts, индексом и submit в web-контроллерах. Вынести **только** эти правила в NEW `kotlin/shared/src/commonMain/kotlin/polski/exam/{reading,listening,writing}/`: для reading/listening `*ExamModel.kt`, `*ExamSession.kt` (immutable state + `Answer/Next/Previous/Submit`), `*ExamScorer.kt` и `*ExamCardModel.kt`; для writing model/session/card model, без автоматического scorer. Сохранить текущие web IDs, порядок вопросов, выбранный writing `setId`, оба prompts в наборе, draft текста и счётчик слов. `Submit` сохраняет снимок и идемпотентен; invalid itemId не создаёт посторонний ответ. Presentation card строится из state, а не управляет им.

Reading scorer использует четвертные `pointsQuarter` и общий evaluator для source-backed open answers; listening использует тот же evaluator/`evaluateUnorderedSetAnswer`, включая поэлементный credit, partial и pending. Агрегат каждой части содержит `confirmedQuarter`, `possibleQuarter`, `manualPendingQuarter`, `isFinal`; при pending виден подтверждённый нижний предел без окончательного процента/вердикта. Writing хранит ответы и статус «требует проверки» с официальным максимумом, но не выставляет придуманные баллы. Оставить `HTMLAudioElement`, media events, `close()/disposeAudio()`, DOM, focus и word-count rendering в `kotlin/composeApp/src/webMain/kotlin/polski/ui/Exam{Reading,Listening,Writing}Web.kt`; web data adapters `Exam{Reading,Listening,Writing}Data.kt` отображают generated rows в общие модели. Не переносить в `commonMain` browser IO, interval или DOM.

Полный последовательный режим — NEW `kotlin/shared/src/commonMain/kotlin/polski/exam/session/ExamSession{Model,Session,CardModel}.kt`, только **после** миграции трёх частей. `ExamModuleRow` **NEW** в `dsl/exam.data-contract` хранит `examRef`, `module`, `order`, официальный `durationSeconds`, `maximumQuarter`; значения для конкретной сдачи авторятся в её `.core-data` из arkusz/regulamin с provenance, без default 25/45 и без вывода по количеству заданий. Валидация: ровно четыре модуля, уникальный порядок, сумма item maxima у автоматически оцениваемой части равна объявленному максимуму, письменный максимум подтверждён источником. Для сдачи без полного конфига сохраняется нынешняя практика отдельных частей; кнопка полного timed flow недоступна. Reducer хранит текущий модуль, снимки ответов и абсолютный дедлайн; host передаёт текущее время события, а web владеет interval/cancel и повторным чтением часов после ухода/возврата. Истечение времени и `FinishPart` фиксируют часть один раз и переходят дальше. Результат полного сеанса суммирует confirmed/pending/manual writing; до ручной проверки **нет** окончательного процента и pass/fail. Официальный порог можно авторить в DSL только после проверки правил для данной сдачи и смысла порога по частям; не применять произвольные 60%.

Приёмка P11: shared tests проверяют навигацию, исправление ответа, повторный submit, точные четверти, B1/2020/B2/2017 unordered sets, B1/2017 partial, B1/2019 и B2/2017 open_manual, B2/2020 зависимый вариант и writing set; реальные DSL oracle содержат входы и ожидания независимо от production scorer. Для полного режима — границы дедлайна (до/ровно/после), повтор события, возврат вкладки, сохранение черновика при переходе, отсутствие ложного итога при pending. Web Playwright проверяет все четыре части, содержательные тексты/изображения, реальные media controls и закрытие/повторный вход. Native compilation не заменяет browser runtime, а web PASS не доказывает native UI.

## P9. Ещё 11 взрослых официальных сдач B2/C1

[Инвентарь](EXAM-2022-2024-SOURCE-INVENTORY.md) перечисляет 11 отдельных сессий B2/C1 2022–2024; уже существует `exams/pl/certyfikat-polski/B2/2024-02/exam.core-data` с `examId: certyfikat-polski-B2-2024-02`. Текущий `ExamId(provider,targetLanguage,level,year)` в `ExamModel.kt` недостаточен для двух сдач одного уровня в год. Добавить в `ExamRow` необязательное поле точной даты/диапазона сессии и отображаемую метку каталога; `examId` остаётся единственным устойчивым ключом прогресса. Для **новых** сдач выбрать однозначный date-qualified ID, проверять глобальную уникальность; существующие `B2-2024-02` и другие опубликованные ID не переименовывать. Не строить UI identity по одному `year`.

Повторяемый срез для каждой сдачи: официальный arkusz + transkrypcja/klucz + MP3 и иллюстрации с URL/SHA-256 → вручную сверенный перечень задач, слотов, ключей, вариантов, весов, genres/sets, module timing → `.core-data` и соответствующие `dsl/biome.project` GENERATE steps → generated typed rows → общий scorer/UI → независимый DSL oracle → browser acceptance. Начать с B2/2024-02 и C1/2024-04, уже имеющих проверенные ссылки и ключи в инвентаре, чтобы закрыть повторяющиеся ID и зависимые ответы до массового импорта. Проверить источник каждой даты и взрослую категорию; не считать опубликованную ссылку доказательством скачанного MP3. Новый каталог открывает вариант только после всех четырёх модулей и чистой воспроизводимой доставки media в checkout. Все 11 затем проходят одинаковый gate; `year`/count не является критерием полноты.

## P12. Оставшийся UiCopy на Swift

Факт: `kotlin/shared/src/commonMain/kotlin/polski/presentation/SnapshotCommon.kt` сейчас передаёт Swift лишь `uiResetProgress`, `uiProgressTab`, `uiSettingsTab`, `uiLifehacks`, `uiAgain`, `uiGood`, `uiShowAnswer`; `kotlin/iosApp/PolskiGrammar/PolskiGrammarApp.swift` уже читает их через `uiText`, но ещё содержит видимые русские подписи и сообщения в navigation/settings/training/progress/empty/error. Сделать список **семантических UI labels**, зависящих от выбранной пары курса; расширить существующий `UiCopy`/pack-aware источник и snapshot keys, затем заменить соответствующие литералы в Swift существующим `uiText`. Содержательные польские примеры, коды уровней, системные названия тем и диагностические тексты рассматривать по смыслу, не переписывать все `Text(...)` построчно. Оставить стабильные snapshot key names и fallback для старых framework/предпросмотра; не дублировать перевод в Swift. `kotlin/apple-bridge` должен экспортировать нужные public types/снимок в реальном framework: проверить сгенерированные Objective-C headers и Swift compile, особенно после P5 `:srs-progress` move. Нативный Mac и JVM Desktop получают только требуемые совместимость/багфиксы, без новых экранов.

Приёмка P12: snapshot tests для pl-ru/en-ru сравнивают конкретные ключи/значения и отсутствие недостающих ключей; iOS Simulator UI tests проверяют выбранные экраны на обоих пакетах и accessibility labels. `:shared:iosSimulatorArm64Test` + `xcodebuild ... test`/device gate запускаются отдельно по доступному host/toolchain; web/snapshot PASS не выдаётся за запуск iPhone/iPad. Реальные команды описаны в `kotlin/README.md`.
