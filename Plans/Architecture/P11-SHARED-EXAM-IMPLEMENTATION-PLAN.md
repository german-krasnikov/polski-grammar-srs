# Module design: P11 shared written exam session

This refines the accepted [P9–P12 plan](NEXT-SESSION-P9-P12-PLAN.md), [question controls](EXAM-QUESTION-CONTROLS-ADDENDUM.md), [C1 answer constraints](C1-2024-ANSWER-CONSTRAINT-ADDENDUM.md), and [source findings](P9-SOURCE-FORM-FINDINGS.md). It is an implementation handoff, not a new catalog approval. P10 question controls must be integrated from their reviewed result before depending on their fields. The accepted C1 pair contract is a narrow P9 prerequisite for activating C1/2024, not a gate on migrating the existing six exams to P11 shared parts or timed infrastructure. The four written parts are listening, reading, grammar and writing; speaking is outside this flow. macOS/JVM Desktop is frozen to bug fixes.

## Scope and consumers

`kotlin/shared/src/commonMain/kotlin/polski/exam/` owns pure exam state, evaluation and presentation data. `kotlin/composeApp/src/webMain/kotlin/polski/ui/ExamWeb.kt` and the three existing `Exam{Reading,Listening,Writing}Web.kt` controllers are the first consumers. Existing `ExamGrammarWeb.kt` already consumes the shared grammar model and remains its owner for grammar controls. `Exam{Reading,Listening,Writing}Data.kt` currently map generated rows to web-local models; move their model targets into common code without changing published exam/question IDs or the current independent-part route. Generated files under `kotlin/shared/src/commonMain/generated/` are output of `biome generate`, never hand edited. No native UI feature follows from the shared model.

The source of truth for official items, module configuration, variants and independent scoring oracles remains `.core-data` under `exams/` and `dsl/`. P9 source authoring remains a separate, paper-by-paper task. The local PDFs/MP3s recorded in [provenance](P9-SOURCE-PROVENANCE.md) prove acquisition, not transcription, media segmentation or public readiness.

Use `ExamAnswerEvaluation.kt` as the single semantics for `Exact/OpenManual`, `Single/UnorderedSet`, `ConfirmedFull/ConfirmedPartial/Wrong/PendingManual`. Do not build a second generic question framework. If a source-backed variant or pair rule is not representable, add the narrow DSL row and mapper; an unknown nonblank open answer remains pending, and a known partial receives only its authored quarter credit. Grammar continues through `GrammarExamScorer.gradeInAttempt(test,item,fullAnswers)`, preserving B2/2020 `onlyIfNotUsedBy`. When the accepted C1/2024 pair table is implemented for P9, pair-dependent evaluation must use the entire frozen answer map at Submit. That source-specific addition does not block P11 for existing exams.

`ExamReadingData.kt`, `ExamListeningData.kt` and `ExamWritingData.kt` become generated-row adapters to these common models. Keep their current catalog keys until P9's date-qualified catalog mapping is integrated; preserve the already existing `certyfikat-polski-B2-2024-02` DSL `examId`. Do not derive identity from `ExamId(provider,targetLanguage,level,year)` or rename published progress keys. Unknown `QuestionType.fromTag` remains an explicit load failure, never a generic web fallback. P10's reviewed control payload belongs in the mapped question model where needed; card models expose it, while DOM controls remain host code.

The web controllers replace local answer/index/submitted state with reducer state, dispatch on input/navigation, and render cards. `ExamListeningWeb.kt` retains `HTMLAudioElement`, set-slot input UI, media events, replay/cancel, and `close()/disposeAudio()`; it must serialize set selections into the reducer's answer string without changing printed slot count. `ExamReadingWeb.kt` retains text and focus rendering. `ExamWritingWeb.kt` retains textarea focus and live count display. `ExamWeb.kt` retains independent module entry and controller disposal.

### P11-B: complete timed session, after P11-A

Introduce **NEW** `ExamModuleRow` in `dsl/exam.data-contract` during P11-A so standalone writing can receive its source-backed maximum; P11-B consumes the same rows for timed configuration: `moduleId: string` as the row key, `examRef: ref ExamRow`, `module: enum listening|reading|grammar|writing`, `order: int`, `durationSeconds: int`, `maximumQuarter: int`. For a particular sitting, author its rows only after visually verifying cover times, order and each maximum in its arkusz/regulamin and recording provenance. Certified rows for existing sittings may be added during P11-A for standalone results; the timed entry waits for all four valid rows and the P11-B engine. No default time or maximum, no inference from audio length or item count. Validate exactly one of each written module, unique consecutive source order, positive duration/maximum, and auto-scored part item quarter totals equal the declared maximum. Writing maximum is independently source-checked. The observed 40/60/60/90 minutes across extracted papers is an authoring check, not a default. Keep separate-part mode for any sitting without a complete valid config.

Add **NEW** `session/ExamSessionModel.kt`, `session/ExamSessionSession.kt`, `session/ExamSessionCardModel.kt` in commonMain. `ExamSessionConfig` contains the exact `examId`, ordered `ExamModuleConfig(module,durationSeconds,maximumQuarter)` and four existing part models. `ExamSessionState` owns current module position, its four immutable part states, `deadlineEpochMs: Long?`, per-part frozen results, and `completed` status. `ExamSessionAction.Start(nowEpochMs)`, `PartAction(module, action, nowEpochMs)`, `FinishPart(module, nowEpochMs)`, `Tick(nowEpochMs)` are pure input events; the reducer takes host time and emits a new state. Start is idempotent once started. On Start/advance, deadline = event time plus the authored duration in milliseconds, with overflow/invalid configuration rejected. For `PartAction` and `FinishPart`, validate the event module against the active module before processing the deadline; a stale event leaves state unchanged. At `nowEpochMs >= deadlineEpochMs`, freeze the current part exactly once before any answer edit or navigation from that event; advance to the next source-ordered part. `FinishPart` uses the same freeze/advance path. Repeated Tick/Finish/Submit cannot skip a part, alter a frozen snapshot or double score it. An old Tick timestamp after advance is a no-op for the new module; no generic catch-up loop or second timer is needed for four unique modules. On tab return, compare host time with the active absolute deadline before accepting input; expire that part if due, then start the next part at the observed transition time. Do not synthesize additional elapsed part transitions or strict proctoring rules. Keep deadline and frozen snapshots in a single owner; do not place a second timer in each part reducer.

`ExamSessionCardModel` projects current part card, remaining time from the host-provided current epoch, progress, and aggregate `confirmedQuarter`, `manualPendingQuarter`, and `possibleQuarter`. `possibleQuarter` means the full official maximum, the sum of four authored module maxima; it is not the confirmed-plus-pending ceiling. The score range is separately `[confirmedQuarter, confirmedQuarter + manualPendingQuarter]` within that official maximum, with writing contributing its source-backed manual maximum. It exposes `isFinal=false` while any answer awaits manual review or writing assessment, and has no final percentage or pass/fail then. The official pass threshold is absent until a paper-specific sourced DSL rule is accepted. Host wall time is an input; the browser owns its interval and cancellation, rereads `Date.now()` on visibility/focus restoration and before every user action, and disposes timer/audio on exit. The clock keeps running during audio pause, practice replay, navigation and tab backgrounding. The recorded repeated playback is already within the authored segment; retain existing practice replay and seek behavior. A monotonic interval alone is insufficient after suspension. No browser clock, DOM, media object or interval crosses into commonMain. If persisted timed resume is introduced, it needs a separate explicit persistence contract; P11 does not assume one.

Wire a timed entry in `ExamWeb.kt` only for a fully configured, mapped and source-certified sitting. It reuses the four existing part views with session-controlled state and a single host timer. A timed module transition disposes audio before leaving listening. The independent-part entries remain available and retain their prior behavior. A source-authoring gap, missing media boundary or incomplete official module maxima disables the timed entry for that sitting.

## State and resources

Reducer state is the only authority for answers, selected writing set, navigation, submitted snapshot and timed deadline. Copy maps/lists at reducer boundaries so callers cannot mutate prior snapshots through aliases. Part result scores use integer quarter units. Presentation models are derived views. The web route owns DOM nodes, focus, media and timer handles; `ExamWebController.close()` and transitions cancel them. Audio playback failure is a host display state and does not falsify submitted answers. Empty/invalid exam data is a load/configuration error or unavailable entry, not an empty exam that can silently finish.
