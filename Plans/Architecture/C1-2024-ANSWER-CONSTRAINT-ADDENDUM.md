## Что утверждает ключ

Grammar I: 10 слотов × 0,5 = 5 баллов; I/8 относится к `kilka`, I/9 к `przyjaciel` в одной фразе. Ключ даёт для I/8 `kilku / kilkoma // kilkorgiem`, для I/9 `przyjaciółmi // przyjaciół` и отдельно требует грамматической согласованности. Его **исчерпывающий явно названный набор пар**: `kilku przyjaciółmi`, `kilkoma przyjaciółmi`, `kilkorgiem przyjaciół`. Не считать декартово произведение ответов допустимым: например, `kilkorgiem przyjaciółmi` и `kilku przyjaciół` ключом не подтверждены. Каждый слот имеет максимум 2 четверти; ключ не устанавливает, какой именно слот теряет балл и сколько при несогласованной паре. Поэтому автоматический evaluator не должен придумывать 0/2 для каждого слота в таком случае.

Grammar II: 5 трансформаций × 1 = 5 баллов. Ключ с. 8 разбивает каждый канонический ответ на четыре фрагмента по 0,25 балла и требует принимать другие правильные решения; частичные баллы распределяются пропорционально выполненным трансформациям и их сложности. Для II/2 и II/5 отмечено, что глагол с предлогом оценивается вместе. Поэтому каноническая **полная** фраза может быть подтверждена автоматически (4 четверти), а другой непустой текст без доказанного полного или частичного варианта остаётся `PendingManual` до 4 четвертей. Пустой ответ = 0 без pending. Нельзя давать 0 за неизвестную грамматически верную трансформацию или начислять четыре четверти по простому наличию четырёх подстрок. Отдельные частичные варианты авторить только если целый ответ и конкретное число четвертей подтверждены ключом/независимым экспертным разбором; машинное выделение фрагментов из произвольного текста этим addendum не разрешено.

## Минимальный DSL и scorer contract

В `dsl/exam.data-contract` добавить **NEW** `GrammarAnswerPairRow` с `pairId`, `firstItemRef: ref GrammarItemRow`, `firstAnswer`, `secondItemRef: ref GrammarItemRow`, `secondAnswer`, `firstEarnedQuarter`, `secondEarnedQuarter`. Авторить три строки в **NEW** `exams/pl/certyfikat-polski/C1/2024-04/grammar-answer-pairs.core-data` после утверждения фактических item IDs; все три получают `(2,2)`. Эта таблица описывает **положительные официальные сочетания**, без нового общего языка условий/DSL PROGRAM. Проверка row mapping: разные пункты одного `GrammarTestRow`, одна пара ref, нормализованные пары уникальны, каждый credit `1..maximumQuarter`; сверять, что declared maxima обоих пунктов = 2. Канонические individual `correctAnswer` и прежние scored variants сохраняются для старых сдач. Для I/8–9 pair table имеет приоритет при `gradeInAttempt(test,item,fullAnswers)`; `grade(item,answer)` без контекста консервативен и не подтверждает условные формы. Не смешивать это с B2/2020 `onlyIfNotUsedBy`: там проверяется **неиспользование** одного слова, здесь — **согласованная пара**.

На полном снимке ответов: если оба заполнены и нормализованная пара есть в таблице, оба `ConfirmedFull(2)`; если оба заполнены, а пары нет, оба `PendingManual(2)` — это консервативная граница до решения проверяющего, **не** утверждение, что обе формы правильны. Если одно поле пусто, оно `Wrong(0)`; непустое поле без подтверждаемой полной пары `PendingManual(2)`, поскольку ключ оценивает согласованную фразу и не описывает изолированный credit. Если оба пусты, оба `Wrong(0)`. Это правило не закрывает экзамен с ложным окончательным процентом; `GrammarExamResult` суммирует `earnedQuarterPoints` и `manualPendingQuarterPoints` раздельно, а `isFinal=false` при pending. Если при визуальной сверке источника или экспертной проверке будет установлена иная политика одиночного/несогласованного ответа, обновить именно DSL oracle/контракт до открытия сдачи в каталоге, не править только UI.

Для II/1–5 `GrammarItemRow.gradingMode=open_manual` и `pointsQuarter=4`; канонический `correctAnswer` берётся из полного ключа, не из склеенных подстрок. `GrammarExamScorer.gradeInAttempt` обрабатывает pair rows перед обычным `evaluateExamAnswer`, остальные items и B2/2020 dependency идут прежним путём. `GrammarExamCardModel.kt` и `ExamGrammarWeb.kt` показывают ту же оценку по полному снимку; review у пары различает подтверждённое и ожидающее ручной проверки. Изменение ответа I/8 до Submit переоценивает I/9 без мутации текста, после Submit ответный снимок неизменен. `ExamData.kt` переносит generated pair rows в shared model; generated Kotlin печатает только `biome generate`.
