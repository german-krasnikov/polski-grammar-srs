## Причина и минимальный контракт

В `kotlin/shared/src/commonMain/kotlin/polski/presentation/SnapshotCommon.kt` функции `choice`, `putSharedSnapshotHeader`, `exerciseJson`, `putProgressFields`, `putEffects`, `lifehackObjectJson` объявлены `internal`. Их единственные внешние Kotlin-потребители по текущему `rg` — `kotlin/apple-bridge/src/{iosMain,macosMain}/kotlin/polski/{ios,macos}/{Ios,Mac}Snapshot.kt` и `{Ios,Mac}MatrixSnapshot.kt`; web/Android/shared production их не вызывают. `internal` виден внутри Gradle-модуля, но не из `:apple-bridge`. Девять ошибок macOS относятся к `choice`, десять — к остальным helper-функциям. iOS использует ту же границу и нуждается в том же исправлении, даже если первый сбой был на macOS.

Перенести **весь** `SnapshotCommon.kt` без изменения JSON-ключей/алгоритмов из `:shared` в **NEW** `kotlin/apple-bridge/src/commonMain/kotlin/polski/presentation/SnapshotCommon.kt`, сохранив package `polski.presentation` и `internal` у шести функций. Это один Apple-only wire adapter для двух native SwiftUI hosts. Типы и функции `AppUiState`, `Lifehack`, `UiCopy`, `sentenceHighlightParts`, `endingHighlightParts`, `StyleId.toLegacyWireValue`, `polski.data.*` и `polski.srs.Rating` уже доступны из public API зависимостей; если компилятор найдёт другую реально internal зависимость, разрешить её по одному подтверждённому call site, не раскрывать весь shared API. В `kotlin/apple-bridge/build.gradle.kts` объявить прямую `implementation(libs.kotlinx.serialization.json)` для нового source файла: `:shared` сейчас использует эту библиотеку как `implementation`, транзитивный доступ не должен быть неявным контрактом. `api(project(":shared"))` и P5 `api`/framework `export(project(":srs-progress"))` сохраняются. `internal` helper-функции не должны появиться как отдельные public declarations в Objective-C header.

`kotlin/apple-bridge/src/macosMain/kotlin/polski/macos/MacVocabularySession.kt:153`: прочитать `state.currentId` один раз в локальный `val currentId`; вычислять preview лишь при `state.revealed && currentId != null`, передавая `currentId`. Это устраняет Kotlin smart-cast across-module property без `!!` и не меняет порядок/значения JSON `now`/`intervals` или FSRS-вызовов. Не менять `AppUiState` visibility/ownership ради одного чтения.

## Swift-visible framework gate

`kotlin/iosApp/generate_project.rb` и `kotlin/macosApp/generate_project.rb` уже строят/копируют `:apple-bridge` framework. Проверенные `kotlin/iosApp/PolskiGrammar.xcodeproj/project.pbxproj` и `kotlin/macosApp/PolskiGrammarMac.xcodeproj/project.pbxproj` ещё вызывают `:shared:linkDebugFramework*` и копируют `shared/build/bin/...`: это отдельный stale consumer path. После успешного bridge link синхронизировать оба **существующих** `.pbxproj` с соответствующими `generate_project.rb` (либо штатной генерацией, если она не перезаписывает посторонние настройки; иначе точечно править два shell-script phase), чтобы Xcode действительно импортировал собранный `:apple-bridge/PolskiShared.framework`. Не менять имена framework и Swift `import PolskiShared`.

Проверить headers `apple-bridge/build/bin/{macosArm64,iosSimulatorArm64}/debugFramework/PolskiShared.framework/Headers/PolskiShared.h` сравнением с исходным `:shared` framework и реальными импортами Swift: публичные `MacSession`, `IosSession`, vocabulary/preferences bridge entrypoints, используемые Swift model/types, и публичные типы `:srs-progress`, нужные через export, доступны; шесть snapshot helper-функций не торчат как новый public Swift API. Успешный header grep сам по себе не доказывает Swift compile. Если обнаружится отсутствующий тип из `:shared`, сначала установить реальный Swift call site и добавить только необходимый framework export/bridge adapter, не включать blanket `transitiveExport` или массовый `public`.
