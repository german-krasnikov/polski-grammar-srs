# P8 W3: проверяемый lifetime web renderer

Дата: 2026-11-08. Узкое дополнение к [NEXT-SESSION-P5-P8-PLAN.md](NEXT-SESSION-P5-P8-PLAN.md) §P8 и [P8-WEB-BASELINE-EVIDENCE.md](P8-WEB-BASELINE-EVIDENCE.md). Baseline проверил 20/20 выбранных browser сценариев, но **не** actual Compose unmount → `TrainingDomRenderer.close()` → remount. Обычная навигация сохраняет renderer; закрытие вкладки не позволяет наблюдать поздний callback. Этот W3 gate нельзя объявить PASS по прежним Playwright тестам.

## Наблюдаемый дефект и владелец

`kotlin/composeApp/src/webMain/kotlin/polski/ui/TrainingWebApp.kt:82–84` создаёт неключевой `remember { TrainingDomRenderer() }` и вызывает `close()` в `DisposableEffect`. Store отдельно ключуется по `activeCoursePackId`, что нужно сохранить. Renderer около строк 320–390 держит `navigation`, `vocabulary`, `exam`, `RouteSlider`, `RiveEffectOverlay` и `matrixPrewarmScheduled`. `scheduleMatrixPrewarm` при первом не-Matrix render ставит `window.setTimeout(..., 1500)` и внутри callback на мгновение добавляет `main.matrix-page` в `document.body`, выполняет layout, удаляет узел. Текущий `close()` закрывает только navigation/vocabulary/exam, не хранит timeout ID и не отменяет callback. После disposal callback всё ещё может выполнить `renderMatrixWeb` с захваченными `AppUiState`/dispatch. RouteSlider уже хранит собственные timer/rAF IDs (`RouteSlide.kt`) и `settle()` завершает анимацию с `finish` callback; WebNav удаляет resize listener, но два init rAF пока не хранят IDs.

После запланированного split `TrainingDomRenderer.kt` **NEW** остаётся единственным владельцем этих ресурсов. Добавить `closed`/`disposed` guard и `matrixPrewarmTimerId: Int?`: при schedule один timer; callback сначала обнуляет ID и проверяет `closed` **перед** `renderMatrixWeb`/DOM append/dispatch; `close()` идемпотентно ставит `closed`, вызывает `window.clearTimeout(id)`, обнуляет ID и закрывает дочерние ресурсы. `render()`/schedule после `close()` не оживляют экземпляр. Новое монтирование создаёт новый renderer, который снова может назначить один prewarm; не сбрасывать `matrixPrewarmScheduled` на каждой route/pack смене. Сохранить 1500 ms, actual offscreen layout и прежний первый Matrix visit; не заменять его невидимым `display:none` или mock DOM. `RouteSlider` получает узкий `close()`/`dispose()` с отменой его timer/rAF и очисткой pending closure **без** вызова `onMounted`/`onSettled` после disposal; `WebNav.close()` отменяет свои два init rAF и resize listener. Renderer вызывает эти методы при закрытии. Не вводить второй renderer/store или глобальный debug/test endpoint. Rive page-level bridge и controller-owned overlays не переписывать в этом срезе без конкретного воспроизведённого leak; проверить их фактический close/host-removal как часть W3 evidence.

## Внутренний seam и реальные проверки

`kotlin/composeApp/build.gradle.kts` уже объявляет `webTest` с `kotlin("test")`; реальные DOM-тесты лежат в `kotlin/composeApp/src/webTest/kotlin/polski/ui/{CardBlocksWebTest,VocabularyWebEditorTest}.kt`. После extraction сделать `TrainingDomRenderer` `internal` (не private), как другие тестируемые web-контроллеры. Конструктор принимает **внутренний**, по умолчанию `window`-backed scheduler с двумя операциями `schedule(delayMs, callback): Int`/`cancel(id)`; production path использует настоящий `window.setTimeout/clearTimeout`. Этот seam отражает реальную зависимость renderer от таймера и не публикуется в JS/Swift/UI. `scheduleMatrixPrewarm` можно оставить `internal` для webTest, чтобы тест вызывал ровно production method без создания `TrainingStore`/`WebPreferencesController`; штатный `render()` остаётся единственным production caller. Держать только один scheduler, не внедрять интерфейс для всего DOM.

**NEW** `kotlin/composeApp/src/webTest/kotlin/polski/ui/TrainingDomRendererLifecycleTest.kt` в JS и Wasm browser runners: (1) создать real renderer с fake scheduler, вызвать production schedule для `AppUiState()` и noop dispatch, проверить один pending callback/1500 ms; (2) вызвать `close()` дважды, проверить ровно одну cancel и отсутствие pending; (3) принудительно доставить старый callback после close как гонку уже dequeued timer и наблюдать **реальный** `document.body`: ни одной вставки `main.matrix-page`/mutation и ни одного dispatch; (4) создать новый renderer и доставить его callback, проверить одну реальную вставку и удаление Matrix узла, отсутствие оставшегося `.matrix-page`; mutation записывать через browser `MutationObserver.takeRecords()` либо другой доступный DOM observer, а не по конечному `querySelector` одному (узел удаляется синхронно). Fake — только часы, не `renderMatrixWeb` и не DOM. Если binding `MutationObserver` не доступен одинаково на JS/Wasm, проверить доступные bindings и использовать эквивалентный тестовый DOM observer/JS-only adapter, указав Wasm W3 как NOT RUN до наблюдаемого gate; не подменять это счётчиком внутри production callback. Дополнительно отдельный focused case открывает pending `RouteSlider`, закрывает и доставляет его старые timer/rAF, убеждаясь, что новый root не меняется и listeners не остаются; выбрать проверяемый route без тестового глобального флага.

Browser acceptance на **новой** production distribution повторяет [baseline W1/W2](P8-WEB-BASELINE-EVIDENCE.md): training reveal/rate/draft/IME focus, pack switch с ровно одним `.route-content`/`.source-sentence`, Matrix first visit, vocabulary/exam nav и UX5 rapid/mid-slide. Это проверяет real host/render после split; internal W3 webTest проверяет close/remount, которого публичный браузерный маршрут сейчас не предоставляет. Если полноценный Compose unmount будет доступен из существующего product flow, добавить сценарий на нём; не добавлять пользовательскую кнопку/URL/debug global только ради теста.
