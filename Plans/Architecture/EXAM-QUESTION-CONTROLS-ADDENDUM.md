## Первый срез: напечатанный банк слов

В `dsl/exam.data-contract` добавить **NEW** `GrammarBankTokenRow KEY tokenId`: `tokenId: string`, `testRef: ref GrammarTestRow`, `position: int`, `text: string`. Это **одна авторская строка на напечатанное вхождение** токена, включая повторяющееся `na` в B2/2019 и B2/2020 II. `position` задаёт порядок печати, `tokenId` различает одинаковые подписи. Валидация у маппера: уникальные ID/позиции внутри test, положительный порядок, непустой текст; список не выводить regex из `instruction`. Инструкция остаётся полным польским текстом задания; bank rows — структурированный список для control. Не копировать один банк в `GrammarItemRow.options` для каждого слота.

Источники для authoring: `exams/pl/certyfikat-polski/B1/2017/grammar-tests.core-data` test `certyfikat-polski-B1-2017-grammar-6`; B1/2019 tests `B1-2019-grammar-2`, `B1-2019-grammar-8`; B1/2020 tests `certyfikat-polski-B1-2020-grammar-2`, `...-grammar-8`; B2/2017, B2/2019, B2/2020 test `certyfikat-polski-B2-<year>-grammar-2`. Для каждого создать **NEW** `grammar-bank-tokens.core-data` в соответствующем каталоге, с точным списком/порядком из arkusz и source evidence; старые `examId`, `testId`, `itemId` сохраняются. Если конкретный task в PDF использует банк только как подсказку к свободному ответу, `word_bank` всё равно показывает выбираемые напечатанные слова и позволяет вводить raw text для open/manual ответа лишь там, где исходное условие это разрешает; не расширять accepted answers UI выбором.

Аддитивно добавить `word_bank` к `GrammarItemRow.questionType` и `QuestionType` в `kotlin/shared/src/commonMain/kotlin/polski/exam/ExamModel.kt`. `ExamDataMapper.grammarTests` получает optional map `testId → List<GrammarBankToken>` (default empty для старых callers), `GrammarTest` хранит упорядоченные tokens; `ExamGrammarWeb.kt` уже держит исходные `tests` рядом с уплощённым state, поэтому может построить `bankByItemId` из принадлежности item к task без изменения `GrammarExamState`. `ExamData.kt` подаёт generated rows для шести сдач после согласования `dsl/biome.project` с P6 worker; generated `ExamRows.kt` руками не редактировать. На клик записывать прежний raw `token.text` через `GrammarExamAction.Answer(itemId,text)`; token ID/position нужны только рендерингу и доступности. Дубликаты показывать как два отдельных button с различимыми accessible labels/occurrence, локально помнить выбранный `tokenId` при навигации; scorer получает только текст и использует прежний `gradeInAttempt` по **полному** answers snapshot. Никакого общего «использовано — выключить во всех слотах»: B2/2020 II/8 `w` зависит ровно от II/6 через существующий `onlyIfNotUsedBy`, B2/2019/2017 не получают неподтверждённых глобальных ограничений. Удалить дублированные per-item `options` для bank items лишь после проверки, что новый control и grader сохраняют все ответы и старый quarter outcome.

## Следующий срез: семантические tags поверх существующих controls

`question_formation`: пометить B1/2017 Grammar IV (`B1-2017-g4-*`), B1/2019 Grammar V (`B1-2019-grammar-5`), B1/2020 Grammar V (`certyfikat-polski-B1-2020-grammar-5-*`). Добавить `GrammarItemRow.questionTarget: string OPTIONAL`: точная подчёркнутая фраза arkusz, отображаемая как отмеченный target рядом с прежним полным `context`/шаблоном; проверять непустой target у этого tag и его соответствие source sentence визуально, не пытаться вычислять его из `correctAnswer` или слова после тире. Control остаётся text input, raw text, включая польские диакритики; B1/2017 IV scored partial variants сохраняются. `transform` остаётся для настоящих парафраз B1/2019 VI, B1/2020 VI и B2 VIII.

`word_formation`: уже есть в `QuestionType`; применить к B2/2017 Grammar VI (`certyfikat-polski-B2-2017-grammar-6-*`) и другим подтверждённым derived-word tasks матрицы. Control = text input, не options. `gap_fill_fragment`: B2/2017 Reading IV, B2/2019 Reading II, B2/2020 Reading II и B1/2020 Reading V — label/fragment choice из существующего `ReadingQuestionRow.options`, показ фрагмента из `ReadingPassageRow.text`, raw answer = напечатанная буква; не перенумеровывать prefilled example и item IDs. `matching`: чтение B1/2017 III–IV, B1/2019 III–IV, B1/2020 III–IV, B2/2017 III, B2/2019–2020 III и listening matching rows из матрицы; каждый slot сохраняет свой raw label, `answerMode=unordered_set` для 2/3 выбранных меток остаётся отдельным атрибутом, а не выводится из tag. `match_heading` сохраняется как существующий tag для задач, уже так закодированных, пока визуальная форма/ключ не требуют точной замены. Аддитивно расширить `ReadingQuestionRow`/`ListeningQuestionRow` enum в `dsl/exam.data-contract` только нужными tags и `QuestionType.fromTag`; не перекодировать все `fill_gap` автоматически.

`ExamGrammarWeb.kt`, `ExamReadingWeb.kt`, `ExamListeningWeb.kt`: сделать явный `when` по enum/type и требуемой форме (`options`, text, unordered set). Переиспользовать текущие маленькие DOM builders для button/text input (`mcOptions`, `fillGapInput`, reading options, grammar `.exam-input`), без нового UI framework. Тип с обязательными options/bank и пустым списком — ошибка данных до открытия задания, с test ID/question ID; неизвестный tag продолжает бросать в `QuestionType.fromTag`. Не оставлять generic `else`, который молча рисует ноль элементов. Сохранить исправление focus loss: ввод текста обновляет state без полной перерисовки текущего поля; навигация и возврат восстанавливают raw answer. Аудио остаётся в web IO, Desktop заморожен.

## DSL oracle, browser и порядок приёмки

В `dsl/exam.data-contract` добавить небольшие typed oracle rows **NEW** `QuestionControlCaseRow` (caseId, sourceItemId, expectedTag, expectedKind enum `single_option|text|unordered_set|bank_option`, expectedOptionCount, expectedRawAnswer, expectedQuarter, expectedStatus) и `BankTokenCaseRow` (testId, expectedOrderedTokenText с явным повтором, expectedDuplicateCount). **NEW** `dsl/exam-scoring/question-controls.core-data` авторит минимум по одному реальному случаю каждого control из матрицы, отрицательный вариант без options/bank, duplicate `na`, B2/2020 II/6+II/8 (`w/w` wrong для второго, `other/w` full) и pending open answer; expected значения берутся из arkusz/klucz, не из production mapper. Kotlin commonTest проверяет mapping/control projection и scorer отдельно; где необходим DOM, PlayTest читает независимые DSL examples через существующий Playwright adapter, а не имитирует успешный render. Если формат oracle с `sourceItemId` не позволяет общему test module загрузить generated exam rows без циклов, держать test-only adapter в `shared/commonTest`, не добавлять новую production зависимость.
