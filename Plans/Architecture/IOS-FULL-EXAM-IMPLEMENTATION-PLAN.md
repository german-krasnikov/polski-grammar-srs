# Module design: P11 full native iOS exam

## Scope and consumers

Finish the existing native exam tab on iPhone/iPad: six published B1/B2 papers, independent Listening/Reading/Grammar/Writing parts, and one source-certified timed four-part sitting. This extends the current Grammar pilot in `kotlin/apple-bridge/src/iosMain/kotlin/polski/ios/IosExamSession.kt` and `kotlin/iosApp/PolskiGrammar/NativeExamView.swift`. `PolskiGrammarApp.swift` already owns the scene-level `NativeExamModel`, Exam tab, and active pack `uiCopy`. Keep its tab navigation and existing Grammar accessibility IDs. `ExamCatalog.entries` is the only catalog; it takes published route IDs and **displayTitle** from generated publication rows. Do not infer a date/title from `year`, and do not publish the 11 P9 drafts or `b1-sample`. A future month-specific publication uses its own authored title and explicit publication row. Desktop receives no feature work; browser Playwright remains a separate host gate.

The shared result/part/timed policy migration in [EXAM-RESULT-SESSION-DSL-PLAN.md](EXAM-RESULT-SESSION-DSL-PLAN.md) is concurrently in progress. This iOS work consumes its public reducers and projection, preserving those APIs. Business outcomes come from authored DSL → generated Kotlin policy → `:shared` scorer/reducer → Apple bridge. Swift owns only presentation, input, clock delivery and media IO. Physical iPad validation is deferred by owner; an installed iPad Simulator UI test is required.

## Public contract

Extend `IosExamSession`, retaining `selectExam`, `selectModule`, Grammar `answer`/`answerBankToken`, `next`, `previous`, `submit`, `exitGrammar`, `close`, and existing Grammar JSON keys. Add semantic bridge calls with unambiguous part identity: `answerPart(module, itemId, value)`, `selectWritingSet(setId: String?)`, `startTimed(nowEpochMs: Long)`, `tick(nowEpochMs: Long)`, `finishPart(module, nowEpochMs: Long)`, and a timed part-action entrypoint or equivalent typed methods that route `ExamPartAction` through `ExamSessionAction.PartAction`. The developer may refine names for Kotlin/ObjC interop, but must retain these argument and routing semantics. `selectModule("listening"|"reading"|"grammar"|"writing")` creates an independent part state from `official*Data`; a timed sitting has its own `ExamSessionState` created from `ExamSessionConfig(exam.routeId, exam.modules sorted by order, ...)`. Do not put policy decisions in the bridge: direct actions call `reduce*Exam`; timed actions call `reduceExamSession`, including Finish/Start/Tick. A tab switch calls neither `close` nor part exit. Explicit return to catalog/new sitting/scene destruction disposes state and media.

`currentSnapshot()` remains UTF-8 JSON with a stable root `screen`, `errorCode`, `catalog`, `selectedExamId`, `modules`, and existing `grammar` field. Add `mode` (`independent`/`timed`), active `module`, `part` (nullable), and `timed` (nullable). A part projection carries `kind`, `testId`/`passageId`/`taskId` as applicable, `position`, `count`, `instruction`, source text (`passageText`, `questionText`, `promptText`, `context`), `questionType`, ordered `options`, ordered `bankTokens` with `tokenId`, `answerMode`, `answerSlotCount`, `questions` (for multi-question passage/task, each with stable `id`, source text/type/options, answer and selected values), selected answer/draft, `sets`, `selectedSetId`, `wordLimit`, `promptImageRef`, `promptImageAlt`, `audioAssetId`, `segmentStartMs`, `segmentEndMs`, `submitted`, and result/review data where relevant. Only project actual source/model data; no official correct answers before submit. Preserve exact source option order and duplicate bank token identity. For unordered sets, bridge accepts the user's selected source values as the reducer's answer string encoding; derive any UI selection list mechanically from the stored answer, without Swift grading or over-selection rules. Matching/fragment controls must present the authored choices and serialize one answer per shared question ID; open/manual controls send raw text.

Result projection uses shared `ExamPartScore`/`GrammarExamResult` and shared `examResultVisibility`/`examSessionCardModel`: integer `confirmedQuarter`, `manualPendingQuarter`, `possibleQuarter`, formatted points, `isFinal`, nullable `finalPercent`, and review status/examples only after submission. Distinguish a part result from whole-sitting result. The timed object contains `started`, `completed`, `currentModule`, `position`, `deadlineEpochMs`, `remainingMs`, `frozenResults`, and sitting totals/visibility from `examSessionCardModel`. `remainingMs` is recomputed from a caller-supplied wall time, never Swift's own deadline arithmetic. An absent result is hidden; Writing and other manual work remain provisional and show no final percent or pass verdict. `errorCode` must distinguish `unknown_exam`, `no_exam`, `unknown_module`/`unknown_item`, invalid media resource, and malformed bridge input; invalid semantic actions leave prior state intact. Do not silently downgrade a missing asset to an empty audio player.

Swift calls `currentSnapshot` after each action and decodes once into its scene-owned `@Published` state. The active pack's `uiCopy` from `AppModel.state` supplies control/error copy via `uiText`; source exam text stays source text. Adding copy keys requires authored pack rows and normal Biome generation, not hardcoded Russian-only strings. Existing `exam-*` catalog, module, Grammar answer/navigation/review identifiers remain stable.

## State and resources

One `IosExamSession` belongs to the scene's `NativeExamModel`. It owns selected paper, independent part attempt or timed `ExamSessionState`, answer/draft snapshots and error. Switching tabs preserves these; leaving the app does not pause a timed deadline. Native model owns a periodic wall-clock `tick` while a timed sitting is active, sends a foreground tick immediately on reactivation, and cancels the timer on completion/explicit close/deinit. Use one time source (`Date` epoch milliseconds) at the event boundary; never a countdown that mutates domain state. A tick/answer/Finish at deadline follows shared session policy, including stale-module precedence, at-most-one-part freeze per event, observed-time next deadline and overflow failure. Avoid a long backlog of ticks after suspension.

`NativeExamAudio` owns its player, observer tokens, progress timer and current asset/task generation. Resolve only bundled, verified manifest IDs and exact source image references (path allowlist; no arbitrary URL). On task change, seek to `startMs`; clamp user seek to `[startMs,endMs]`; pause at `endMs`; replay seeks to start before play, even after end. If metadata is not ready, preserve play intent until seek completes; discard stale callbacks when task/asset changes. Provide elapsed/segment duration and accessible play/pause/replay/seek/progress. On module/route switch, explicit close, scene destruction or screen unmount, stop, remove observers, cancel progress updates and release player. On tab switch, pause audio while preserving Kotlin answer/draft/timed state; on background, pause audio and stop display updates, then refresh shared time on foreground. Do not pause the official timed deadline. Failure to resolve/play a published MP3 shows a concrete module error; no misleading enabled player.

## Decisions and tradeoffs

Reuse the existing single JSON bridge and scene model. A parallel Swift exam store would duplicate submission/result policy and make tab restoration diverge. Do not create native score/answer/session permission ladders. Swift may use `switch` for visual control types and media state; all answer validity, manual pending, part transition and timed disposition remains in shared DSL-backed reducers. The app's bundle is deliberately distinct from web resources: web `exam-audio/...` and `exam-images/...` are source references mapped to verified native resources. No Desktop adaptation and no new publication are implied.

## Verification and implementation order

1. **Bridge first.** Add reading/listening/writing independent states and projection, preserving Grammar pilot. Bridge tests compare source IDs/text/options, source module order/maxima, writing set/task/draft retention and shared reducer outcomes to `official*Data` and authored DSL examples. Test invalid IDs/actions and that no answer key leaks before submit. Keep existing 51 bridge tests and six exam cases green; this count is baseline evidence, not a fresh run here.
2. **Timed routing.** Construct `ExamSessionConfig` from each published cover and existing four models. Test Start idempotence, stale module, answer at deadline ignored, one freeze per event, next observed-time deadline, backward clock, overflow, four-part completion and provisional Writing result against the shared session-policy oracle. Do not invent iOS-specific timeout behavior.
3. **Native resources and audio.** Reuse the six pinned MP3 SHA-256 values from `dsl/exam-assets/exam-audio.core-data`; verify all before copying and hash the final app-bundle files. Preserve paths for the four source-referenced images and alt text. Offline missing media must fail packaging or make only the affected module visibly unavailable, never silently play a web URL. Simulator integration exercises a real >40-second source segment (passport case), play → progress → pause → seek → resume → end → replay, plus task switch, tab switch, background and unmount cleanup. A player mock alone is insufficient.
4. **Installed SwiftUI acceptance.** Cover all four modules and timed flow for a published paper, source passage/options, matching/fragment/free text, Polish IME, duplicate word-bank tokens, writing set/draft/photo, review with confirmed/pending quarters and no false final percent, deadline transition, accessibility labels, Dynamic Type/iPad split resize, and tab return. Retain existing `testOfficialB12017GrammarUsesSharedNativeExam`/typed draft IDs while replacing its obsolete expectation that modules say unavailable. Verify distinct `displayTitle` values from publication rows without assuming year uniquely identifies future months.

From `kotlin/`, use actual `./gradlew :apple-bridge:iosSimulatorArm64Test` and `:apple-bridge:linkDebugFrameworkIosSimulatorArm64`; from repository root use `xcodebuild -project kotlin/iosApp/PolskiGrammar.xcodeproj -scheme PolskiGrammar -configuration Debug -destination 'generic/platform=iOS Simulator' -derivedDataPath kotlin/iosApp/build CODE_SIGNING_ALLOWED=NO build`, then `xcodebuild ... -destination 'platform=iOS Simulator,id=<installed-id>' test` (discover with `xcodebuild -showdestinations`). Run `biome generate --check --project dsl/biome.project` for generated/source consistency and the asset staging/final-bundle verification command added by implementation. Browser Playwright remains independently reported; generic Xcode build does not prove launch, and simulator launch does not prove physical iPad. This architecture task ran no commands as verification: DSL/tests/framework/build/Simulator/device/browser all **NOT RUN** here.
