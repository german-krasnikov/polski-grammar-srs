# Качество экзаменов и учебного маршрута: P13–P19

2026-11-12. Новый обязательный объём по запросу владельца: перепроверить все опубликованные экзамены и пустые ответы; дать мгновенную обратную связь в самостоятельной тренировке, по умолчанию включённую; показывать выбранный неверный ответ в отчёте; устранить зависающие состояния анимаций; убрать английский материал из польского курса; расширить правила, упражнения, лайфхаки и сводки на основе проверенных пробелов. Рабочий язык курса сначала `pl-ru`; архитектура сохраняет универсальный выбор пары. Исполнение идёт Architect → Developer → Tester → Reviewer с настоящими browser PlayTests. Это план, не результат проверки.

## Контракт и решения

1. **Аудит источников.** Для каждой из 16 `ExamPublicationRow` построить матрицу `examId × модуль × задача × вопрос`: исходная PDF-страница/ключ/аудио или рисунок, напечатанный текст и варианты, ключ и разрешённые альтернативы, баллы, пример, режим проверки, control и заполненность пользовательского ответа/эталона в реальном UI. Различать пустой *ввод пользователя* (допустим до ответа), пустой *слот/эталон из источника* (дефект) и ожидающую ручной проверки формулировку (не ошибка). Отдельно проверить пустые кнопки, пустые labels, `[—]` после реально выбранного ответа, ошибочно обрезанные варианты и placeholder. Не исправлять строки ответов по одному generated файлу: менять `.core-data`, `biome fmt`, `biome generate`, затем независимая сверка с PDF/ключом. Не изменять закреплённые oracles/fixtures под новый вывод без подтверждённой коррекции требования. Повреждённый B2/2022-06 исключён из 16, архив остаётся.
2. **Режим обратной связи.** NEW `UserPreferencesV2.immediateExamFeedbackEnabled: Boolean = true` (рабочее имя) и переключатель «Показывать правильный ответ сразу» в настройках. Отсутствие поля в прежнем POLSKI-TEXT/JSON → `true`; явное `false` переживает restart, импорт/экспорт и смену хоста. Не терять неизвестный raw при `RecoveryRequired`. Схему/allowlist/bridge snapshots обновлять как одну совместимую миграцию; имя класса `V2` не причина ломать wire. Режим применяется к самостоятельному прохождению отдельной части/тренировке. Полный timed exam сохраняет официальный ход: ответы можно менять до submit/deadline, feedback скрыт до фиксации результата. Данный scope не меняет FSRS и не начисляет оценки тренировочным карточкам за экзамен.
3. **Commit и показ.** В самостоятельном режиме одиночный выбор/токен банка после первого нажатия фиксирует выбранное значение, использует общий scorer/policy и показывает «Верно» либо одновременно «Ваш ответ» красным и «Правильный ответ» зелёным. Дополнить цвет текстом/значком и live region/VoiceOver announcement; фокус/контраст проверять на mobile и клавиатуре. Первый подтверждённый выбор остаётся в оцениваемом snapshot; повторный tap не меняет его. Для набора вариантов commit только когда заполнено официальное число слотов или по явному «Проверить», если ввод открытый/неоднозначный; набор можно исправлять до commit. Для текста commit по явному «Проверить», не на каждый `input`; неизвестное `open_manual` показывает «Требует проверки» и подтверждённую часть без ложного красного/зелёного. Зависимые парные/банковые ответы оцениваются только когда доступны все необходимые ответы; до того не показывать преждевременный неверный verdict. Для writing нет автоматического эталона. Предлагаемый узкий общий immutable presentation state NEW `kotlin/shared/src/commonMain/kotlin/polski/exam/ExamPracticeFeedback.kt` хранит `itemId`, committed answer, grade/status и разрешение перехода; reducer/DSL policy остаются владельцами предметных решений. Не создавать второй scorer.
4. **Переход через две секунды.** Только после окончательного оценённого ответа в самостоятельном режиме. Автоматически переходить к следующему *вопросу*, а не перескакивать оставшиеся вопросы текущей reading/listening задачи или весь модуль. На последнем вопросе оставлять результат/явное завершение. Для ручного/pending и письма доступна явная навигация без автоматического «успеха». Host timer владеет задержкой 2000 мс; общий state выдаёт разрешение/цель. Отмена/поколение события при новом задании, ручной навигации, route change, reset, submit, switch курса, уходе вкладки/background, unmount/close; повторное нажатие не создаёт второй переход. При Reduced Motion/animations off смысл и 2 секунды сохраняются, визуальные переходы мгновенны.
5. **Отчёт.** На каждом graded вопросе явные поля «Ваш ответ: …», «Правильный ответ: …» и статус/подтверждённые четверти; для пропуска «Не отвечено», для нескольких выборов показывать фактически зафиксированный набор. Корректные source-backed варианты и partially correct показывать без объявления единственной формулировки, если официальный ключ допускает несколько. Для `PendingManual` указывать введённое, известные примеры и ожидаемые баллы, не писать «неверно». Письмо показывать как черновик/ручную проверку, не как правильный ответ. Не подменять старый snapshot текущим UI draft после submit. Web `renderResult` в трёх Exam*Web контроллерах, общий `ExamSessionCardModel`, Apple bridge snapshot и SwiftUI review получают один и тот же семантический результат; формат строк через pack-aware UiCopy.
6. **Зависшие состояния.** Описать и исправить конкретный воспроизводимый lifecycle каждого feedback/animation overlay: start → committed/review → next/reset/route/background → disposed. Остатки «правильно/неправильно» не видны на следующем вопросе или после возврата; callback старого вопроса не меняет новый. Учитывать `animationsEnabled` и `Motion.Reduced`; не привязывать бизнес-состояние к CSS transitionend/Rive completion. Проверить web контроллеры, существующие `TrainingWebApp` callback cleanup и SwiftUI при наблюдаемом воспроизведении, не делать вслепую общий animation framework.
7. **Языковой набор и курс.** Польская матрица не показывает английские `English: лицо × время` и `do-support`; при `en-ru` английский материал остаётся доступным. Web `MatrixWeb.kt` и SwiftUI `PolskiGrammarApp.swift` проверяют выбранный target из одного pack snapshot; Apple `IosSnapshot.kt` может не создавать английские строки для `pl-ru`, если consumer требует этого. Затем по матрице пробелов из п. 1 сопоставить экзаменные конструкции с имеющимися `skills`, `recipes`, `reference`, таблицами и заданиями `pl-ru`. Добавлять только доказанные темы/упражнения с точными польскими формами, русскими объяснениями и полной цепочкой вход → операция → предложение; не превращать официальный экзамен в готовую тренировочную карточку без педагогического контекста. `lifehacks.core-data` хранит короткий приём и реальную citation; `reference.core-data`/соответствующие текущие source rows — правило, примеры, сводку. Четыре `PreferredStyle` меняют подачу и плотность объяснения, не тип учащегося, ключ, оценку или FSRS. Копии `en-ru` мапперов получать только через `dsl/derive-enru-mappers.mjs`/generate; generated Kotlin не править вручную.

## Порядок и владение

**P13 — 16 экзаменов, audit ledger.** Developer/source owner собирает матрицу с источниками и воспроизводимыми пустотами; независимый Tester сверяет выборку и критические находки. Сначала исправляются ошибки публикации/ключа, затем новая UX семантика. Пустой draft вне публикации не делает ложный провал активного каталога.

Дополнение 2026-11-13: полный повторный source audit зафиксирован в [P13-OFFICIAL-SOURCE-REAUDIT.md](P13-OFFICIAL-SOURCE-REAUDIT.md). Подтверждены десять индивидуальных числовых подсказок `()` без операнда и неверное независимое сочетание двух ответов C1/2022-11; исправления проходят отдельные проверки. Критерии письма отсутствуют в данных 14 из 16 сдач; принят [WRITING-SOURCE-GUIDANCE-DESIGN.md](WRITING-SOURCE-GUIDANCE-DESIGN.md): один авторский rubric на writing cover, механическая передача существующим потребителям без автоматической оценки письма. P13 остаётся открытым до реализации и независимой проверки этих исправлений.

Имеющийся read-only baseline координатора: поддерживаемый Biome reader прочёл опубликованный generated source: 1125 Grammar + 604 Listening + 691 Reading = 2420 строк. Не найдено пустых `correctAnswer`, пустых элементов pipe-списков options и обязательных пропусков options у `choose_form`/`multiple_choice`/`matching`/`gap_fill_fragment`; воспроизведение и JSON лежат в соседнем `recovery-logs/20261112/exam-learning-quality/initial-row-audit.{mjs,json}`. Это **не** проверка всех 16 source PDF, mapping/snapshot, DOM или SwiftUI: жалоба на пустые ответы остаётся открытой. P13 должен пройти цепочку source → generated rows → model/card snapshot → фактический экран/отчёт для каждого вопроса, включая пустой пользовательский ответ и заполненный неверный ответ.

**P14 — preference и практика.** Общий настройка/codec + DSL правило допуска немедленного feedback, затем один вертикальный web срез single-choice grammar; source-backed RED → GREEN и PlayTest. Расширить на reading/listening и варианты/банк/open_manual только после доказательства первого среза. Архитекторское решение о timed из п. 2 действует для всех хостов.

**P15 — отчёт выбранного ответа.** Общая модель review и web/iOS consumers; test с неправильным, частичным, пропущенным и pending ответом. Не менять scoring policy ради оформления.

**P16 — lifecycle/animation.** Изолировать воспроизводимые stale callbacks и закрепить отмену таймера, сброс overlay и Reduced Motion. Проверить быстрые клики, Back, reset, переход задачи/части, hidden tab.

**P17 — language leak.** Исправить web/iOS conditional rendering; проверить `pl-ru → en-ru → pl-ru` без перезапуска и native snapshot. Это ограниченный host bugfix; Android и замороженный Desktop затрагивать только при реально подтверждённой утечке.

**P18 — пробелы курса.** После аудита P13 согласовать конкретный gap ledger (тема → экзаменный факт → существующий навык/отсутствие → source row → тест/экран), затем приоритетные правила, упражнения, лайфхаки и сводки. Авторские `.core-data` → `biome fmt` → `biome generate`; новые DSL конструкции только если существующая грамматика не выражает нужный повторяемый контракт. Не создавать Core feature ради одного примера.

**P19 — независимое принятие.** Tester проходит реальные browser PlayTests и нативные затронутые host сценарии; Reviewer читает итоговый diff и evidence. Main agent синхронизирует user docs/`AI/decisions.md`, результаты и открытые device gates. Деплой не следует автоматически из плана или тестового PASS.

Следующий ограниченный implementation slice: P13 audit ledger + исправление первой подтверждённой пустоты в активном экзамене, с независимой source сверкой; параллельно можно начать строго отдельный P17 language leak без правки тех же файлов. После этого P14 single-choice grammar задаёт проверяемый базовый контракт для остальных input типов.

## Проверка и критерии

- **A13:** Все 16 опубликованных `examId` перечислены из publication DSL; у каждой части и задачи есть source-receipt, непустые отображаемые поля и ключ либо явно документированная ручная оценка. Найденные расхождения исправлены в авторских строках и проверены независимо; backlog не называется PASS.
- **A14:** Новый профиль, старый export, явное OFF и restart/import на web/iOS/реально используемых hosts дают ожидаемое значение. В non-timed single-choice первое нажатие фиксирует ответ, статус и два различимых значения; второй tap не меняет оценку. Timed показывает verdict только после submit/deadline.
- **A15:** Неверный выбранный ответ виден рядом с правильным в итоговом отчёте; пропуск, частичный результат, accepted variant, набор и pending не искажаются.
- **A16:** С контролируемыми часами/Playwright ожиданием состояния переход происходит после 2 с один раз, остаётся внутри группы до последнего вопроса и отменяется на навигации/unmount/background; старый feedback не всплывает на новом вопросе. Reduced Motion и клавиатура сохраняют смысл.
- **A17:** На польской матрице English/do-support отсутствуют и в DOM/SwiftUI accessibility tree; на английской есть; переключение pack без restart обновляет обе версии.
- **A18:** Каждая добавленная тема имеет точную source/экзаменную привязку, полные русские объяснения и связанные предложения; новые tips имеют невыдуманные citations, а все четыре стиля показывают доступный материал без изменения оценок/FSRS.
- **A19:** `biome generate --check --project dsl/biome.project`, затронутые Kotlin tests/compilation, `npm` checks и Playwright через `tests/browser/kotlin-exam.spec.ts` и `dsl/exam-web/*.playtest` (NEW cases) дают отдельные PASS/FAIL/NOT RUN; iOS Simulator XCTest при изменении SwiftUI отдельно, Android only если затронут. Проверять реальные вопросы/выбранные неправильные значения и таймер, а не один факт наличия CSS-класса. Фикстуры ожиданий формируются независимо от production output. Статус browser, build, Simulator и physical device не смешивать.

## Основание для DSL и документации

Применены локальные `biome-dsl/AI/{ARCHITECTURE,BestPractice,PATTERN_DICTIONARY,PRINCIPLES,ProjectMigratioPrincipals}.md`: один авторский факт/решение; данные в `.core-data`, повторяемая бизнес-политика в существующей `.logic`/контракте, generated artifacts не редактируются, UI таймер/DOM/SwiftUI остаётся нативным. Пользовательская граница важнее экономии строк: новый DSL pattern/contract лишь после измерения повторений и реального consumer. Developer/main обновляет `AI/decisions.md`, настройки/справку и текущий статус P13–P19. Исторические PASS остаются историческими; новых запусков архитектор не выполнял.
