## Test additions and limits

I changed only `tests/browser/kotlin-exam-content-audit.spec.ts` and `kotlin/shared/src/commonTest/kotlin/polski/exam/ExamContentIntegrityAuditTest.kt`. The browser test now forces the actual JS compatibility branch when its run is labeled `KOTLIN_SPIKE_BRANCH=js` and asserts the loaded branch script, preventing a mislabeled Wasm pass. It also checks that the published B2 reading option can be selected at 375×667. The shared test now asserts independently recorded published totals, so two truncated layers cannot agree vacuously. No production, source, generated or renderer file was changed by this tester.

The all-paper browser traversal verifies ordered authored prompts, options for reading/listening and choice/word-bank grammar, writing sets/prompts/image alternatives, nonempty controls, and review item counts. It submits blank attempts for all sections. It does not select and grade every one of the 2,420 keyed questions. The separate wrong-answer case verifies one B2 reading answer remains visible and distinct from `[—]` in the review. Thus this run found no reproducible empty published answer or option on those paths, but cannot establish that the owner's intermittent empty-answer symptom is fixed in every state or host. A report with route, part, task/question ID, host, and action sequence is still needed to reproduce that exact symptom; P13 should not be called a full semantic PDF audit or a verified fix for an unidentified intermittent case.
