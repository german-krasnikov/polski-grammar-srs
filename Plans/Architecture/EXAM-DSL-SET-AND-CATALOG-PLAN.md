## 1. Наборы: подтверждённый факт не равен строке ответа

**Фактический разрыв.** В `/tmp/polski-p11-shared-worktree/kotlin/shared/src/commonMain/kotlin/polski/exam/ExamAnswerEvaluation.kt` `evaluateUnorderedSetAnswer` считает `correctAnswer.split("|")` одновременно ключом, числом обязательных ответов и базой `creditPerCorrectQuarter * key.size == maximumQuarter`. `ListeningQuestion.answerSlotCount` и `ReadingQuestion.answerSlotCount` также равны длине ключа. Это не выражает B2/2024-06 Listening V/3 (`...-l5-q3`): любые **два из трёх** оснований, 2 четверти за каждое, максимум 4. Черновик P9 уже ставит `requiredSelections: 2`, но `dsl/exam.data-contract` его пока не объявляет. C1/2023-11 Listening IV (`...-l4-...`) требует ровно шесть утверждений из 12, а V/1, V/2, V/7 имеет два факта из более широких пулов; `requiredSelections: 6/2` уже есть в черновиках. В C1/2023-11 Reading IV `...-r4-q2` и `...-r4-q6` требуют B|E и B|C: B может использоваться в разных вопросах, глобального depletion нет. C1/2023-04 Listening содержит разные веса 4/2 четверти у отдельных групп, их нельзя заменить единым глобальным весом.

**Минимальное расширение данных.** В `dsl/exam.data-contract` `ListeningQuestionRow` и `ReadingQuestionRow` получают `requiredSelections: int OPTIONAL` и source-backed `AcceptedFactRow` **NEW** с `factId`, `questionRef` (ссылка на конкретный listening или reading question через два отдельных record типа, если контракт не допускает union ref), `creditQuarter`, `displayText`; `AcceptedFactAliasRow` **NEW** с `aliasId`, `factRef`, `answerText`. Альтернативно назвать record отдельно по module, чтобы `ref` оставался проверяемым Biome; не вводить строковый вопрос без ref. Одна строка accepted fact = одно смысловое основание, несколько формулировок = alias того же `factId`; повтор одного факта не зарабатывает баллы дважды. `correctAnswer` и имеющиеся `ListeningAnswerVariantRow` остаются для legacy и показа официального примера; для новых fact rows не парсить `|` как идентичность факта. `requiredSelections` отдельно от размера accepted pool и числа alias. Для существующих rows при отсутствии поля и fact rows сохранить `key.size` и старый API/результат; при добавлении нового поля без fact rows разрешить только source-backed exact choices, не выдумывать synonym identity. Миграция B2/2024-06 и C1 — после проверки автором официальных ключей, без активации неполных черновиков.

**Границы валидации.** Подтверждённый синтаксис `.data-contract` — `RECORD`/`KEY`/`COUNT`, типы, `enum`, `ref`: он проверяет уникальность исходных `factId`/`aliasId`, ссылки и типы `requiredSelections`/`creditQuarter`; положительные пределы, сравнение `requiredSelections <= factCount`, арифметика весов и уникальность **нормализованных** alias этим контрактом пока не подтверждены. Проверка индекса фактов в общем Kotlin resolver и независимых oracle cases должна отвергать неоднозначный `normalize(alias)` внутри вопроса, нулевой вес, неверное число слотов и невозможный максимум **до оценивания**; это integrity guard источника, а не ещё один grading verdict. Если нужен build-time gate для этих свойств, подтвердить существующий валидатор Biome Core или зафиксировать узкий Core gap, не приписывать `.data-contract` неподдерживаемый синтаксис. Нельзя считать одно `correctAnswer` полным перечнем допустимых фактов. Сохранить исходные printed choices и IDs. Для `open_manual` неизвестная непустая фраза может быть верным paraphrase: confirmed только за известный distinct fact, остаток возможных четвертей pending; blank даёт 0 без pending. Консервативная ручная оценка избыточных/ошибочных выборов применяется **только к новым source rows с явным metadata режима** и независимыми cases; существующая `evaluateUnorderedSetAnswer` и все frozen legacy outcomes сохраняют прежний вердикт. В UI не разрешать выбрать больше объявленных слотов, но оценка импортированного/raw ответа должна оставаться честной. Отдельные вопросы не делят пул и не расходуют его.

**Logic decision.** `dsl/exam/set-policy.{logic,contract}` **NEW** принимает механически вычисленные facts `selectionCount`, `requiredSelections`, `distinctKnownFactCount`, `knownCreditQuarter`, `maximumQuarter`, `unknownNonblankCount`, `hasMalformedSelection`, `openManual`, `usesSourceConservativeOverselection`; возвращает disposition (`full`, `partial`, `pending`, `wrong`, `manual_review`) при явном порядке. `usesSourceConservativeOverselection` задаётся явным metadata только для новых fact rows и не включается по умолчанию для legacy. `dsl/exam/set-policy-outcomes.core-data` **NEW** сопоставляет disposition с `ExamAnswerStatus` и источниками confirmed/pending credit по образцу single-answer pilot. Kotlin fact resolver в `ExamAnswerEvaluation.kt` нормализует/tokenizes, сопоставляет alias→fact ID, убирает повтор, суммирует **по fact ID**, ограничивает confirmed максимумом, а policy решает status/видимость и право автоподтверждения. Для неизвестной фразы открытого задания pending upper bound = `maximumQuarter - confirmedQuarter`; не превращать её в неверный ответ. Подтверждённая частичная оценка и pending могут сосуществовать. Предложить минимальный overload/spec для new fact data, сохранив старую сигнатуру `evaluateUnorderedSetAnswer`; `ListeningQuestion`/`ReadingQuestion` получают optional `requiredSelections`/accepted facts, `answerSlotCount` читает explicit count или legacy key count. Scorer/session/card не имеют собственной лестницы вердиктов.

**Независимые cases до кода.** `dsl/exam/set-policy.examples` и `dsl/exam-scoring/set-facts.core-data` **NEW**: B2/2024-06 два из трёх в обоих порядках=4/4, один=2/4, три выбора остаются manual **только при явном новом metadata** и отсутствии источника штрафа; C1/2023-11 IV шесть из 12, пять partial только если официальный ключ допускает per-item credit, иначе pending по source rule; V/1,2,7 alias одного fact не засчитывается дважды; C1/2023-04 отдельные группы 2×4 и 2×2 четверти с собственными максимумами, без выдуманной группы смешанного веса; C1 Reading IV общий B у разных вопросов не расходуется; unknown open, blank, duplicate, malformed, legacy B1/2020 B2/2017/B2/2020 unordered cases с **точно прежними** статусами и четвертями. Нельзя авторить ожидаемые статусы из Kotlin output. Негативный контроль ломает alias distinctness или count приоритета и обязан краснеть. Testers сверяют source PDF/key и текущие frozen oracle values; для непроверенной официальной семантики case остаётся pending, не guessed full/partial.

## 2. Единый опубликованный каталог без новых ручных Kotlin imports

**Проверка механизма.** `biome data generate` в текущем `implementations/typescript/packages/biome/src/commands/data.mjs` принимает повторяемые явные пары `--rows <Record> <file>` и **не раскрывает glob**; несколько файлов одного record печатает одной константой в порядке аргументов. `GENERATE ... derive` в `commands/generate.mjs` возвращает детерминированные `[path,text]` и следующий шаг выполняется по порядку, включая `--check`; такой шаг уже применяется в этом проекте для форм и mapper copies. Следовательно, прямой `--rows exams/**/exam.core-data` здесь не является поддержанной функцией. Derive использует поддержанный Biome reader для publication rows и копирует уже проверенные исходные строки с provenance; не вводить собственный parser `.core-data`, локальную Kotlin reflection/JSON базу или `mapB1...` для 11 новых сессий. Если публичный reader API для derive не доступен, это отдельный Core gap до реализации aggregation.

В P11 WIP `ExamCatalog.kt` вручную перечисляет шесть `polski.exam.data.b*y*` packages; `ExamSourceData.kt` повторяет `map*` для grammar. Четыре webMain `ExamData.kt`, `ExamReadingData.kt`, `ExamListeningData.kt`, `ExamWritingData.kt` содержат аналогичные six-paper mappings. **Один путь:** authored `dsl/exam-published.core-data` + `ExamPublicationRow` **NEW** в `dsl/exam.data-contract`: стабильный `routeId`, `examRef`, `sourceDir` (путь к каноническим source `.core-data`, не копия текста экзамена). Первые шесть published rows сохраняют `b1-2017`...`b2-2020`; `b1-sample` остаётся web-only alias. Новая дата вроде `2024-02` получает уникальный `routeId`, не выводится только из `year: int`, иначе столкнётся с другим экзаменом того же года и старым progress ID. Публикация нового черновика требует одной source-backed записи после полноты/проверки; само наличие папки не объявляет его доступным.

Сначала `GENERATE exam-published-source-check script ...` **NEW** читает publication rows и вызывает **поддержанный** `biome data check --contract exam --rows ...` для оригинальных файлов каждой опубликованной сдачи; `biome fmt --check` проверяет их до конкатенации. Таким образом синтаксическая/ссылочная диагностика указывает исходный файл и строку. Затем `dsl/derive-exam-published.mjs` **NEW**, шаг `GENERATE exam-published-aggregate derive ...` **NEW**: читает только прошедшие source check publication rows, сортирует/проверяет route IDs и sourceDir, собирает файлы каждого record в `dsl/exam-published/generated/<record>.core-data` **NEW generated** и записывает line provenance mapping `<aggregate>:<line> → <source>:<line>` рядом с ними. Поддержанный `data` check обеспечивает `KEY`/`ref`/типы/`enum`; проверка полноты четырёх модулей и соответствия `examRef` опубликованной сдаче — отдельный механический publication gate. Он также проверяет объявленные `audioUrl` против **закреплённого** `dsl/exam-assets/exam-audio.core-data`; image refs проходят отдельную проверку resource paths, потому что image manifest в текущем контракте не подтверждён. `biome generate --check` не требует ignored локальных MP3, декодирования или сети. Проверка реальных байтов, SHA-256, декодируемости и web/iOS distribution — отдельный delivery gate. Никакой смысловой grading decision в derive. Следующий `GENERATE exam-published-rows data --contract exam --rows ExamRow <aggregate> --rows ExamModuleRow <aggregate> ... --target kt --kt-package polski.exam.data.published --out kotlin/shared/src/commonMain/generated/kotlin/polski/exam/data/published/ExamRows.kt` **NEW** использует поддержанный printer/refs и сравнивает выход на `generate --check`. Для отсутствующего optional record агрегат пуст, но файл существует; порядок published records стабилен. `ExamPublicationRow` включён в общий `data` check, чтобы `examRef` проверялся. Если оригинальные source diagnostics или provenance mapping нельзя надёжно сохранить либо Core не поддерживает нужный cross-file ref check, это **Core gap**: остановить aggregation pilot и зафиксировать узкий запрос к Biome Core, не подменять его рукописным Kotlin registry или самодельным парсером.

`kotlin/shared/src/commonMain/kotlin/polski/exam/{ExamCatalog.kt,ExamSourceData.kt}` затем читает единые generated `EXAM_ROW_ROWS`/`EXAM_MODULE_ROW_ROWS`/question/task rows и группирует по `examRef`/`taskRef` универсальными мапперами (`ExamDataMapper` уже существует). Никаких imports пакетов по дате или `when (examId)`; значения official order, max, options, modes, variants остаются в DSL. Web `ExamWeb.kt` и четыре `Exam*Data.kt` становятся тонкими consumers shared catalog/data, `IosExamSession` читает тот же catalog; `:apple-bridge` и webMain зависят от `:shared`, обратных зависимостей нет. Дата опубликована только если typed rows, module cover, объявленные media refs и source completeness проходят source gate; реальные media bytes проверяются позже перед доставкой. Сравнить snapshots существующих шести (IDs, counts, module order/max, texts, scores, image/audio refs) до/после, `b1-sample` отдельно.

**Мерка P25.** До: шесть регистраций `ExamCatalog`, шесть grammar maps в shared и по шесть maps в web adapters; после: одна публикационная строка на сдачу и одна generic projection каждого record. Зафиксировать authored/derived LOC, число точек правки при добавлении седьмой сдачи, время `biome generate`, размер Kotlin output и parity snapshots. Если механика aggregation увеличивает риск потери source diagnostics/ID или существенно сложнее ручной регистрации, записать Core gap и временно сохранить текущие шесть; не заявлять цель «одна база» выполненной.

### Source filename compatibility
The six existing papers use `modules.core-data`; P9 author drafts use `exam-modules.core-data`. Aggregate discovery must identify records through the supported Biome reader/check path rather than assume one filename or duplicate these facts in native code. Preserve original file/line provenance and reject duplicate module records if both files are present. No author draft is renamed or activated merely to satisfy a hardcoded scanner.
